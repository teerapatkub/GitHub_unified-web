# Spec 0001 — คำตัดสินเดียวทุกโหมด และความพร้อมสำหรับการใช้งานจริง

สถานะ: `ready-for-agent` (ยังไม่ได้ publish ขึ้น issue tracker — ดู Further Notes)
ศัพท์ที่ใช้ในเอกสารนี้อ้างอิง [CONTEXT.md](../CONTEXT.md)

---

## Problem Statement

PySim เป็นโปรเจคจบที่ต้อง **deploy ขึ้นใช้งานจริง** ไม่ใช่เดโมบนเครื่องผู้พัฒนา และผู้ใช้จริง
คือ **คนที่ไม่เคยเขียนโปรแกรมมาก่อน** เมื่อวัดด้วยเกณฑ์นั้น ระบบวันนี้ยังไม่พร้อมด้วยเหตุผลสี่ชั้น

**ชั้นที่ 1 — รางวัลที่ได้มาไม่ได้แปลว่าทำโจทย์ได้** ผู้เรียนกดส่งสตริงว่างในโจทย์ 26 ข้อที่
*ตรวจอัตโนมัติไม่ได้* แล้วได้ XP และทองเต็มจำนวน และในโหมด Arcade ที่ผู้เล่นแข่งกันเพื่อทอง
เบราว์เซอร์เป็นฝ่ายตัดสินเองว่าโค้ดถูกกี่ข้อแล้วส่งคะแนนขึ้นมา — ใครก็ตามที่เปิดเครื่องมือนักพัฒนาเป็น
จะชนะทุกแมตช์โดยไม่ต้องเขียนโค้ดเลย อันดับทั้งกระดานจึงเชื่อถือไม่ได้

**ชั้นที่ 2 — บางครั้งระบบตัดสินคนที่เขียนถูกว่าผิด** ซึ่งร้ายกว่าชั้นแรกสำหรับผู้เริ่มต้น เพราะ
ทำให้เขาเลิกเชื่อตัวเอง กรณีที่พบและยืนยันแล้ว: โปรแกรมที่พิมพ์คำตอบถูกต้องแต่มีข้อความใดๆ
ออกทาง stderr ถูกตัดสินว่าผิด · คำตอบที่ต้องพิมพ์ภาษาไทยในโหมด Competitive Arena
ล้มด้วย `UnicodeEncodeError` ทุกครั้งบน Windows · โจทย์ที่คำตอบไม่ตายตัว (สุ่มรหัส PIN)
ไม่มีทางผ่านเพราะข้อกำหนดเขียนไว้เป็นรูปแบบ regex แต่ไม่มีโค้ดส่วนไหนอ่านรูปแบบนั้นเป็น

**ชั้นที่ 3 — เมื่อตอบผิด ผู้เริ่มต้นไม่รู้ว่าต้องทำอะไรต่อ** สิ่งที่เห็นคือ traceback ดิบของ Python
เป็นภาษาอังกฤษ และเลขบรรทัดที่ชี้ผิดไป 6 บรรทัดจากที่เห็นในเอดิเตอร์

**ชั้นที่ 4 — เว็บนี้ deploy ไม่ได้เลย** ที่อยู่ของ API ถูกเขียนตายเป็น `localhost` กระจายอยู่ทั้ง
ฝั่งหน้าเว็บ ไม่มีไฟล์ประกอบ container ไม่มีใครเสิร์ฟไฟล์หน้าเว็บที่ build แล้ว และระบบตรวจคำตอบ
ต้องมี Python จริงบนเครื่องปลายทาง ซึ่งเป็นเงื่อนไขที่โฮสต์ Node ทั่วไปไม่มีให้

## Solution

**คำตัดสิน** (ถูกหรือผิด) จะมีที่มาที่เดียวคือฝั่ง server และเหมือนกันทั้งสามโหมด ส่วน
**การให้คะแนน** ยังต่างกันตามโหมดโดยตั้งใจ — บทเรียนให้ XP กับทอง, Competitive Arena
ให้คะแนน 0–100, Arcade ให้อันดับที่คิดจากความถูกต้อง คุณภาพโค้ด และเวลาที่เหลือ

ผลที่ผู้ใช้จะเห็น:

- **ผู้เรียน** ได้รางวัลเมื่อเขียนโค้ดที่ผ่านจริงเท่านั้น และเมื่อยังไม่ผ่าน จะได้คำอธิบาย
  ภาษาไทยที่ชี้บรรทัดถูก พร้อมปุ่มให้ผู้ช่วย AI อธิบายเพิ่มถ้าต้องการ
- **ผู้เล่น Arcade** ส่งเฉพาะโค้ดขึ้นไป แล้ว server เป็นผู้รันเทส เรียกตัวตรวจคุณภาพโค้ด และ
  อ่านเวลาจากนาฬิกาของตัวเอง คะแนนรอบทั้งก้อนจึงปลอมไม่ได้ และผู้เล่นจะไม่เสียรอบเพราะ
  เครือข่ายของตัวเองช้า เพราะ server รับโค้ดไว้ก่อนแล้วตัดสินตอนปิดรอบ
- **ผู้แข่ง Competitive Arena** ส่งคำตอบที่พิมพ์ภาษาไทยได้ และโจทย์ที่คำตอบไม่ตายตัวผ่านได้จริง
- **ผู้ดูแลการติดตั้ง** นำระบบขึ้นโฮสต์ใดก็ได้ด้วยไฟล์ประกอบ container เดียว โดยยังไม่ต้อง
  ตัดสินใจล่วงหน้าว่าจะใช้ผู้ให้บริการราย ไหน

## User Stories

### ความน่าเชื่อถือของคำตัดสิน

1. As a ผู้เรียน, I want ระบบตัดสินคำตอบของฉันด้วยการรันโค้ดจริงบน server, so that คะแนนที่ฉันได้สะท้อนว่าฉันทำโจทย์ได้จริง
2. As a ผู้เรียน, I want การส่งโค้ดว่างเปล่าถูกปฏิเสธในทุกโจทย์รวมถึงโจทย์ที่ตรวจอัตโนมัติไม่ได้, so that ความก้าวหน้าของฉันไม่ปะปนกับการกดส่งเปล่าๆ
3. As a ผู้เรียน, I want โจทย์ที่ตรวจอัตโนมัติไม่ได้ยังต้องการโค้ดที่ต่างจากโค้ดตั้งต้นและรันได้โดยไม่ error, so that ฉันไม่ได้รางวัลจากการกดส่งทันทีโดยไม่แตะอะไรเลย
4. As a ผู้เล่น Arcade, I want คะแนนรอบถูกคำนวณโดย server ทั้งหมด, so that ไม่มีใครแก้ตัวเลขในเบราว์เซอร์แล้วชนะฉันได้
5. As a ผู้เล่น Arcade, I want ตารางอันดับสะท้อนฝีมือจริง, so that การแข่งขันมีความหมายและทองที่ได้มายุติธรรม
6. As a ผู้เรียน, I want คำตัดสินของโจทย์ข้อเดียวกันเหมือนกันไม่ว่าฉันเจอมันในโหมดไหน, so that ฉันไม่สับสนว่าทำไมคำตอบเดิมผ่านที่หนึ่งแต่ไม่ผ่านอีกที่หนึ่ง
7. As a ทีมพัฒนา, I want มีตัวตรวจคำตอบเพียงตัวเดียวในระบบ, so that การแก้กติกาครั้งเดียวมีผลทุกโหมดและกติกาไม่เลื่อนออกจากกันอีก

### การไม่ตัดสินคนที่เขียนถูกว่าผิด

8. As a ผู้เรียน, I want โปรแกรมที่พิมพ์คำตอบถูกต้องผ่าน แม้จะมีข้อความเตือนออกทาง stderr, so that คำเตือนของไลบรารีไม่ทำให้คำตอบที่ถูกกลายเป็นผิด
9. As a ผู้แข่ง Competitive Arena, I want คำตอบที่ต้องพิมพ์ข้อความภาษาไทยถูกตรวจได้ถูกต้อง, so that โจทย์ภาษาไทยไม่กลายเป็นโจทย์ที่ไม่มีใครผ่านได้
10. As a ผู้แข่ง Competitive Arena, I want โจทย์ที่ผลลัพธ์ไม่ตายตัว เช่น การสุ่มรหัส PIN ผ่านได้เมื่อคำตอบตรงรูปแบบที่กำหนด, so that โจทย์ประเภทสุ่มใช้งานได้จริง
11. As a ผู้เรียน, I want โจทย์ที่มีเฉลยผิดถูกแก้ให้ถูกต้อง, so that ฉันไม่เสียเวลาไล่หาข้อผิดพลาดที่ไม่ได้อยู่ในโค้ดของฉัน
12. As a ผู้แข่ง Competitive Arena, I want คำสั่งของโจทย์กับเทสเคสของโจทย์ตรงกัน, so that ฉันทำตามคำสั่งแล้วผ่าน

### ประสบการณ์ของผู้ที่ไม่เคยเขียนโปรแกรม

13. As a ผู้เริ่มต้น, I want ข้อความบอกข้อผิดพลาดเป็นภาษาไทยที่บอกว่าเกิดอะไรขึ้น, so that ฉันเข้าใจโดยไม่ต้องรู้จักคำว่า traceback
14. As a ผู้เริ่มต้น, I want เลขบรรทัดในข้อความผิดพลาดตรงกับบรรทัดที่ฉันเห็นในเอดิเตอร์, so that ฉันหาจุดที่ต้องแก้เจอ
15. As a ผู้เริ่มต้น, I want ปุ่มขอให้ผู้ช่วย AI อธิบายข้อผิดพลาดให้ฟัง, so that ฉันขอความช่วยเหลือเพิ่มได้เมื่อคำอธิบายสั้นๆ ยังไม่พอ
16. As a ผู้เริ่มต้น, I want ระบบไม่เรียก AI ทุกครั้งที่ฉันพิมพ์ผิด, so that ฉันได้คำตอบทันทีสำหรับข้อผิดพลาดพื้นฐานโดยไม่ต้องรอ
17. As a ผู้เรียน, I want เห็นว่าเทสเคสไหนไม่ผ่านและคาดผลลัพธ์อะไร, so that ฉันเทียบกับสิ่งที่โปรแกรมของฉันพิมพ์ออกมาได้
18. As a ผู้เรียน, I want การลองรันในเบราว์เซอร์บอกแค่ผลลัพธ์ที่โปรแกรมพิมพ์ ไม่ตัดสินว่าผ่านหรือไม่ผ่าน, so that ฉันไม่เจอกรณีที่เบราว์เซอร์บอกว่าผ่านแล้วกดส่งได้ไม่ผ่าน
19. As a ผู้เรียน, I want การลองรันยังคงให้ผลทันทีโดยไม่ต้องรอ server, so that ฉันทดลองแก้โค้ดได้ลื่นไหล

### Arcade แบบเรียลไทม์

20. As a ผู้เล่น Arcade, I want ส่งโค้ดขึ้น server ให้ทันเวลารอบ แล้วให้การตัดสินเกิดตอนปิดรอบ, so that ฉันไม่ตกรอบเพราะเครือข่ายของฉันช้าในวินาทีสุดท้าย
21. As a ผู้เล่น Arcade, I want เวลาที่ใช้ถูกวัดจากนาฬิกาของ server, so that ไม่มีใครอ้างเวลาที่เหลือเกินจริงเพื่อเพิ่มคะแนน
22. As a ผู้เล่น Arcade, I want คะแนนคุณภาพโค้ดยังถูกคิดรวมในคะแนนรอบ, so that การเขียนโค้ดที่อ่านง่ายยังมีความหมายเหมือนเดิม
23. As a ผู้เล่น Arcade, I want คะแนนของบอทกับของคนถูกคิดบนสเกลเดียวกัน, so that การแข่งกับบอทยังยุติธรรม
24. As a ผู้เล่น Arcade, I want ระบบส่งคำตอบอัตโนมัติยังทำงานเมื่อฉันไม่ได้กดส่ง, so that ฉันไม่ได้ศูนย์คะแนนทั้งที่เขียนโค้ดไว้แล้ว

### สองภาษา

25. As a ผู้เรียนที่ใช้ภาษาอังกฤษ, I want โจทย์ทุกข้อมีชื่อและคำอธิบายภาษาอังกฤษ, so that การสลับภาษาใช้ได้จริงทั้งเว็บ
26. As a ผู้เรียนที่ใช้ภาษาอังกฤษ, I want สตริงที่ต้องพิมพ์ยังคงเป็นภาษาไทยตามเดิมในคำอธิบายภาษาอังกฤษ, so that ฉันพิมพ์ข้อความที่ระบบคาดไว้ได้ถูกต้อง
27. As a ผู้เรียน, I want เห็นภาษาไทยแทนช่องว่างถ้าโจทย์ข้อนั้นยังไม่มีคำแปล, so that ไม่มีหน้าไหนแสดงหัวข้อว่างเปล่า
28. As a ทีมพัฒนา, I want เติมคำแปลซ้ำได้เรื่อยๆ โดยข้ามข้อที่แปลแล้ว, so that การเพิ่มโจทย์ใหม่ไม่ต้องแปลใหม่ทั้งกอง
29. As a ทีมพัฒนา, I want มีการพิสูจน์ว่าการแปลไม่แตะโค้ดตั้งต้น เฉลย หรือเทสเคส, so that การแปลไม่ทำให้คำตอบที่ถูกกลายเป็นผิดโดยไม่มีใครรู้

### ความพร้อมในการติดตั้งใช้งาน

30. As a ผู้ดูแลการติดตั้ง, I want ที่อยู่ของ API มาจากการตั้งค่าสภาพแวดล้อม, so that ระบบทำงานได้บนโดเมนจริงโดยไม่ต้องแก้โค้ด
31. As a ผู้ดูแลการติดตั้ง, I want ไฟล์ประกอบ container ที่มีทั้ง Node, Python และไลบรารีที่โจทย์ต้องใช้ครบ, so that ระบบตรวจคำตอบทำงานบนเครื่องปลายทางเหมือนบนเครื่องพัฒนา
32. As a ผู้ดูแลการติดตั้ง, I want เสิร์ฟหน้าเว็บที่ build แล้วจากที่เดียวกับ API, so that ติดตั้งครั้งเดียวจบและไม่มีปัญหาข้ามโดเมน
33. As a ผู้ดูแลการติดตั้ง, I want ไฟล์ที่ผู้ใช้อัปโหลดไม่หายเมื่อติดตั้งเวอร์ชันใหม่, so that รูปโปรไฟล์และสื่อของบทเรียนไม่หายไปหลังอัปเดต
34. As a ทีมพัฒนา, I want เลือกผู้ให้บริการโฮสต์ทีหลังได้โดยไม่ต้องรื้อโค้ด, so that เราตัดสินใจเรื่องนั้นได้หลังซ่อมบั๊กเสร็จ
35. As a ทีมพัฒนา, I want จำนวนโจทย์ที่ตรวจอัตโนมัติไม่ได้ถูกคำนวณใหม่หลังติดตั้งไลบรารีครบ, so that โจทย์ที่ตรวจได้จริงกลับมาถูกตรวจแทนที่จะถูกยกเว้นต่อไป
36. As a อาจารย์ผู้ประเมิน, I want เปิดเว็บจาก URL จริงแล้วใช้งานได้ทุกโหมด, so that ประเมินจากระบบที่ทำงานจริง ไม่ใช่จากวิดีโอหรือการเดโมบนเครื่องนักศึกษา

### ความถูกต้องของข้อมูลและการดูแลระบบ

37. As a แอดมิน, I want การสร้างโจทย์ใหม่สำเร็จทั้งหมดหรือไม่สำเร็จเลย, so that ไม่เกิดโจทย์ที่ไม่ถูกผูกกับโหมดใดและมองไม่เห็นจากที่ไหน
38. As a แอดมิน, I want สร้างโจทย์พร้อมกันกับแอดมินอีกคนได้, so that ไม่มีใครเจอข้อผิดพลาดจากการชนกันของหมายเลขในโหมด
39. As a ผู้เรียน, I want ระบบยังตอบสนองเมื่อมีคนส่งคำตอบพร้อมกันหลายคน, so that การเรียนของฉันไม่ค้างเพราะคนอื่นกำลังถูกตรวจอยู่
40. As a ทีมพัฒนา, I want ฐานข้อมูลไม่มีตารางค้างที่ไม่มีโค้ดส่วนใดอ้างถึง, so that คนที่มาดูต่อไม่สับสนว่าข้อมูลจริงอยู่ที่ไหน

### การรักษางานและคุณภาพของชุดทดสอบ

41. As a ทีมพัฒนา, I want งานทั้งหมดถูกเก็บไว้บน repository ส่วนกลาง, so that งานหลายสิบชั่วโมงไม่ได้อยู่บนเครื่องเดียวโดยไม่มีสำเนา
42. As a ทีมพัฒนา, I want ไม่มีคีย์ของบริการภายนอกอยู่ในโค้ดหรือในประวัติของ repository, so that repository สาธารณะไม่เปิดเผยคีย์ที่ใช้งานได้จริง
43. As a ทีมพัฒนา, I want ชุดทดสอบล้มเมื่อระบบพัง ไม่ใช่ผ่านโดยไม่ได้ตรวจอะไร, so that ผลสีเขียวมีความหมาย
44. As a ทีมพัฒนา, I want เครื่องมือตรวจโค้ดรายงานข้อผิดพลาดจริงแทนที่จะถูกกลบด้วยคำเตือนจำนวนมาก, so that เราเห็นปัญหาที่ซ่อนอยู่
45. As a ผู้เรียนที่ใช้อินเทอร์เน็ตช้า, I want หน้าเว็บโหลดเร็วขึ้น, so that ฉันเริ่มเรียนได้โดยไม่ต้องรอนาน
46. As a ทีมพัฒนา, I want ผู้ที่ไม่เคยเขียนโปรแกรมจริงได้ทดลองใช้ก่อนส่งงาน, so that เราพบจุดที่คนกลุ่มเป้าหมายติดจริง ซึ่งไม่มีชุดทดสอบใดแทนได้

## Implementation Decisions

### สถาปัตยกรรมของการตัดสินและการให้คะแนน

- แยกสองชั้นออกจากกันอย่างชัดเจนตาม `CONTEXT.md`: **คำตัดสิน** เป็นของกลาง มีที่มาที่เดียว
  และอยู่ฝั่ง server ทั้งหมด · **การให้คะแนน** เป็นของแต่ละโหมด และเรียกใช้คำตัดสินเป็นวัตถุดิบ
- ตัวตรวจกลางรับ *โจทย์* กับ *โค้ด* แล้วคืนผลว่าผ่านกี่เทสเคส พร้อมรายละเอียดรายเทสเคส
  ไม่รับรู้เรื่อง XP ทอง อันดับ หรือเวลา
- ทั้งสามโหมดเรียกตัวตรวจกลางตัวเดียวกัน ตัวรัน Python ที่ซ้ำอยู่ในชั้น API ถูกลบทิ้ง
  เหลือโมดูลตัวรันเดียวที่ตั้งค่า encoding เป็น UTF-8 เสมอ

### การตัดสินผ่าน/ไม่ผ่าน

- ผลการตัดสินมาจากผลลัพธ์ทาง stdout เทียบกับค่าที่คาดไว้ ประกอบกับสถานะการจบโปรแกรม
  **ไม่ใช้การมีข้อความใน stderr เป็นเกณฑ์ตัดสินว่าผิด**
- รองรับค่าที่คาดไว้แบบรูปแบบ (regular expression) นอกเหนือจากการเทียบตรงตัว สำหรับโจทย์
  ที่ผลลัพธ์ไม่ตายตัว การตีความรูปแบบอยู่ในตัวตรวจกลางที่เดียว
- โจทย์แบบเรียกฟังก์ชันต้องกันไม่ให้โค้ดของผู้เรียนปลอมผลการตัดสินได้ ตัวคั่นที่ใช้สื่อสาร
  ผลลัพธ์ระหว่างโปรแกรมที่รันกับตัวตรวจต้องเดาไม่ได้ล่วงหน้าและตรวจสอบความถูกต้องได้
- การครอบโค้ดของผู้เรียนด้วยโค้ดเสริมต้องไม่ทำให้เลขบรรทัดที่รายงานคลาดจากไฟล์ที่ผู้เรียนเห็น

### โจทย์ที่ตรวจอัตโนมัติไม่ได้

- แยกสองแนวคิดที่เคยใช้ธงเดียวกัน: **ตรวจอัตโนมัติได้** เป็นคุณสมบัติของโจทย์ ส่วน
  **รับไว้โดยไม่ตัดสิน** เป็นสิ่งที่เกิดกับการส่งคำตอบ
- เกณฑ์ของโจทย์กลุ่มนี้: โค้ดต้องต่างจากโค้ดตั้งต้นที่ระบบให้มา **และ** ต้องรันได้โดยไม่เกิด
  ข้อผิดพลาด จึงจะรับไว้และให้รางวัล
- ถ้าโค้ดล้มเพราะไม่มีไลบรารีที่โจทย์ตั้งใจให้ใช้บนเครื่องนั้น ให้ถอยไปใช้เกณฑ์ตรวจไวยากรณ์แทน
  **ห้ามตัดสินว่าผิด** — เป็นตาข่ายกันระบบพังตอนย้ายเครื่อง ไม่ใช่เกณฑ์หลัก
- ค่าที่บอกว่าโจทย์ข้อใดตรวจอัตโนมัติได้ ต้องคำนวณจากการรันเฉลยจริง ไม่ใช่กำหนดด้วยมือ
  และต้องคำนวณใหม่ทุกครั้งที่ชุดไลบรารีบนเครื่องเปลี่ยน

### Arcade

- สัญญาการส่งคำตอบเปลี่ยนจาก "ส่งคะแนน" เป็น **"ส่งโค้ด"** server เป็นผู้รันเทส เรียกตัวตรวจ
  คุณภาพโค้ด และอ่านเวลาที่ใช้จากกำหนดเวลาของรอบที่ตัวเองเป็นคนตั้ง แล้วคิดคะแนนรอบทั้งก้อน
- server **รับโค้ดเก็บไว้ก่อน แล้วตัดสินตอนปิดรอบ** — สิ่งที่ผู้เล่นต้องทำทันเวลาคือส่งโค้ด
  ส่วนความเร็วในการตัดสินเป็นภาระของ server ช่วงสรุปรอบที่มีอยู่แล้วคือจังหวะที่ใช้ตัดสิน
- การตัดสินฝั่งเบราว์เซอร์ถูกถอดออกจากเส้นทางการให้คะแนน เหลือไว้เฉพาะเป็น *ลองรัน*
- คะแนนของบอทยังถูกสังเคราะห์ฝั่ง server บนสเกลเดียวกับผู้เล่นจริงเหมือนเดิม

### ข้อความบอกข้อผิดพลาดสำหรับผู้เริ่มต้น

- มีตัวแปลงข้อผิดพลาดหนึ่งตัวอยู่ฝั่ง server ทำหน้าที่แปลงผลจากการรันเป็นข้อความภาษาไทย
  ที่สั้นและบอกสิ่งที่ต้องทำต่อ ครอบคลุมข้อผิดพลาดที่ผู้เริ่มต้นพบบ่อย เช่น ใช้ตัวแปรก่อนสร้าง
  ไวยากรณ์ผิด ย่อหน้าไม่ถูก ชนิดข้อมูลไม่เข้ากัน ลืมเครื่องหมายท้ายบรรทัด และลืมปิดวงเล็บ
- ข้อความนี้เดินทางไปกับผลการส่งคำตอบทาง API จึงใช้ได้เหมือนกันทุกโหมดและทุกหน้าจอ
- ผู้ช่วย AI เป็นทางเลือกที่ผู้เรียนกดเรียกเอง ไม่ถูกเรียกอัตโนมัติทุกครั้งที่ตอบผิด
  และใช้คีย์ของแชทบอทเท่านั้น **ห้ามใช้คีย์ของตัวตรวจคุณภาพโค้ดใน Arcade**

### ความถูกต้องของข้อมูลและการสร้างโจทย์

- การสร้างโจทย์ใหม่ต้องเกิดในทรานแซกชันเดียว ทั้งตัวโจทย์และทะเบียนโหมด และการกำหนด
  **หมายเลขในโหมด** ต้องกันการชนกันเมื่อมีการสร้างพร้อมกัน
- การรันโค้ดของผู้เรียนต้องไม่เกิดขณะที่ถือทรานแซกชันฐานข้อมูลค้างไว้
- โจทย์ที่คำสั่งกับเทสเคสไม่ตรงกันให้ยึด *คำสั่ง* เป็นหลักและเขียนเทสเคสใหม่ให้ตรง
- ตารางสำเนาก่อนรวมคลังโจทย์ยังเก็บไว้เพราะชุดทดสอบใช้เป็นตัวเทียบจริง ส่วน schema ที่ไม่มี
  โค้ดส่วนใดอ้างถึงให้สำรองเป็นไฟล์แล้วนำออกจากฐานข้อมูล

### การติดตั้งใช้งาน

- ที่อยู่ของ API ฝั่งหน้าเว็บมาจากการตั้งค่าสภาพแวดล้อม มีค่าเริ่มต้นเป็นเส้นทางแบบสัมพัทธ์
  เพื่อให้ทำงานได้ทั้งตอนพัฒนาและตอนติดตั้งจริงโดยไม่ต้องแก้อะไร
- ไฟล์ประกอบ container บรรจุ Node, Python และไลบรารีที่โจทย์ต้องใช้ทั้งหมด ซึ่งทำให้
  ไฟล์นี้กลายเป็นคำตอบเดียวของทั้งเรื่องความสามารถในการตรวจและความสามารถในการติดตั้ง
- server เสิร์ฟไฟล์หน้าเว็บที่ build แล้ว และที่เก็บไฟล์อัปโหลดต้องอยู่นอกวงจรการติดตั้ง
- ยังไม่ผูกกับผู้ให้บริการรายใด การเลือกโฮสต์เป็นการตัดสินใจแยกที่ทำได้ภายหลัง

### ลำดับการทำงาน

งานถูกแบ่งเป็นก้อนที่ก้อนหลังพึ่งก้อนหน้า ไม่ได้เรียงตามความง่าย:

0. สำรองงานขึ้น repository ส่วนกลาง หลังเปลี่ยนคีย์บริการภายนอกแล้ว
1. ทำให้คำตัดสินเชื่อถือได้ (ปิดช่องปลอมผล · เกณฑ์ของโจทย์ที่ตรวจไม่ได้ · เลิกใช้ stderr
   ตัดสิน · ตัวรัน Python ตัวเดียว · รองรับค่าคาดหวังแบบรูปแบบ · เลขบรรทัดถูกต้อง ·
   ทรานแซกชันของการสร้างโจทย์ · เลิกรันโค้ดคาทรานแซกชัน)
2. ทั้งสามโหมดใช้คำตัดสินเดียวกัน และ Arcade คิดคะแนนฝั่ง server
3. ประสบการณ์ของผู้เริ่มต้น (ข้อความผิดพลาดภาษาไทย · ปุ่มขอคำอธิบาย · แก้โจทย์ที่ผิด)
4. พร้อมติดตั้งโดยยังไม่ผูกโฮสต์
5. ปิดงานค้าง (คำแปลที่เหลือ · เครื่องมือตรวจโค้ด · ชุดทดสอบบอท · ขนาดไฟล์หน้าเว็บ ·
   เก็บกวาดฐานข้อมูล) และการทดสอบกับผู้เริ่มต้นจริง

## Testing Decisions

### สิ่งที่ทำให้เทสดี

ทดสอบ **พฤติกรรมที่มองเห็นจากภายนอก** เท่านั้น: สำหรับคำตัดสินคือ "โค้ดชุดนี้ผ่านหรือไม่ผ่าน"
สำหรับการให้คะแนนคือ "ยอด XP ทอง และอันดับเปลี่ยนไปเท่าไหร่จริงในฐานข้อมูล" ไม่ทดสอบว่า
ภายในเรียกฟังก์ชันใดหรือมีตัวแปรชื่ออะไร

บทเรียนจากชุดทดสอบเดิมที่ต้องไม่เกิดซ้ำ: ชุดทดสอบความสมบูรณ์ของการส่งคำตอบเคยผ่าน 7/7
ขณะที่ช่องโหว่ยังเปิดอยู่ เพราะมันเลือกทดสอบเฉพาะโจทย์ที่ตรวจอัตโนมัติได้ **ทุกเทสต้องระบุให้ชัด
ว่าเลือกข้อมูลอะไรมาทดสอบ และต้องครอบคลุมกรณีที่ระบบ *ไม่* เดินตามเส้นทางปกติด้วย**
ชุดทดสอบที่ผ่านโดยไม่ได้ตรวจอะไรเลยถือว่าล้มเหลว ไม่ใช่ผ่าน

### Seam ที่ใช้ — ไม่สร้างใหม่ ใช้ของเดิมสามจุด

**Seam A — โมดูลตัวตรวจกลาง** (ต่อยอดจากชุดทดสอบตัวตรวจที่เรียกโมดูลตรงๆ อยู่แล้ว)
ใช้ทดสอบทุกอย่างที่เป็น *คำตัดสิน* เพราะเร็วและไม่ต้องมี server รันอยู่:

- เฉลยของทุกโจทย์ที่ตรวจอัตโนมัติได้ต้องผ่านเทสเคสของตัวเอง
- คำตอบผิดต้องไม่ผ่าน และการพิมพ์ค่าที่มีค่าที่ถูกต้องเป็นส่วนหนึ่งต้องไม่ผ่าน
- โปรแกรมที่พิมพ์คำตอบถูกแต่มีข้อความใน stderr ต้องผ่าน
- โค้ดที่พยายามปลอมผลการตัดสินของโจทย์แบบเรียกฟังก์ชันต้องไม่ผ่าน
- ค่าคาดหวังแบบรูปแบบต้องผ่านเมื่อผลลัพธ์ตรงรูปแบบ และไม่ผ่านเมื่อไม่ตรง
- คำตอบที่พิมพ์ภาษาไทยต้องผ่าน
- ตารางแปลงข้อผิดพลาดเป็นภาษาไทยต้องให้ข้อความและเลขบรรทัดถูกต้องสำหรับข้อผิดพลาด
  แต่ละแบบที่ผู้เริ่มต้นพบบ่อย และเลขบรรทัดต้องตรงกับไฟล์ที่ผู้เรียนเขียน

**Seam B — HTTP endpoint ส่งคำตอบของทั้งสามโหมด** (ต่อยอดจากชุดทดสอบความสมบูรณ์ของ
การส่งคำตอบ และชุดทดสอบขอบเขตคะแนนของ Arcade) ใช้ทดสอบทุกอย่างที่เป็น *การให้คะแนน*
โดยยิงคำขอจริงแล้ว **อ่านยอดกลับจากฐานข้อมูล** เพราะสิ่งที่ต้องปกป้องคือสิ่งที่ถูกจ่ายจริง:

- ส่งโค้ดว่าง ส่งคำตอบผิด และส่งโค้ดที่ไม่ต่างจากโค้ดตั้งต้น ต้องไม่ได้ XP หรือทอง
  **และต้องทดสอบทั้งกับโจทย์ที่ตรวจอัตโนมัติได้และโจทย์ที่ตรวจไม่ได้**
- ส่งเฉลยที่ถูกต้องต้องได้รางวัลตามที่โจทย์กำหนด
- อ้างผลว่าผ่านมาในคำขอโดยไม่ส่งโค้ดต้องถูกปฏิเสธ
- Arcade: ส่งโค้ดขึ้นไปแล้วคะแนนรอบต้องมาจาก server และคะแนนที่ผู้เล่นแนบมาเองต้องไม่มีผล
- Arcade: ส่งโค้ดทันเวลาแต่การตัดสินเกิดตอนปิดรอบ ต้องได้คะแนนตามจริง ไม่ใช่ศูนย์
- Arcade: ส่งซ้ำในรอบเดียวกันต้องไม่สะสมคะแนน และผู้ที่ตกรอบแล้วส่งไม่ได้
- Competitive Arena: คำตอบที่ถูกต้องซึ่งพิมพ์ภาษาไทยต้องได้คะแนนความถูกต้องเต็ม
- ส่งคำตอบพร้อมกันหลายรายการต้องไม่ทำให้คำขออื่นค้าง

**Seam C — ระดับฐานข้อมูล** (ต่อยอดจากชุดทดสอบความตรงกันของคลังโจทย์และชุดตรวจสองภาษา)
ใช้กับความถูกต้องของข้อมูลที่ไม่ต้องรันโค้ด:

- คลังโจทย์ยังให้ข้อมูลตรงกับก่อนรวมทุกแถวทุกคอลัมน์
- โจทย์ทุกข้อมีชื่อและคำอธิบายครบสองภาษา
- ค่าที่ใช้ตัดสิน (โค้ดตั้งต้น เฉลย เทสเคส) ต้องไม่ถูกแตะจากงานแปล พิสูจน์ด้วยการเทียบลายนิ้วมือ
- สตริงที่ต้องพิมพ์ยังคงอยู่ครบตัวอักษรในคำอธิบายภาษาอังกฤษ
- ไม่มีทะเบียนโหมดที่ชี้ไปยังโจทย์ที่ไม่มีอยู่ และไม่มีโจทย์ที่ไม่ถูกผูกกับโหมดใด

### การทดสอบความพร้อมในการติดตั้ง

ไม่มี seam ใหม่ — หลังสร้าง container ให้ยิงชุดทดสอบของ Seam B ใส่ container นั้น
ถ้าผ่านแปลว่า Python และไลบรารีที่จำเป็นอยู่ครบในภาพจริง ไม่ใช่แค่บนเครื่องผู้พัฒนา

### สิ่งที่ชุดทดสอบแทนไม่ได้

การให้ผู้ที่ไม่เคยเขียนโปรแกรมจริง 1–2 คนใช้งานโดยไม่มีใครช่วย แล้วบันทึกว่าติดตรงไหน
เป็นด่านสุดท้ายก่อนถือว่าเสร็จ และเป็นสิ่งเดียวที่ไม่มีสคริปต์ใดทดแทนได้

## Out of Scope

- **การเลือกผู้ให้บริการโฮสต์** เป็นการตัดสินใจแยกที่ทำหลังงานซ่อมเสร็จ งานในสเปกนี้ทำให้
  ระบบพร้อมขึ้นโฮสต์ใดก็ได้ แต่ไม่ได้เลือกให้
- **การแปลคอมเมนต์ในโค้ดตั้งต้น** ยังเป็นภาษาไทยทุกโหมด ต้องเก็บเป็นคอลัมน์แยกซึ่งเป็นงานคนละก้อน
- **การแปลหน้าจอและปุ่มทั้งเว็บ** สเปกนี้ครอบคลุมเฉพาะข้อความของโจทย์
- **การเขียนโจทย์ใหม่หรือเพิ่มจำนวนโจทย์** ยกเว้นการแก้โจทย์ที่ผิดจนทำไม่ได้
- **การเปลี่ยนสูตรคิดคะแนนของโหมดใดๆ** สเปกนี้ย้ายที่คำนวณ ไม่ได้เปลี่ยนสูตร
- **การเปลี่ยนหมายเลขของโจทย์ที่มีอยู่** ห้ามโดยเด็ดขาด มีการอ้างอิงจำนวนมากชี้อยู่
- **การรื้อระบบสิทธิ์ผู้ใช้ การเข้าสู่ระบบ หรือระบบร้านค้า**
- **ประสิทธิภาพในระดับผู้ใช้จำนวนมาก** เป้าหมายคือรองรับการใช้งานจริงระดับชั้นเรียน
  ไม่ใช่การปรับแต่งเพื่อรองรับผู้ใช้พร้อมกันจำนวนมาก
