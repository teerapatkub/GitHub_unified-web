# 09: ตรวจนาฬิกาในรอบกับปุ่มสุ่มร้านใหม่

**What to build:** ผู้เล่นต้องเชื่อนาฬิกาในรอบได้ และเมื่อจ่ายเงินสุ่มร้านใหม่ต้องได้สินค้าชุดใหม่จริง

จาก user test มีสองอาการที่สงสัยแต่ยังไม่ได้วัด:
- ในโหมดเร็ว ตัวนับลดจาก 29s เหลือ 12s ทั้งที่เวลาจริงผ่านไปแค่ประมาณ 6–7 วินาที
- กดสุ่มร้านใหม่แล้วโดนหักเงิน 200 แต่สินค้า 4 ชิ้นยังเหมือนเดิม

**ให้วัดก่อน แล้วแก้เฉพาะที่ผิดจริง** ถ้านาฬิกาผิด ให้คำนวณเวลาจาก deadline ของ server แทนการนับ tick

## ผลการวัด (2026-10-26, dev server, ห้องโหมดเร็ว)
- **นาฬิกา:** ตัวนับลดจาก 23s ถึง 1s ในเวลาจริง 20.1 วินาที (สุ่มอ่านทุก 2 วินาที) ตรงกับเวลาจริงภายใน 1 tick **ไม่ใช่บั๊ก** อาการใน user test น่าจะมาจากแท็บที่ถูกพักไว้เบื้องหลัง
- **สุ่มร้านใหม่:** ใช้งานได้ หักเงิน 200 ราคาครั้งต่อไปเป็น 400 และของเปลี่ยน แต่ server ตอบช้ากว่า 1.5 วินาที (ฐาน Supabase อยู่โตเกียว) และปุ่มไม่บอกสถานะ จึงดูเหมือนไม่ทำงาน
  - แก้ให้ปุ่มขึ้น "กำลังดำเนินการ…" พร้อมไอคอนหมุน และ `aria-busy` ระหว่างรอ
  - พบบั๊กจริงอีกข้อ: การสุ่มอาจได้ของ 4 ชิ้นชุดเดิม จึงให้สุ่มใหม่จนกว่าจะได้ชุดที่ต่างจากเดิม (เทส `arcade-shop-offers.test.js` สุ่ม 500 ครั้งจากของ 5 ชิ้น ก่อนแก้ล้ม)
- ยังไม่ได้ดูสถานะ "กำลังดำเนินการ…" ด้วยตาในเบราว์เซอร์ (แก้หลังจากช่วงร้านค้าของแมตช์ทดสอบผ่านไปแล้ว)
