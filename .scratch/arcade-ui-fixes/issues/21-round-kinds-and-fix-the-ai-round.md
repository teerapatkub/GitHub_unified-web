# 21: รูปแบบรอบ ห้อง "คลาสสิก/ผสม" และรอบ "แก้โค้ดที่ AI เขียน"

**What to build:** หัวห้องเลือกได้ว่าห้องเป็นแบบ "คลาสสิก" (เขียนโค้ดอย่างเดียว) หรือแบบ "ผสม" ห้องแบบผสมจะมีบางรอบเป็น **รอบแก้โค้ดที่ AI เขียน**

ในรอบแก้โค้ด:
- **โจทย์:** ผู้เล่นได้ "คำตอบที่ AI เขียนมา" ซึ่งดูเหมือนถูก แต่ผ่านเทสไม่ครบ และเห็นตั้งแต่ต้นรอบว่าผ่านกี่เทส
- **งานของผู้เล่น:** หาบั๊กแล้วแก้ให้ผ่าน
- **การตัดสิน:** ใช้เทสชุดเดิมของโจทย์ ส่วนคุณภาพวัดด้วย code-metrics เดิม
- **บอท:** พิมพ์จากโค้ดเริ่มต้นจนได้เฉลย (ADR 0005)

นอกจากนี้ ผู้เล่นต้องเห็นรูปแบบของรอบถัดไปก่อนช่วงซื้อของ และประวัติแมตช์ต้องแสดงรูปแบบของแต่ละรอบ

**สิ่งที่ตัดสินใจแล้วใน Spec 0005:**
- **ที่เก็บรูปแบบรอบ:**
  - รูปแบบรอบ (`write`/`fix`/`predict`/`review`) เป็นค่าเฉพาะโหมดในทะเบียนโหมด ไม่ใช่คุณสมบัติของโจทย์
  - แถวเดิมทั้งหมดเป็น `write`
- **การบันทึกในห้อง:**
  - ห้องเก็บรูปแบบของแต่ละรอบคู่กับ id ของโจทย์
  - ห้องเก่าที่ไม่มีค่านี้ให้อ่านเป็น `write`
- **ที่มาของโค้ดเริ่มต้นรอบ `fix`:**
  - ใช้คำตอบผิดที่ bot-coder สร้างไว้และตรวจด้วย `gradeSubmission` แล้ว
  - เลือกเฉพาะคำตอบที่ผ่านอย่างน้อยหนึ่งเทสแต่ไม่ครบ
  - ไม่เรียกโมเดลจริง
- **ลำดับรอบในห้องผสม (4 รอบ):**
  - ทายผลลัพธ์ / เขียน / แก้ / สุ่ม
  - ระหว่างที่ ticket 22 ยังไม่เสร็จ รอบที่ควรเป็น `predict` ให้ใช้ `write` แทน
- **การให้คะแนน:** ไม่มีโมเดลอยู่ในเส้นทางให้คะแนน (ADR 0007)
- **การแก้ schema:**
  - แก้ใน problems schema module เท่านั้น
  - ห้ามเปลี่ยน entry id เดิม

**ต้องถามผู้ใช้ก่อนเริ่ม:** ห้องใหม่จะใช้ "ผสม" เป็นค่าเริ่มต้นหรือไม่

อ้างอิง: Spec 0005 Track G1

**Blocked by:**
- 06, 07, 08, 09: แกนของ Arcade ต้องนิ่งก่อน
- 10: ประวัติแมตช์ต้องแสดงรูปแบบรอบได้
