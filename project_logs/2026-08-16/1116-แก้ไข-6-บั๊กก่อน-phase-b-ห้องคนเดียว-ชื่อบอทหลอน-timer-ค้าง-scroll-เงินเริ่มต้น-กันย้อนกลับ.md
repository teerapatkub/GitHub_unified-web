### 3) เวลาในเกมไม่นับถอยหลัง ทำให้ไปรอบต่อไปไม่ได้
**สาเหตุที่ตรวจสอบได้**: ระบบนับเวลาเดิมใช้ `setTimeout(() => setTimeLeft(prev => prev - 1), 1000)` ลดค่าทีละ 1 ต่อ tick — วิธีนี้เปราะบางต่อการที่เบราว์เซอร์หน่วงความถี่ของ `setTimeout` เมื่อแท็บไม่ได้อยู่ในโฟกัส (Chrome throttling) ถ้า tick ใดถูกดีเลย์/ข้าม เวลาที่แสดงจะ "ค้าง" ไม่สอดคล้องกับเวลาจริงที่ผ่านไป และไม่มีกลไกแก้ตัวเอง (self-correction)
**แก้ไข**: เปลี่ยนเป็นระบบนับเวลาแบบอิง wall-clock deadline — เพิ่ม `phaseDeadlineRef` เก็บ timestamp สัมบูรณ์ (`Date.now() + duration*1000`) ทุกครั้งที่เริ่ม phase ใหม่ผ่านฟังก์ชันช่วย `startPhaseTimer(duration)` ตัวใหม่ (แทนที่ `setTimeLeft(ROUND_TIMES.X)` เดิมทั้ง 6 จุดเรียก) แล้วให้ tick แต่ละครั้งคำนวณเวลาที่เหลือจริงจาก deadline นี้เสมอ (`Math.ceil((deadline - now)/1000)`) แทนการลบทีละ 1 แบบสะสม — ทำให้แม้ tick ใดถูกดีเลย์ไปกี่วินาทีก็ตาม tick ถัดไปจะแก้ค่าให้ตรงกับเวลาจริงทันที ไม่ค้างอีก
**หมายเหตุ**: ตรวจสอบด้วย React fiber โดยตรงพบว่า state `timeLeft` ที่แท้จริงลดลงถูกต้อง (60→58 หลังผ่านไปหลายวินาที) แม้จอที่แสดงผลจะดูเหมือนค้าง — ตรงกับพฤติกรรม `document.hidden` throttling ของแท็บอัตโนมัติที่เจอซ้ำหลายครั้งในเซสชันนี้ ไม่สามารถยืนยัน 100% ว่าเป็นบั๊กเดียวกับที่ผู้ใช้เจอในเบราว์เซอร์จริงหรือไม่ แต่การแก้แบบ deadline-based นี้ทำให้ระบบทนทานขึ้นในทุกกรณีโดยไม่มีข้อเสีย

### 5) เงินเริ่มต้น 0 + ได้เงินตามอันดับที่ทำได้ในแต่ละรอบ
**ตกลงกับผู้ใช้**: ตารางคงที่ 5 อันดับ 🪙 500/400/300/200/100 (อันดับคำนวณจากคะแนนของรอบนั้นๆ เทียบเฉพาะผู้เล่น/บอทที่ยังไม่ตกรอบ)
**แก้ไข**:
- เงินเริ่มต้นเปลี่ยนจาก 1000 → 0 ทุกจุด: `playerState` เริ่มต้น, `opponents` เริ่มต้น (BOT_NAMES placeholder), fallback `p.cash || 1000` ทั้ง 2 จุด, DB column default (`server/db.js` — พร้อม migration `ALTER TABLE ... ALTER COLUMN cash SET DEFAULT 0` แบบ idempotent สำหรับฐานข้อมูลเดิม), และ REMAIN-choice reset ใน `server.js`
- `evaluateRound()` เขียนใหม่: คำนวณคะแนนของรอบนั้น (ไม่ใช่คะแนนสะสม) ของผู้เล่นทุกคนที่ยังไม่ตกรอบ จัดอันดับ 1-N แล้วจ่ายเงินตาม `RANK_CASH_REWARDS = [500, 400, 300, 200, 100]` แทนสูตรเดิมที่อิง `passCount*150+readability*2`
- **พบบั๊กแทรกซ้อนระหว่างแก้ข้อนี้**: `BotAIEngine` (`botAI.js`) มีระบบเงินภายในของตัวเองที่แยกจากระบบจริง (`this.cash += 250` ทุกครั้งที่บอท "พิมพ์โค้ดเสร็จ" จำลอง) และ `botManager.js` ซิงก์ `cash: botInstance.cash` ทับกลับเข้า `opponents` state ทุก tick — ถ้าไม่แก้ เงินรางวัลตามอันดับที่เพิ่งจ่ายจะถูกทับด้วยค่าเงินภายในปลอมทันทีในติ๊กถัดไป (บั๊กรูปแบบเดียวกับที่เคยพบกับ `score` ในรอบก่อนหน้าของเซสชันนี้) แก้โดย: ลบการเพิ่มเงินภายในจากการพิมพ์โค้ดเสร็จออกจาก `botAI.js` (คงเหลือแค่ `score` ภายในไว้ใช้เฉพาะ heuristic เลือกเป้าหมายของบอทเอง) และเพิ่มเมธอด `botManager.awardCash(name, amount)` ให้ `evaluateRound()` เรียกเพื่อฝากเงินรางวัลเข้า `BotAIEngine` instance จริงโดยตรง ทำให้เงินที่แสดงผล = เงินที่บอทใช้ซื้อของจริงเป็นค่าเดียวกันเสมอ
