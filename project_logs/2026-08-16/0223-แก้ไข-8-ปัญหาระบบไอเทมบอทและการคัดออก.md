# บันทึกการทำงาน (Work Log)

**วันที่และเวลา**: 2026-08-16 02:23
**ผู้ทำงาน**: Person 3 (Arcade Battle Royale & Overall System Architecture)
**บริบท**: ผู้ใช้เล่นทดสอบจริงกับบอท 4 ตัว (3 เกม) แล้วรายงานปัญหา 8 ข้อ พร้อมรายละเอียดเพิ่มเติมอีก 3 ข้อระหว่างชี้แจง (รวม 11 จุด) ทั้งหมดสืบเนื่องจากการที่ `botAI.js` ไม่เคยเดินตาม semantics เดียวกับที่ผู้เล่นจริงใช้อยู่แล้ว

## สาเหตุร่วม
ฝั่งผู้เล่น (`initiateItemUse`/`executeItem` ใน `ArcadeBattleRoyale.jsx`) แยกไอเทม buff/attack/aoe ถูกต้องอยู่แล้ว แต่ `botAI.js` ปฏิบัติกับไอเทมทุกชิ้นเหมือนเป็น "ซื้อเก็บแล้วยิงใส่ผู้เล่น" หมด ไม่สนใจ `type`, ใช้ list ไอเทม 7 ชิ้นที่ hardcode ไม่ตรงกับ `SHOP_ITEMS` จริง 15 ชิ้น, ไม่เช็คว่าเป้าหมายโดนดีบัฟอยู่แล้วหรือยัง, มุ่งเป้าที่ผู้เล่นมนุษย์ตายตัว, และไม่ถูกจำกัดให้ซื้อได้เฉพาะช่วง Shop

## สิ่งที่แก้ไข

### ไฟล์ใหม่: `client/src/bot/shopCatalog.js`
Catalog ไอเทมทั้ง 15 ชิ้น (id/type/price/name) แยกไฟล์ต่างหาก ไม่ import จาก `ArcadeBattleRoyale.jsx` โดยตรงเพื่อเลี่ยง circular import (หน้านั้น import `botManager.js` ซึ่ง import `botAI.js` อยู่แล้ว)

### `client/src/bot/botAI.js` (เขียนใหม่เกือบทั้งไฟล์)
1. **แก้บั๊ก Shield**: เดิมเช็ค `chosenItem.type === 'shield'` (ผิด field เพราะ item จริงมี `type:'buff', id:'shield'`) ทำให้ Shield หลุดไปอยู่ใน inventory แล้วถูกใช้ "โจมตี" คนอื่นแทนที่จะป้องกันตัวเอง
2. **แยก buff/attack/aoe ตรงกับผู้เล่นจริง**: ซื้อแล้วเข้า inventory เหมือนกันทุกประเภท (ตรงกับที่ตรวจโค้ดผู้เล่นจริงพบว่าเป็นแบบนั้น ไม่ใช่ instant-on-purchase อย่างที่เข้าใจตอนแรก) ตอน "ใช้" ค่อยแยก: `buff` ใช้ตัวเองทันที, `aoe` ยิงทุกเป้าหมายทันที, `attack` เลือกเป้าหมายก่อน
3. **ซื้อได้เฉพาะช่วง Shop**: ก่อนหน้านี้กันไว้แค่ ROUND_1 เท่านั้น ตอนนี้ปิดการซื้อไอเทมใหม่ทั้งหมดนอกช่วง `SHOP_1`/`SHOP_2` แก้ปัญหา "ไอเทมเหมือนไม่มีวันหมด" ที่มาจากบอทมีรายได้ต่อเนื่องจากคะแนนเขียนโค้ดในตัว
4. **ใช้ SHOP_CATALOG จริงทั้ง 15 ชิ้น + ให้น้ำหนัก `favoriteItems`**: เดิม `favoriteItems` ที่นิยามไว้ใน `botProfiles.js` ไม่เคยถูกใช้เลย ตอนนี้บอทจะพยายามซื้อจาก favorite ก่อนถ้าซื้อไหว ไม่งั้น fallback ไปของราคาที่พอซื้อได้ ทำให้รูปแบบการซื้อต่างกันตาม persona และเงินคงเหลือจริง
5. **จำกัดกระเป๋า 3 ชิ้น, AOE ได้ 1 ชิ้น (นับรวมใน 3)**: เพิ่มเงื่อนไขก่อนซื้อทุกครั้ง
6. **กรองเป้าหมายที่โดนดีบัฟอยู่แล้วออกจากตัวเลือก (เฉพาะ `attack`)**: ถ้าไม่มีเป้าที่ว่างเลยจะเก็บไอเทมไว้ในกระเป๋าก่อน ไม่เสียของทิ้ง — `aoe` ไม่ถูกกรอง (ยิงทับดีบัฟเดิมได้เป็นข้อยกเว้นตามที่ผู้ใช้ระบุ)
7. **เป้าหมายเริ่มต้นเปลี่ยนเป็น "อันดับ 1 ปัจจุบัน"**: จากเดิม "มุ่งผู้เล่นมนุษย์ตายตัว" เปลี่ยนเป็นคำนวณคะแนนสูงสุด ณ ขณะนั้นจากผู้เล่นที่ยังไม่ตกรอบทั้งหมด (รวมบอทคู่แข่งด้วย) ยกเว้นมี revenge target ค้างอยู่ (ยังคงมีสิทธิ์เหนือกว่าตามเดิม)

### `client/src/bot/botManager.js`
- Sync สถานะ `isDebuffed` ของแต่ละบอทกลับเข้า `opponents` state ทุก tick (จุดเดิมที่ sync score/cash/eliminated) ให้ UI ผู้เล่นใช้เกรย์เอาต์เป้าหมายได้
- **เขียนใหม่การจัดการ cashSteal/taxCollection**: ย้ายการคำนวณยอดโอนเงินมาไว้ที่นี่ทั้งหมด (คำนวณสดจาก cash ปัจจุบันจริง ไม่ใช้ค่าที่ค้างมาจาก `botAI.js`) และเช็ค Shield ป้องกันก่อนเสมอ (รวมถึงป้องกันไอเทมประเภทเศรษฐกิจ ไม่ใช่แค่ดีบัฟ) ป้องกันปัญหาโบนัสเงินซ้ำซ้อนถ้าเป้าหมายมี Shield บล็อกไว้

### `client/src/pages/ArcadeBattleRoyale.jsx`
1. เพิ่ม `hasSubmittedThisRound` flag — ตั้ง `true` ตอนกดส่งคำตอบ, รีเซ็ต `false` ทุกครั้งที่ขึ้นรอบใหม่ (ครบทั้ง 4 จุดที่เริ่มรอบ) ใช้ปิดปุ่มใช้ไอเทมจนกว่าจะขึ้นรอบถัดไป (ผู้เล่นที่ส่งแล้ว = ผู้ชม ตามที่ผู้ใช้ต้องการ)
2. เกรย์เอาต์การ์ดคู่แข่งที่โดนดีบัฟอยู่ในหน้าเลือกเป้าหมาย (กดไม่ติด, มีป้าย "โดนไอเทมอยู่ — เลือกเป้าอื่นแทน")
3. แจ้งเตือน: เปลี่ยน id จาก `Date.now()` เป็นตัวนับ (กันชนกันตอนยิงถี่ในหน่วย ms เดียวกัน) + จำกัดแสดงพร้อมกันสูงสุด 5 อัน ตัดอันเก่าทิ้งอัตโนมัติ
4. แก้จำนวนคนคัดออกต่อรอบให้ตรง 5→3→2→1: เพิ่ม `eliminateBottom(2)` หลังรอบ 1 (เดิมไม่มี), เปลี่ยนหลังรอบ 2 จาก `eliminateBottom(2)` เป็น `eliminateBottom(1)`, เพิ่ม `eliminateBottom(1)` หลังรอบ 3 (เดิมไม่มี)
5. เพิ่ม limit กระเป๋า 3 ชิ้น/AOE 1 ชิ้นในปุ่มซื้อของร้านค้า พร้อมแจ้งเตือนเฉพาะ ("กระเป๋าเต็ม" / "ถือ AOE ได้แค่ 1 ชิ้น")
6. เพิ่มส่วน **ขายไอเทมคืนได้ในช่วงร้านค้า** (เฉพาะผู้เล่นมนุษย์) ราคาขายคืน = 50% ของราคาซื้อ
