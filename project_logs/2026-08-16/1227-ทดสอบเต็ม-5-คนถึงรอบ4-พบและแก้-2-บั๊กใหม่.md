## บั๊กที่ 1 (ร้ายแรง): eliminateBottom() ทำงานซ้ำ 2 ครั้งในรอบเดียว

**อาการที่พบ**: ทดสอบรอบแรกด้วยห้อง 5 คน (ผู้เล่น+บอท 4 ตัว) หลังรอบ 2 (ควรคัดออก 2 คน จาก 5→3) หน้าสรุปผลแสดงถูกต้องว่ามีแค่ 2 คนตกรอบ แต่พอเข้ารอบ 3 จริง กลับพบว่ามี **3 คนตกรอบ** ไม่ใช่ 2 คน (ตรวจสอบผ่าน React state โดยตรงยืนยันชัดเจน)

**สาเหตุ**: `useEffect` ที่คุมตัวจับเวลาและเรียก `handlePhaseTransition()` มี dependency array รวม `roomParticipants` ซึ่งได้ array reference ใหม่ทุกครั้งที่ poll สถานะห้อง (ทุก 2 วินาที) ถ้า `roomParticipants` เปลี่ยนอ้างอิงขณะที่ `timeLeft` ยังค้างอยู่ที่ 0 (ระหว่างรอ `handlePhaseTransition()` ซึ่งเป็น async ทำงานอยู่ — รอผลตรวจโค้ดจาก Pyodide + readability judge) useEffect จะทำงานซ้ำอีกรอบโดยใช้ค่า `phase` เดิมที่ยังไม่อัปเดต (stale closure) ทำให้ `evaluateRound()`/`eliminateBottom()` ถูกเรียกซ้ำสำหรับรอบเดียวกัน คัดคนออกซ้ำเกินจำนวนที่ตั้งใจ

**แก้ไข**: เพิ่ม re-entrancy guard ด้วย `useRef` — `isTransitioningRef` ตั้งเป็น `true` ทันทีที่ `handlePhaseTransition()` เริ่มทำงาน และเช็คก่อนว่าถ้ากำลังทำงานอยู่แล้วให้ return ทันที (ไม่ทำซ้ำ) รีเซ็ตกลับเป็น `false` ใน `finally` block เมื่อทำงานเสร็จ ป้องกันการเรียกซ้ำไม่ว่าจะมาจากสาเหตุใดในอนาคตด้วย

**ทดสอบยืนยัน**: ทดสอบห้อง 5 คนซ้ำอีกรอบหลังแก้ ตรวจผ่าน React state โดยตรงยืนยันว่าหลังรอบ 2 เหลือผู้รอดชีวิตพอดี 3 คน (ไม่ใช่ 2) ตรงตามสเปค 5→3 ทุกประการ

## บั๊กที่ 2: โค้ดตั้งต้นของรอบที่ 4 เป็นเฉลยสำเร็จรูป ไม่ใช่โจทย์เปล่า

**อาการที่พบ**: เข้าถึงรอบ 4 จริงเป็นครั้งแรกในเซสชันนี้ พบว่าช่องเขียนโค้ดมีคำตอบที่ถูกต้องสมบูรณ์อยู่แล้ว (`def max_sub_array(nums): ... return max_so_far` เต็มฟังก์ชัน) ทำให้ผู้เล่นกดส่งได้เลยโดยไม่ต้องเขียนโค้ดอะไรเลย

**สาเหตุ**: คอลัมน์ `initial_code` ในตาราง `arcade_tasks` ถูก seed ไว้เป็นเฉลยสมบูรณ์ (สำหรับใช้เป็นสื่อการเรียนของระบบ Person 1 เดิม ไม่ใช่สำหรับโหมดแข่งขันนี้) `getRound4Task()` ที่เพิ่งเขียนดึงค่า `initial_code` มาใช้ตรงๆ โดยไม่ได้ตัดเฉลยออก

**แก้ไข**: ปรับ `getRound4Task()` ให้ดึงเฉพาะบรรทัดประกาศฟังก์ชัน (`def ชื่อฟังก์ชัน(...):`) ด้วย regex แล้วต่อท้ายด้วย placeholder เดียวกับที่ใช้ในรอบ 1-3 (`# Write your python code here` + `pass`) ก่อนส่งเป็น `initialCode` ให้ผู้เล่น — ส่วน `functionName`/`testCases` ที่ใช้ตรวจคำตอบจริงยังคงดึงจากซอร์สเดิมถูกต้อง ไม่กระทบ

**ทดสอบยืนยัน**: ทดสอบห้อง 5 คนอีกรอบ (รอบที่ 3 ของการทดสอบวันนี้) ยืนยันหน้ารอบ 4 แสดงชื่อโจทย์/คำอธิบายจาก DB ถูกต้อง ("1. ผลรวมย่อยสูงสุด / อัลกอริทึม Kadane (Max Subarray Sum)") และช่องโค้ดแสดงแค่ `def max_sub_array(nums):` + placeholder เท่านั้น ไม่มีเฉลยติดมา

## ผลการทดสอบเต็มรูปแบบ (หลังแก้ทั้ง 2 บั๊ก)

ทดสอบห้อง 5 คน (ผู้เล่น + บอท 4 ตัว) เล่นจนจบครบทั้ง 4 รอบจริงผ่านเบราว์เซอร์:
- **รอบ 1**: ไม่คัดออก (5→5) หน้าสรุปแสดงอันดับ 1-5 พร้อมเหรียญ 500/400/300/200/100 ถูกต้อง ไม่มีป้ายตกรอบ
- **รอบ 2**: คัดออก 2 คนถูกต้อง (5→3) ยืนยันผ่าน React state ตรงว่าเหลือผู้รอด 3 คนพอดี
- **รอบ 3**: คัดออก 1 คนถูกต้อง (3→2)
- **รอบ 4**: โจทย์จาก DB จริง พร้อมโค้ดตั้งต้นเป็นช่องว่างถูกต้อง คัดออกคนสุดท้าย (2→1)
- **หน้าผลสรุป**: จัดอันดับทั้ง 5 คนถูกต้องตามคะแนนสะสม ผู้เล่นชนะด้วยคะแนนสูงสุด (102,800,000 pt)
