# ไอเทมโจมตีบอท (Ink Fog / Time Freeze) ทำให้บอทเสียคะแนนจริง

**วันที่:** 2026-10-18 04:40 (Asia/Bangkok) — Person 3 (Arcade)
ต่อจากข้อที่ค้างไว้ใน `project_logs/2026-10-17/2010-arcade-playtest-every-rank-and-fixes.md`
("ไอเทมโจมตีบอทไม่มีผลต่อคะแนนบอท") ซึ่งตั้งใจแยกออกมาเพราะเปลี่ยนความเก่งของบอท

## ปัญหา

- `synthesizeBotRoundScore` ใน `server/arcade/phase-finalizer.js` สุ่มคะแนนบอทจากระดับห้องอย่างเดียว
  ไม่ดู `bot_state.progress` (หลอดที่ `server/arcade/bot-ticker.js` เดิน) และไม่ดูเอฟเฟกต์ที่โดน
  - เวลาส่งสุ่มแบบ uniform ทั้งรอบ
- Ink Fog / Time Freeze หยุดหลอดได้จริง แต่หลอดเป็นแค่ภาพ คะแนนไม่เปลี่ยน
  - ที่มีผลกับบอทจริงมีแค่ Cash Steal / Tax Collector (หักเงิน)
- Quick Mode (รอบ 30 วิ): หลอดเดินด้วยความเร็วเท่ารอบ 60 วิ เลยแทบไม่เคยถึง 100%
  แต่บอทยังได้คะแนนเต็มสูตรเหมือนทำเสร็จ

## กติกาใหม่ (อธิบายได้ในประโยคเดียว: "คะแนนบอทอ่านจากหลอดของมัน")

| สถานะหลอดตอนหมดเวลา | ข้อที่ผ่าน (test) | คะแนนความเร็ว (time) | คุณภาพ (quality) |
|---|---|---|---|
| ถึง 100% ที่วินาที T | ตามสุ่มระดับห้องเหมือนเดิม | คิดจาก T เหมือนเวลาส่งของคน | ตามสุ่มเหมือนเดิม |
| ค้างที่ p% | สุ่มระดับห้อง × p/100 | 0 (เหมือนคนที่ถูกส่งอัตโนมัติตอนหมดเวลา) | ตามสุ่มเหมือนเดิม |
| ไม่ได้ทำงานรอบนี้เลย (state เป็นของรอบก่อน) | 0 | 0 | ตามสุ่มเหมือนเดิม |

- โดน Fog/Freeze → หลอดหยุด → ถึง 100% ช้าลง (เสียคะแนนความเร็ว) หรือไม่ถึงเลย (เสียข้อที่ผ่านด้วย)
- คุณภาพไม่ถูกลด: บอทที่โดนหมอกเขียนโค้ดได้น้อยลง ไม่ใช่เขียนแย่ลง
- โดนหลังหลอดเต็มแล้วไม่มีผล ตรงกับคนที่ส่งแล้ว editor ล็อก

## การปรับความเร็วหลอด (เพื่อให้บอทที่ไม่โดนโจมตีเก่งเท่าเดิม)

ถ้าใช้หลอดตัดสินโดยไม่ปรับอะไร บอทจะอ่อนลง ~10% ทุกระดับทั้งที่ไม่มีใครยิง
เพราะหลอดเดิม (22–34 ก้าว) เต็มช้ากว่ากลางรอบ ส่วนเวลาสุ่มแบบเดิมเฉลี่ยที่กลางรอบพอดี จึงปรับสองอย่าง:

1. **จำนวนก้าวต่อรอบ 22–34 → 14–24** (`BOT_MIN_STEPS`/`BOT_STEP_SPREAD` ใน `bot-ticker.js`)
   - บอทเฉลี่ยทำเสร็จราวกลางรอบ
   - PyNinja 17–29 วิ, BugHunter 31–53 วิ ในรอบ 60 วิ
   - บอทเร็ว/ช้ายังต่างกันตาม `typingSpeedMs` ของแต่ละตัว
2. **ความเร็วหลอดตามความยาวรอบของห้อง** (`roundPaceScale`): Quick Mode ก้าวละครึ่งเวลา
   - หลอดเต็มในสัดส่วนของรอบเท่ากับห้องปกติ
   - แก้ปัญหาหลอดไม่ถึง 100% ใน Quick Mode โดยไม่ทำให้บอท Quick Mode อ่อนกว่าเดิม

ผลจำลอง Monte Carlo (200k รอบ/ระดับ เฉลี่ยทั้ง 5 persona) คะแนนเฉลี่ยต่อรอบของบอทที่ไม่โดนโจมตี:

| เคส/ระดับ | easy | default | medium | hard |
|---|---|---|---|---|
| 3 เคส เดิม | 92.9 | 134.7 | 166.4 | 185.7 |
| 3 เคส ใหม่ | 92.2 | 133.4 | 164.8 | 184.1 |
| ถ้าใช้หลอดเดิม 22–34 ก้าว | 84.4 | 121.4 | 148.4 | 166.1 |

ต่างจากเดิมไม่เกิน ~1% ทุกระดับ (4 และ 2 เคสให้ผลแบบเดียวกัน) จึง **ไม่ได้แตะ `botSkillByDifficulty`**

ที่เปลี่ยนจริงคือความต่างระหว่าง persona: เดิมทุกตัวสุ่มเวลาเท่ากัน ตอนนี้ตัวพิมพ์เร็วได้คะแนนความเร็วมากกว่า
(default 3 เคส: PyNinja ~140, BugHunter ~124)

## ผลกระทบ / ยังไม่ได้ทำ

- **ยังไม่ได้เล่นผ่าน dev server จริง** (CLAUDE.md ขอให้ทดสอบจริงเมื่อแตะบอท) เทสข้างบนรัน ticker + finalizer ตัวจริงกับ DB จริง
  แต่ยังไม่มีคนนั่งยิง Fog ใส่บอทแล้วดูคะแนนบนจอ
- `test:score`, `test:bots`, `test:draw`, `test:spectator` ต้องมี server ที่ :3001 ไม่ได้รัน
- หลอดบนจอเดินเร็วขึ้น (เต็มเร็วกว่าเดิมราว 1/3) และเต็มใน Quick Mode แล้ว เป็นแค่ภาพ ไม่ต้องแก้ client
- ไอเทมโจมตีตัวอื่น (Blackout, Screen Shake, Key Scrambler ฯลฯ) ยังไม่มีผลกับบอท ticker หยุดหลอดเฉพาะ `inkFog`/`timeFreeze`
  ถ้าต้องการให้ทุกตัวมีผล อาจให้หลอดเดินช้าลงครึ่งหนึ่งระหว่างโดน แต่เป็นการเปลี่ยนสมดุลอีกเรื่อง ต้องตัดสินใจแยก
- บอทที่หลอดเต็มแล้วยังไม่นับเป็น `has_submitted` คนจึงยังยิงไอเทมใส่ได้ (เสียของฟรีเหมือนยิงคนที่ส่งแล้ว)
- schema ไม่เปลี่ยน (`finishedAt` เป็น key ใหม่ใน JSONB `bot_state`)
- รอบที่เล่นค้างอยู่ตอน deploy: หลอดเต็มแต่ไม่มี `finishedAt` ได้ข้อที่ผ่านครบแต่ไม่มีคะแนนความเร็ว เกิดแค่รอบเดียว
