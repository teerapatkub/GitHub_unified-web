## ใบ 11 + 12 — Arcade ส่งแค่โค้ด server คิดคะแนนทั้งก้อน

**เดิม**: เบราว์เซอร์รันเทสเองด้วย Pyodide เรียก AI ตรวจคุณภาพ คิดเวลาเอง รวมเป็นคะแนนแล้วส่ง
ตัวเลขสำเร็จรูปขึ้นมา server ทำได้แค่ clamp เพดาน คอมเมนต์ในโค้ดเองเขียนไว้ตรงๆ ว่า
*"ทุกอย่างใต้บรรทัดนี้ผู้เล่นแก้ได้ server คำนวณซ้ำเองไม่ได้"*

**ตอนนี้**: `POST /submit-round` รับแค่ `{user_name, code, score_multiplier_active}`
เก็บโค้ดไว้ในคอลัมน์ใหม่ `submitted_code` + `submitted_at` แล้ว `finalizeArcadePhase()`
เป็นคนตัดสินตอนรอบปิด — รันโค้ดผ่านตัวตรวจกลาง เรียกตัวตรวจคุณภาพ และอ่านเวลาจาก
`phase_deadline` ที่ server เป็นคนตั้งเอง

**ตัดสินตอนปิดรอบ ไม่ใช่ตอนรับ** (ตามที่ตกลงใน Q18): สิ่งที่ผู้เล่นต้องทำให้ทันคือ *ส่ง*
ส่วนการตรวจจะช้าแค่ไหนเป็นภาระของ server ผู้เล่นไม่เสียรอบเพราะเน็ตตัวเองช้าอีกต่อไป

ตรวจพร้อมกันทุกคนด้วย `Promise.all` เพราะ tick loop เป็นแบบเรียงลำดับ ถ้าตรวจทีละคน
สี่คนจะถ่วงทั้งแมตช์

**ข้อจำกัดที่เหลือและตั้งใจปล่อยไว้**: `score_multiplier_active` ยังมาจากเบราว์เซอร์
เพราะของในร้านค้าเก็บอยู่ฝั่ง client เท่านั้น มันทำได้แค่คูณสองกับคะแนนที่ server คิดเอง
การย้ายคลังไอเทมมาฝั่ง server เป็นงานคนละก้อน

**ใบนี้พึ่งใบ 2 โดยตรง** — `submitted_at` เป็นคอลัมน์ `timestamp` ถ้าเวลายังเหลื่อม 7 ชั่วโมง
เวลาที่คำนวณได้จะติดลบหรือเกินรอบทุกครั้ง

## ใบ 13 — โหมดแข่งใช้ตัวตรวจกลาง

`runCompetitivePythonTests` เคยวนเรียก `runPythonCase` เอง จึงไม่ได้รับสิ่งที่ตัวตรวจกลาง
เรียนรู้มาทีหลัง — โดยเฉพาะ `regexp:` ที่โจทย์ของโหมดแข่งเองใช้อยู่ ตอนนี้เรียก `gradeSubmission`
ยังจำกัด 8 เทสเคสเหมือนเดิม

## ใบ 14 — ลองรันเลิกโกหก

**เจอของหนักระหว่างทาง**: ปุ่ม "ลองรัน" ของ Arcade (`runCodeTests`) **ไม่เคยรันโค้ดเลย**
มันพิมพ์สตริงตายตัว:

```
[PASS] Test Case 1
[PASS] Test Case 2
[SUCCESS] Code compiled successfully!
```

ทุกครั้ง ไม่ว่าผู้เล่นเขียนอะไร แม้แต่โค้ดที่ compile ไม่ผ่านก็ได้ข้อความนี้ พร้อมแจ้งเตือน
"โค้ดผ่านการทดสอบทั้งหมด! กดส่งได้เลย" — เป็นการบอกผู้เล่นว่าคำตอบถูกโดยไม่เคยตรวจอะไร

แก้เป็นรันจริงผ่าน Pyodide แล้วแสดง**ผลลัพธ์ที่โปรแกรมพิมพ์ออกมาจริง** ไม่พูดคำว่าผ่าน/ไม่ผ่านเลย
ตรงกับศัพท์ใน `CONTEXT.md`: **ลองรัน** ไม่เคยตัดสิน มีแต่ **ส่งคำตอบ** ที่ตัดสิน
คีย์ `testsPassed` ถูกลบทิ้งทั้งสองภาษา

## เก็บกวาดที่ตามมา

- ลบโค้ดตัดสินฝั่ง client 57 บรรทัด (`buildTestHarness`, `runCorrectnessCheck`, `requestQualityScore`)
- ลบ endpoint `POST /rooms/:id/judge-round` — ไม่มีใครเรียกแล้ว และถ้าปล่อยไว้จะกลายเป็น
  endpoint ที่ไม่ต้องล็อกอินแต่สั่งให้ AI ที่เสียเงินทำงานกับโค้ดอะไรก็ได้ที่ยิงเข้ามา
- `useRoundJudging` ไม่รับ `phase` กับ `timeLeft` อีกแล้ว เพราะทั้งคู่เป็นเรื่องของ server

## ทดสอบ

เขียน `scripts/arcade-tests/server-scoring-test.js` แทน `score-bounds-test.js` ที่เดิม
เพราะสมมติฐานของไฟล์เก่าไม่จริงแล้ว — มันเปิดหัวว่า *"server ไม่มี Python จึงคำนวณคะแนนซ้ำไม่ได้
ต้องเชื่อ client"* และตรวจแค่ว่าตัวเลขที่ client ส่งถูก clamp

ชุดใหม่สร้างห้องจริง เริ่มแมตช์จริง ส่งเฉลยของโจทย์ที่ห้องนั้นสุ่มได้จริง แล้วบังคับปิดรอบ:

| ตรวจ | ผล |
|---|---|
| ส่งโดยไม่มีโค้ด | ถูกปฏิเสธ 400 |
| ตอนรับคำตอบยังไม่มีคะแนนถูกบันทึก | `pending_round_score` เป็น null |
| หลังปิดรอบมีการตรวจจริง | เฉลยผ่าน **5/5** เทสเคส |

## ที่ยังไม่ทำ

- ห้องที่เริ่มไปแล้วก่อนอัปเดตนี้ (ไม่มี `round_task_ids`) จะได้คะแนนเฉพาะส่วนคุณภาพโค้ด
  เพราะไม่มีโจทย์ให้ตรวจ — ห้องมีอายุสั้นมากจึงยอมรับได้ แต่บันทึกไว้
- คลังไอเทมยังอยู่ฝั่ง client (ดูข้อจำกัดในใบ 12)
- ยังไม่ได้ทดสอบบนหน้าจอจริงกับผู้เล่นสองคน — ชุดทดสอบครอบเส้นทาง server ครบแล้ว
  แต่ `CLAUDE.md` กำหนดให้ทดสอบ real-time บน dev server จริงก่อนถือว่าเสร็จ
