**วันที่:** 2026-08-25 เวลา 12:30
**ผู้ทำ:** Person 3
**เหตุผล:** ผู้ใช้ส่งคีย์และโมเดลชุดใหม่มาให้ใช้แทนตัวที่ถอดออกไปเมื่อ 11:30

ทำงานจริงโดยไม่ต้องจำลอง

## 3. บั๊กร้ายแรงที่เจอระหว่างทดสอบ — โหมดแข่งเล่นไม่ได้เลย

ระหว่างทดสอบเส้นทาง AI ของโหมดแข่ง พบว่า `elapsedSeconds` เป็น **25,200 วินาที (7 ชั่วโมงเป๊ะ)**
ทันทีที่กดรับโจทย์ วัดซ้ำแล้วยืนยันชัด:

```
เพิ่งกดรับโจทย์เมื่อ   : 2026-08-25T08:32:02Z
accepted_at ที่อ่านกลับ : 2026-08-25T01:32:02Z
ส่วนต่างที่โค้ดคำนวณได้ : 25200 วินาที  (ควรเป็น ~0)
```

**สาเหตุ**: `active_accepted_challenges.accepted_at` เป็น `timestamp without time zone`
ฐานข้อมูลเขียนค่าด้วยเวลา UTC แต่ตอนอ่านกลับ ตัว driver สร้าง JS `Date` โดยตีความว่าเป็นเวลา
ท้องถิ่นของเครื่อง (UTC+7) ค่าที่ได้จึงย้อนหลังไป 7 ชั่วโมงเสมอ — เป็นบั๊กชนิดเดียวกับที่เคยเจอ
และแก้ไปแล้วกับ `expires_at` ตอนรวมโปรเจค

**ผลกระทบ**: โจทย์โหมดแข่งทุกข้อมี `time_limit` = 300 วินาที ซึ่งน้อยกว่า 25,200 มาก
ระบบจึงตัดสินว่า **หมดเวลาตั้งแต่วินาทีที่กดรับโจทย์** ทุกครั้ง ผลคือได้ 0 คะแนน
ข้อความ "Time limit exceeded" ไม่มีการเรียก AI ตรวจ และไม่ได้รางวัล
**โหมดแข่งจึงเล่นไม่ได้เลยในทางปฏิบัติ**

โจทย์ทดสอบสองข้อ (`is_test = 1`) รอดมาได้เพราะตั้ง `time_limit` ไว้ 9,999,999 วินาที
ซึ่งเป็นเหตุผลที่บั๊กนี้ไม่เคยถูกสังเกต

**ยังไม่แก้** เพราะอยู่นอกขอบเขตที่ผู้ใช้สั่งในรอบนี้ และการแก้มีสองทางที่ต้องให้ผู้ใช้เลือก
(เปลี่ยนชนิดคอลัมน์เป็นแบบมีเขตเวลา หรือบังคับให้เขียน/อ่านด้วยฐานเวลาเดียวกัน)
รวมถึงต้องพิจารณาแถวข้อมูลเดิมที่มีอยู่แล้ว — รายงานให้ผู้ใช้แล้ว

## 4. สิ่งที่ยังต้องทำ

- **แก้บั๊กเวลาเหลื่อม 7 ชั่วโมงในหัวข้อ 3** — บล็อกโหมดแข่งทั้งโหมด
- ตรวจสอบคอลัมน์ `timestamp without time zone` อื่นๆ ที่ถูกนำมาคำนวณส่วนต่างเวลา
  ว่ามีอาการเดียวกันหรือไม่
- `maxRetries: 0` ของ client ตัวตรวจ ทำให้ 503 ชั่วคราวครั้งเดียวทำให้ผู้เล่นเสียคะแนน AI ไป
  เหมาะกับ Arcade (รอบกำลังปิด) แต่โหมดแข่งน่าจะลองซ้ำได้สัก 1 ครั้ง
- ไฟล์สำรอง `server/.env.backup-before-key-removal` ยังมีคีย์เดิม กัน git แล้วแต่ยังอยู่บนดิสก์
- คีย์เดิมทั้งสองตัวยังไม่ถูกเพิกถอนที่ NVIDIA
