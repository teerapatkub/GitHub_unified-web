## ข้อ 9 — กดส่งคำตอบแล้วไม่มีอะไรเกิดขึ้น

สิ่งที่ผู้ใช้ขอ: กดส่งแล้วต้องแก้โค้ดต่อไม่ได้ กลายเป็นผู้ชม กดที่รายชื่อเพื่อดูว่าคนอื่น
เขียนถึงไหนแล้วได้ และไอเทมยังใช้ได้ตามปกติ

### สิ่งที่ต้องสร้างขึ้นก่อน

ก่อนหน้านี้ **server เห็นโค้ดของผู้เล่นครั้งแรกตอนกดส่งเท่านั้น** จะดูว่าใครเขียนถึงไหน
จึงเป็นไปไม่ได้เลยด้วยข้อมูลที่มีอยู่ ต้องเพิ่ม "ฉบับร่าง" ขึ้นมาก่อน

- คอลัมน์ใหม่ `arcade_participants.draft_code` และ `draft_updated_at`
  **แยกจาก `submitted_code` โดยตั้งใจ** — `submitted_code` คือคำตอบที่กำลังถูกตรวจ
  เขียนแล้วต้องไม่ขยับอีก ส่วนฉบับร่างเปลี่ยนทุกครั้งที่พิมพ์
- `POST /rooms/:id/code-draft` รับฉบับร่าง เฉพาะระหว่างรอบเขียนโค้ด และเฉพาะคนที่ยังไม่ส่ง
  — พอส่งคำตอบแล้วฉบับร่างจะหยุดนิ่ง คนที่ดูอยู่จะได้เห็นสิ่งที่ส่งไปจริง ไม่ใช่สิ่งที่ค้างในช่องแก้โค้ด
- ฝั่งเบราว์เซอร์ส่งขึ้นทุก **4 วินาที** และส่งเฉพาะตอนข้อความเปลี่ยนจริง
  อ่านค่าผ่าน ref ไม่ใช่ dependency — ถ้าใส่ `playerState` เป็น dependency
  interval จะถูกสร้างใหม่ทุกตัวอักษรที่พิมพ์ แล้ว 4 วินาทีจะไม่มีวันมาถึง

### กฎการมองเห็น คือหัวใจของข้อนี้

`GET /rooms/:id/code/:user_name?viewer=...` จะยอมให้ดูก็ต่อเมื่อ**คนขอดูส่งคำตอบไปแล้ว
หรือตกรอบไปแล้ว** คนที่ยังแก้โค้ดของตัวเองได้อยู่ถูกปฏิเสธเสมอ แม้คนที่อยากดูจะส่งไปแล้วก็ตาม
เพราะไม่อย่างนั้นฟีเจอร์นี้กลายเป็นปุ่มลอกทันที

ข้อยกเว้นเดียวคือ **ขอดูของตัวเองได้ตลอด** ซึ่งทำให้ endpoint นี้เป็นทางกู้คืนโค้ดตอนเน็ตหลุดไปในตัว

บอทไม่มีโค้ดจริง จึงตอบตรงๆ ว่าไม่มีให้ดู ไม่ใช่คืนช่องว่างที่อ่านแล้วเหมือนคนที่ยังไม่เขียนอะไร

### บนหน้าจอ

- กดส่งแล้ว editor ล็อก · ขึ้นแถบอธิบายว่าทำไม · ปุ่มส่งเปลี่ยนเป็น "ส่งคำตอบแล้ว"
- **ไอเทมยังกดใช้ได้** — เอาเงื่อนไข `hasSubmittedThisRound` ออกจากปุ่มไอเทม
  การส่งก่อนคือการซื้อเวลาไปเล่นเกมไอเทม ไม่ใช่การจบรอบของตัวเอง
- กดที่รายชื่อ → โค้ดของคนนั้นมาแทนที่ editor เป็น `<pre>` อ่านอย่างเดียว
  (ไม่ใช่ Monaco อีกตัว จึงไม่มีทางเขียนกลับไปที่คำตอบของเขาได้) พร้อมปุ่ม "กลับไปดูโค้ดของฉัน"
- อัปเดตทุก 2 วินาทีตามจังหวะเดียวกับที่ poll สถานะห้อง

### เจอระหว่างทาง: รายชื่อแสดงผู้เล่นจริงเป็นบอท

ผู้เล่นจริงในรายชื่อขึ้นอวาตาร์ตัว "B" และหลอด ROUND PROGRESS ที่ค้างอยู่ที่ **0% ตลอดกาล**
เพราะหลอดนั้นมาจากตัวจำลองบอทฝั่งเบราว์เซอร์ ซึ่งไม่รู้จักผู้เล่นจริงเลย

พอรายชื่อกลายเป็นสิ่งที่กดได้ ความเข้าใจผิดนี้ยิ่งสำคัญ แก้เป็น: บอทเห็นหลอด ส่วนคนจริงเห็น
สถานะที่รู้จริงคือ "✍️ กำลังเขียนอยู่" หรือ "✅ ส่งคำตอบแล้ว" และอวาตาร์ใช้ตัวแรกของชื่อ

**หน้าตารางเกียรติยศใหม่** (`/leaderboard`) จัดอันดับด้วย **XP** เพราะ XP ได้จากทุกโหมด
— บทเรียน แบบฝึกหัด มินิเกม และการแข่ง — จึงเป็นตัวเลขเดียวที่มีความหมายเท่ากันสำหรับทุกคน
ส่วนสนามแข่งยังมีกระดานของตัวเองสำหรับคะแนนของโหมดนั้น

`GET /api/leaderboard` คืนแค่ ชื่อ เลเวล XP และเหรียญ **ไม่มีอีเมล** และไม่มีบัญชีที่ถูกลบหรือถูกแบน
— หน้าของผู้เรียนต้องไม่เรียก `/api/admin/users` ซึ่งคืนข้อมูลมากกว่านี้มาก

**Active Players** = คนที่ client ฝั่ง Arcade ยัง poll อยู่ (ในกรอบเวลาเดียวกับที่ระบบใช้กวาด
ผู้เล่นที่หลุด) บวกคนที่ถือโจทย์โหมดแข่งค้างอยู่ โดยนับเฉพาะที่ยังไม่หมดเวลาของโจทย์นั้น
และตัดที่ 1 ชั่วโมง เพราะโจทย์ทดสอบระบบตั้ง time_limit ไว้มหาศาล ถ้าไม่ตัด แถวเก่าแถวเดียว
จะทำให้ตัวเลขนี้พองตลอดไป **ถ้าคำตอบจริงคือ 0 ก็แสดง 0**

### 11ก — เลย์เอาต์

**ตัวการหลัก: แถบปุ่มลอยทับ editor** — `Run` / `Run Tests` / `Submit` ถูกวางแบบ
`absolute bottom-5 right-5` คือลอยอยู่บนพื้นที่เขียนโค้ด บนจอที่ไม่ใช่จอเดสก์ท็อป
มันไปนั่งทับบรรทัดที่ 8–10 ของคำตอบสิบบรรทัดพอดี (เห็นในภาพที่ผู้ใช้ส่งมา)
ย้ายลงมาเป็นแถวจริงในเลย์เอาต์ ไม่มีทางบังโค้ดได้อีก

**และทุกอย่างใหญ่เกินพื้นที่ของมัน** — ชื่อโจทย์ `text-3xl` ถึง `4xl` ในคอลัมน์กว้าง 290px
ทำให้ชื่อสั้นๆ กลายเป็นสามบรรทัดซ้อนกัน · คำอธิบาย 16px/28px ดันตัวอย่างผลลัพธ์ตกขอบจอ ·
หัวข้อด้านขวาแสดงชื่อโจทย์ซ้ำกับที่ sidebar แสดงอยู่แล้ว กินพื้นที่หนึ่งแถบเต็มเพื่อบอกเรื่องเดิม

ลดขนาดตัวอักษร ระยะขอบ และความสูงเทอร์มินัล (192 เหลือ 144px) ตัดหัวข้อที่ซ้ำออกเมื่อ
sidebar แสดงอยู่

**เจอบั๊กที่ใหญ่กว่าความสวยงาม**: ต่ำกว่าความกว้าง `xl` sidebar ถูกซ่อน และ**คำอธิบายโจทย์
อยู่ในนั้นที่เดียว** ผู้เรียนบนโน้ตบุ๊กจึงเห็นแต่ช่องเขียนโค้ดกับชื่อโจทย์ โดยไม่มีทางอ่านคำสั่งได้เลย
เพิ่มกล่องโจทย์แบบพับได้ (ใช้ `<details>`) ที่โผล่เฉพาะจอที่ไม่มี sidebar

### 11ข — ไม่สุ่มโจทย์จากคลัง

ทั้งสองหน้าขอโจทย์ใหม่จาก **AI ทุกครั้ง** ไม่เคยแตะคลังโจทย์เลย ซึ่งผู้เรียนเป็นคนจ่ายราคาสองทาง:
โจทย์ที่เพิ่งถูกสร้างไม่เคยมีใครลองทำ จึงอาจทำไม่ได้จริงหรือคำตอบที่คาดไว้ผิด และเปลืองโทเคน
ของแชทบอททุกครั้งที่เปิดหน้า

ตอนนี้ **คลังมาก่อน AI เป็นทางสำรอง** — สุ่มจากโจทย์บทเรียน 94 ข้อที่ตรวจอัตโนมัติได้
ซึ่งทุกข้อผ่านการรันกับเฉลยของตัวเองแล้วโดย `npm run test:tasks`

- จำกัดเฉพาะโจทย์ `stdio` เพราะตารางของ task ไม่มีช่องบอกวิธีรันเทสเคส และ endpoint
  ตรวจคำตอบมองทุกอย่างเป็น stdin/stdout — โจทย์แบบเรียกฟังก์ชันที่หลุดเข้ามาจะตัดสิน
  คนตอบถูกว่าผิด
- บทเรียนปลดตามเลเวล ผู้เริ่มต้นจะไม่เจอโจทย์บทท้ายๆ ตั้งแต่ครั้งแรก ถ้าเงื่อนไขนี้ทำให้ไม่เหลือ
  โจทย์ให้สุ่ม จะเลิกใช้เงื่อนไขแล้วสุ่มจากทั้งคลัง
- ข้ามโจทย์ 8 ข้อล่าสุดของผู้เรียนคนนั้น กด "รีโจทย์" แล้วจึงได้โจทย์ใหม่จริง
- รางวัลใช้ของโจทย์นั้นเอง แต่ไม่ต่ำกว่าขั้นต่ำของโหมด — Hard Challenge ที่จ่าย 6 เหรียญ
  ตามโจทย์บทแรกจะอ่านแล้วเหมือนพัง

**เจอระหว่างทาง**: ตาราง `learning_ai_tasks` มาจากไฟล์ dump ที่ import เข้ามา
ไม่เคยอยู่ใน schema ตอนบูตเลย แปลว่า**ฐานข้อมูลที่สร้างใหม่จะไม่มีตารางนี้ และทั้งสองหน้าจะพังทันที**
ย้ายมาสร้างใน `db.js` ตามกฎของโปรเจค พร้อมคอลัมน์ `problem_id` ที่บอกว่าโจทย์มาจากคลังข้อไหน

## ที่ยังไม่ทำ

- ฉบับร่างถูกเก็บที่ server แล้วและเจ้าตัวขอกลับมาอ่านได้ แต่หน้าจอยังไม่เอามาใส่กลับใน editor
  ให้อัตโนมัติเมื่อเน็ตหลุดแล้วกลับเข้ามา
- ห้อง Arcade ความยาก `default` ยังใช้โจทย์ตายตัว 3 ข้อในรอบ 1–3
- โจทย์โหมดแข่งที่หมดอายุยังไม่ถูกนำไปสุ่มในโหมดอื่น (รอผู้ใช้เลือกโหมดปลายทาง)
- คำแปลอังกฤษของโจทย์อีก 78 ข้อ
