## ใบ 2 — เวลาเหลื่อม 7 ชั่วโมง (seam C)

PostgreSQL ตั้ง `TimeZone = Etc/UTC` ค่าที่ `current_timestamp` เขียนลงคอลัมน์
`timestamp without time zone` จึงเป็นเวลา UTC แต่ตัวอ่านของ pg สร้าง JS `Date`
โดยตีความว่าเป็นเวลาท้องถิ่น ค่าที่ได้จึงย้อนหลัง 7 ชั่วโมงเสมอบนเครื่อง UTC+7

**กระทบ 54 คอลัมน์** แต่ที่เห็นผลชัดที่สุดคือโหมดแข่ง: `time_limit` ของโจทย์ทุกข้อคือ 300 วินาที
ระบบจึงตัดสินว่า **หมดเวลาตั้งแต่วินาทีที่กดรับโจทย์** ได้ 0 คะแนน ไม่เรียก AI ตรวจ ไม่ได้รางวัล
โจทย์ทดสอบสองข้อรอดเพราะตั้งเวลาไว้ 9,999,999 วินาที ซึ่งน่าจะเป็นเหตุผลที่ไม่มีใครสังเกตเห็น

แก้ที่ type parser ใน `db.js` ที่เดียว ไม่ได้ไล่แก้ทีละจุดเรียก เพราะทั้ง 54 คอลัมน์ผิดเหมือนกันหมด
และคอลัมน์ที่ยังไม่มีใครทดสอบจะยังผิดต่อไป คอลัมน์ที่เป็น `timestamptz` อยู่แล้ว 23 ตัว
ไม่ได้รับผลกระทบ

`npm run check:time` (ใหม่) เทียบ *ช่วงเวลา* ไม่ใช่ *ตัวอักษร* — เทสที่อ่านสตริงกลับมาเทียบสตริง
จะผ่านสบายๆ ทั้งที่โหมดยังพังอยู่

## ใบ 3 — ตัวรัน Python ตัวเดียว

`server.js` มีสำเนาของ `normalizeOutput` + `resolvePythonBin` + `runPythonCase` อยู่ 92 บรรทัด
เขียนไว้ก่อนรวมโปรเจค และ **สำเนานี้ไม่เคยตั้ง `PYTHONIOENCODING`** คำตอบในโหมดแข่งที่ต้องพิมพ์
ภาษาไทยจึงล้มด้วย `UnicodeEncodeError` stdout ว่าง แล้วถูกตัดสินว่าผิด

ลบทิ้ง ใช้ `server/pythonRunner.js` ตัวเดียว — พิสูจน์ด้วยเทสเคสจริงของโจทย์ #19
(คาด `ไม่มีเลขคู่`) ผ่านครบทั้ง 3 เทสเคส

## ใบ 4 — stderr ไม่ใช่คำตัดสิน

`passed` เคยผูกกับ "stderr ว่างหรือไม่" ผลคือผิดสองทางพร้อมกัน: คำตอบถูกที่มี warning
หลุดออก stderr **ถูกตัดสินว่าผิด** และโปรแกรมที่พิมพ์ถูกแล้ว `sys.exit(1)` **ถูกตัดสินว่าถูก**
ตอนนี้ดูสถานะการจบโปรแกรมแทน ส่วน stderr ยังเก็บไว้แสดงให้ผู้เรียนอ่าน

## ใบ 5 — รองรับ `regexp:`

ข้อมูลใช้ prefix `regexp:` มาตั้งแต่ก่อนรวมโปรเจค แต่**ไม่มีโค้ดที่ไหนแปลความหมายเลย**
โจทย์ Password Generator (สุ่ม PIN) จึงถูกเทียบกับสตริง `regexp:\d{4}` ตรงตัวและไม่มีทางผ่าน

วางไว้ใน `pythonRunner.js` เพราะมีผู้ใช้สองราย — ตัวตรวจของบทเรียน/มินิเกม และตัวรันของโหมดแข่ง
**pattern ที่ compile ไม่ผ่านต้องปฏิเสธ ไม่ใช่ผ่านหมด** มีเทสเฉพาะข้อนี้

## ใบ 6 — ปิดช่องปลอมผลตัดสิน

โค้ดของผู้เรียนรันก่อนตัวประกอบเทส การพิมพ์ `__PYSIM_JUDGE__` ตามด้วย JSON ที่แต่งเอง
ทำให้ตัวตรวจอ่านบรรทัดนั้นเป็นผลของตัวเอง — **พิสูจน์แล้วว่าได้ 5/5 โดยไม่ต้องนิยามฟังก์ชันเลย**

แก้เป็นตัวคั่นสุ่มต่อการรันหนึ่งครั้ง และอ่านบรรทัด**สุดท้าย**ไม่ใช่บรรทัดแรก
การปลอมแบบเดิมตอนนี้ได้ 0/5

## ใบ 7 — โจทย์ที่ตรวจอัตโนมัติไม่ได้ต้องมีโค้ดจริง

"รับไว้โดยไม่ตัดสิน" เคยแปลว่ารับทุกอย่าง ส่งสตริงว่างได้ xp 15 ทอง 35 (ยืนยันด้วยการยิงจริง)
ตอนนี้ต้อง **ไม่ว่าง + ต่างจากโค้ดตั้งต้น + รันได้จริง**

มีทางออกฉุกเฉินหนึ่งทาง: ถ้าโค้ดล้มเพราะ `ModuleNotFoundError` ของไลบรารีที่โจทย์สอน
ให้ถอยไปตรวจว่า compile ผ่านไหมแทน ไม่งั้นย้ายไปเครื่องที่ไม่มี Flask แล้วคำตอบ Flask ที่ถูก
จะถูกปฏิเสธ — แย่กว่าช่องโหว่ที่กำลังปิด

ตรวจแล้วว่าโจทย์ทั้ง 26 ข้อไม่มีข้อไหนเรียก `input()` การรันโดยไม่ป้อน stdin จึงปลอดภัย

## ใบ 8 — เลขบรรทัดตรงกับที่ผู้เรียนเห็น

โค้ดแก้ `input()` เคยถูกแปะไว้ข้างบนโค้ดผู้เรียน ทำให้เลขบรรทัดในข้อผิดพลาดเลื่อนไป 6
และ **`from __future__` ใช้ไม่ได้เลย** เพราะต้องเป็นคำสั่งแรกของโมดูล

เปลี่ยนเป็นให้โค้ดผู้เรียนเป็นไฟล์ของตัวเอง แล้วตัวโหลดเรียกผ่าน `runpy` — เลขบรรทัดตรง
`from __future__` กลับมาใช้ได้ และตัดเฟรมของตัวโหลดกับ path ชั่วคราวออกจากข้อความที่ผู้เรียนเห็น

## ใบ 9 — สร้างโจทย์ปลอดภัย

เดิมเป็นสองคำสั่งแยกกันไม่มีทรานแซกชัน และคำนวณ `entry_id` ด้วย `MAX + 1`
สร้างพร้อมกันสองคนจะอ่านค่าเดียวกัน คนที่สองชน primary key ได้ 500 และทิ้ง**โจทย์กำพร้า**
ที่ไม่ผูกกับโหมดใดเลยแต่กินหมายเลขที่ห้ามนำกลับมาใช้

แก้เป็นทรานแซกชันเดียว + `pg_advisory_xact_lock` ต่อโหมด
**ทดสอบยิงพร้อมกัน 5 คำขอ: ได้ 201 ทั้งหมด · entry_id 21–25 ไม่ชนกัน · โจทย์กำพร้า 0**

## ใบ 10 — ไม่รันโค้ดคาทรานแซกชัน

`/api/learning/ai-task/submit` เปิดทรานแซกชันแล้วค่อยรัน Python ทีละเทสเคส
ถือ connection ของ pool ไว้ตลอด สิบคำขอช้าพร้อมกันก็พอทำให้ทั้งเว็บค้าง

เปลี่ยนเป็นอ่าน → ตรวจ → ค่อยเปิดทรานแซกชัน แล้ว**อ่านซ้ำในทรานแซกชัน** เพื่อกันการส่งซ้ำ
ระหว่างที่ Python กำลังรันอยู่
