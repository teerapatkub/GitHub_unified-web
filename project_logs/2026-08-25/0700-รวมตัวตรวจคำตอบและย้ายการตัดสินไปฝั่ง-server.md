## 3. สามเรื่องที่ไม่รู้ล่วงหน้า และเปลี่ยนรูปงาน

### 3.1 `input("คำถาม: ")` พิมพ์ prompt ลง stdout ด้วย

คำตอบที่เก็บไว้ทั้งระบบไม่มี prompt เช่นโจทย์ที่เฉลยเป็น
`name = input("ชื่อ: ")` แล้ว `print("สวัสดี", name)` เก็บคำตอบไว้แค่ `สวัสดี Lumi`

**นี่คือเหตุผลที่ตัวตรวจเดิมต้องใช้ `includes()`** — และเป็นเหตุผลเดียวกับที่มันปล่อย `17` ผ่าน `7`

แก้ให้ถูกทางด้วยการ**กลบ prompt** (แทน `builtins.input` ให้ไม่พิมพ์ argument) โค้ดของผู้เรียน
ไม่ถูกแตะ เขียน prompt ได้ตามโจทย์ แต่การเทียบยังตรงตัว — โจทย์กลับมาผ่านเพิ่ม 5 ข้อทันที

### 3.2 Python บน Windows พิมพ์ภาษาไทยไม่ได้

`UnicodeEncodeError` ทุกครั้งที่คำตอบต้องพิมพ์ภาษาไทย stdout ว่างเปล่า → ถูกตัดสินว่าตอบผิด
โปรเจกต์นี้โจทย์เป็นภาษาไทยเกือบทั้งหมด จึงไม่ใช่กรณีขอบ
แก้ด้วย `PYTHONIOENCODING=utf-8` + `PYTHONUTF8=1` ใน env ของ child process

### 3.3 โจทย์บางข้อตรวจอัตโนมัติไม่ได้ และไม่ใช่ความผิดของโจทย์

พอเอาเฉลยของทุกข้อไปตรวจด้วยตัวตรวจใหม่ **มี 26 ข้อที่เฉลยของตัวเองยังไม่ผ่าน**
ไล่สาเหตุแล้วส่วนใหญ่ไม่ใช่โจทย์พัง แต่เป็นโจทย์ที่ไม่มีคำตอบตายตัว:
Flask 5 · matplotlib 5 · requests 5 · pytest 2 · ต้องมีไฟล์อยู่ก่อน 3 · ผลลัพธ์สุ่ม 2

ถ้าบังคับตรวจทั้งหมด ผู้เรียนที่เขียนถูกจะถูกตัดสินว่าผิดใน 26 ข้อนี้

จึงเพิ่ม `problems.is_auto_gradable` ที่ **คำนวณจากการรันจริง ไม่ได้เดา** —
`npm run mark:gradable` เอาเฉลยของทุกข้อไปตรวจแล้วบันทึกผล ได้ 166 ตรวจได้ / 26 ตรวจไม่ได้
ข้อที่ตรวจไม่ได้จะรับคำตอบไว้เหมือนเดิม แต่**อยู่ในรายชื่อที่เปิดดูได้** ไม่ใช่ยกเว้นแบบเงียบๆ
ถ้าติดตั้ง pandas/matplotlib/requests/flask ให้ runner แล้วรันสคริปต์ใหม่ ตัวเลขจะลดลงเอง

## 4. บั๊กที่เจอเพิ่ม

**เฉลย 3 ข้อของบทเรียนผิดจริง** — `#104` ใช้ `r"d+"` แทน `r"\d+"`, `#105` ใช้ `r"d"`,
`#106` ใช้ `r"^[w.-]+@[w.-]+.w+$"` — backslash หายไป (ร่องรอย escape แบบเดียวกับที่เจอในมินิเกม)
คำตอบที่เก็บไว้ถูก แต่**เฉลยผิด** ตัวตรวจจับได้ ยังไม่แก้เพราะเป็นเนื้อหาของ Person 1 — แจ้งไว้

**มินิเกม 12 ข้อ escape ซ้อนที่ `solution_code`/`starter_code`/`desc_th` ด้วย**
(รอบก่อนซ่อมแต่ `test_cases_json`) เช่น `course = \"Python\"\nprint(course)`
ซึ่งไม่ใช่ Python ที่รันได้เลย — **12 ด่านนั้นทำไม่ได้มาตลอด** ซ่อมแล้วโดยถอด JSON ทั้งค่า
(รอบแรกผมถอดครึ่งเดียว `\"`→`"` แต่ปล่อย `\n` เป็นตัวอักษรสองตัว ทำให้ยังพัง — ตัวตรวจจับได้อีกรอบ)

**regression ที่ผมทำเอง** — ตอนเปลี่ยนชั้น DB ผมตัดกฎ rewrite `TRUE`→`1` ทิ้งหลัง grep แล้วคิดว่าไม่มีใครใช้
แต่ grep แคบไป พลาด `VALUES (?, ?, ?, true, 100)` ที่เขียนลง `exercise_submissions.is_passed`
ซึ่งเป็น SMALLINT ผลคือ**ตอบถูกแล้ว 500** โผล่ตอนเทสคำตอบที่ถูกต้อง
แก้โดยเขียน `1` ตรงๆ ทั้ง 3 จุด (ไม่เอากฎ rewrite เหมารวมกลับมา เพราะมันเคยทำ JSON seed พัง)

**ช่องโหว่ของตัวตรวจ SQL** — `is of type` ถูกจัดเป็น "inconclusive" มาตั้งแต่ยุคที่ตัวตรวจ
แทน placeholder ด้วย `'1'` เหตุผลนั้นหมดไปแล้วตั้งแต่ใช้ bind parameter จริง
กฎนี้จึงกลบ type error จริงไว้ 3 จุด (รวมข้อข้างบน) — เอาออกแล้ว
