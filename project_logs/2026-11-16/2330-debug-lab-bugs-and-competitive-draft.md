## ข้อ 3: Debug Lab ไม่มีโค้ดที่มีบั๊กให้แก้

**สาเหตุ:** Debug Lab สุ่มโจทย์บทเรียนจากคลังมาใช้ แต่ `starter_code` ของโจทย์บทเรียนเป็นโครงเปล่า ไม่ใช่โค้ดที่มีบั๊ก และเลิกให้ AI ใส่บั๊กไปแล้ว เพราะบั๊กที่ AI ใส่ 14 ใน 15 ข้อไม่ได้ทำให้ผลลัพธ์เปลี่ยน

**สิ่งที่แก้:**
- **`server/bug-mutator.py` (ใหม่):** parse เฉลยด้วย `ast` แล้วเขียนสำเนาที่มีบั๊กแบบที่มือใหม่ทำบ่อย ทีละจุด
  - เครื่องหมายเปรียบเทียบเลื่อนไปหนึ่งขั้น (`<`↔`<=`, `==`↔`!=`)
  - ใช้ operator ผิดตัว, สลับลำดับ `a - b`
  - `and`↔`or`
  - ขอบเขตของ `range()` เกินหรือขาดไปหนึ่ง
  - `max`↔`min`, `upper`↔`lower`
  - index เลื่อนไปหนึ่งตัว
  - ลืม `int()` รอบ `input()` ทุกตัว (`"3" + "4"` ได้ `"34"`)
  - สคริปต์นี้แค่เขียนสำเนา ไม่ได้รันอะไร
- **`server/debugLab.js` (ใหม่):** `plantBug({ solution, testCases })`
  - เลือกเฉพาะบั๊กที่**รันจบโดยไม่ error และให้ผลลัพธ์ผิด** กับ test case ของโจทย์จริง
  - เช็คด้วยว่าเฉลยที่ถูกจัดรูปแบบใหม่ยังผ่าน
- **`server/server.js` `drawLearningTaskFromBank`:**
  - โหมด `exercise` (Debug Lab) สุ่มโจทย์มาครั้งละ 12 ข้อ แล้วใช้ข้อแรกที่ใส่บั๊กได้
  - `starterCode` คือโค้ดที่มีบั๊ก และคำสั่งบรรทัดแรกคือ "โค้ดด้านล่างมีบั๊ก 1 จุด…"
  - ชนิดของบั๊กเก็บไว้ใน `ai_payload` ฝั่ง server เท่านั้น
  - ถ้าใส่บั๊กไม่ได้สักข้อ จะให้โจทย์แบบเดิม (มี warning ใน log)
- **ครอบคลุม:** โจทย์บทเรียน 28 จาก 94 ข้อใส่บั๊กได้ (วัดบน playtest DB) ใช้เวลาประมาณ 0.4 วินาทีต่อข้อ
  - ข้อที่เหลือส่วนใหญ่เป็นโจทย์ที่คำตอบคือพิมพ์ข้อความตายตัว ไม่มีจุดให้บั๊กเปลี่ยนผลลัพธ์ได้

## ข้อ 6: Generated โจทย์ Competitive ได้แค่ตัวโจทย์

**สาเหตุ:**
- server ส่ง test case มาแล้ว แต่กล่องผลลัพธ์ไม่แสดง
- ปุ่ม "ใช้โจทย์นี้" ถูกล็อกเมื่อเปลี่ยนหมวดระหว่างรอ
- `onApply` ไม่ได้ตั้งค่ารางวัลและเวลา
- ตัวอย่างในคำอธิบายมาจากโมเดล จึงขัดกับเทสได้ ("สมชาย มีตรี" บอกว่า 10 แต่เทสคาด 8)

**สิ่งที่แก้:**
- **`server/competitiveAi.js`:**
  - **prompt:** ให้โจทย์ฝึกหมวดที่เลือกจริง, ใช้คำว่า "ข้อมูลที่รับเข้า/ผลลัพธ์ที่ต้องแสดง" แทน stdin/stdout และห้ามเขียนตัวอย่างเอง
  - **`withRunExample()`:** ตัดทุกอย่างตั้งแต่บรรทัด "ตัวอย่าง/Example/Sample" ออก, แทนคำ stdin/stdout แล้วต่อท้ายด้วยตัวอย่าง 2 ชุดจากผลรันเฉลยจริง
  - ส่ง `topic`, `rewardCoins`, `timeLimitSec` กลับไปด้วย (community 300/600 วินาที, daily 800/1800, weekly 2000/5400)
  - **โจทย์ในคลังที่สร้างไว้ก่อน:** ตอนหยิบออก จะสร้างตัวอย่างใหม่และเติมค่าเหล่านี้ให้ ทำซ้ำได้ผลเท่าเดิม
- **`client/src/components/CompetitiveGenerator.jsx`:**
  - แสดง test case ทั้ง 8 ชุด และป้าย "สร้างจากหมวด …"
  - **ปุ่มนำไปใช้ไม่ถูกล็อกแล้ว:** หมวดในฟอร์มใช้แค่กำหนดการสร้าง ไม่ได้ถูกโพสต์ จึงบอกแค่ว่าโจทย์มาจากหมวดอื่น
- **`client/src/pages/CompetitiveArena.jsx`:**
  - `onApply` ตั้งเหรียญและเวลาให้ด้วย
  - ตอนโพสต์ เช็คว่ามี test case อย่างน้อย 2 ชุดที่ input ต่างกัน ตรงกับกฎฝั่ง server จากข้อ 1 (เดิม server ปฏิเสธแต่ผู้ใช้เห็นแค่ข้อความ error ทั่วไป)

## ที่ยังไม่ได้ทำ
- **ยังไม่ได้ลองสร้างโจทย์ Competitive ใหม่จากโมเดลจริง** (Ollama ไม่ได้เปิดในเครื่องนี้) prompt ใหม่จึงยังไม่ได้วัดว่าโมเดลทำตามแค่ไหน
  - แต่การตัดตัวอย่างและเติมตัวอย่างจากผลรันไม่ขึ้นกับโมเดล
- **ตัวอย่างที่โมเดลเขียนแทรกกลางย่อหน้า** (ไม่ได้ขึ้นบรรทัดด้วย "ตัวอย่าง") ยังไม่ถูกตัด
- **คำอธิบายของบางโจทย์ในคลังบอกสูตรตรงๆ** (เช่น `price * 1.07`) Debug Lab จึงง่ายสำหรับข้อนั้น
- ยังไม่ได้ deploy ขึ้นเครื่อง มข.
