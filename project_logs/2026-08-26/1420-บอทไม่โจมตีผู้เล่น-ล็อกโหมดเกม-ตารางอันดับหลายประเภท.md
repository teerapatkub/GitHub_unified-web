## 1. บอทไม่โจมตีผู้เล่นเลย แม้ผู้เล่นจะนำอยู่

อาการที่แจ้ง: "เล่นมาหลายตา บอทไม่โจมตีผมเลย ถึงคะแนนผมจะนำอยู่ก็ตาม"
มีสองสาเหตุ และแต่ละสาเหตุก็เพียงพอที่จะทำให้เกิดอาการนี้เองได้

### สาเหตุที่ 1 — ตารางคะแนนคนละใบ

`pickAttackTarget` เลือกเป้าหมายจาก "ใครคะแนนสูงสุด" ซึ่งถูกต้อง
แต่มันเทียบ **คะแนนสองชุดที่คนละมาตราส่วน**:

| ใคร | คะแนนที่ถูกเอามาเทียบ | ขนาดจริง |
|---|---|---|
| บอท | `this.score` ที่บอทคิดเอง | +100 ถึง +500 ต่อรอบที่ "เขียนเสร็จ" |
| ผู้เล่น | `playerState.score` จาก server | สูงสุดราว 300 ต่อรอบ และปกติได้น้อยกว่านั้นมาก |

คะแนนในจินตนาการของบอทจึงชนะคะแนนจริงของผู้เล่นแทบทุกครั้ง ไอเทมเลยวิ่งไปหาบอทตัวอื่น
คะแนนของบอทที่ **แสดงบนหน้าจอ** มาจาก server อยู่แล้ว ผู้เล่นจึงเห็นตัวเองนำ
แต่บอทไม่ได้ตัดสินใจจากตัวเลขชุดนั้น

**แก้:** `botManager.update()` สร้างตารางคะแนนใบเดียวจาก `arcade_participants` (ทั้งบอทและคน
มาจากตารางเดียวกัน) แล้วส่งให้บอททุกตัวใช้ร่วมกัน `this.score` เหลือเป็นแค่ค่าสำรอง
เผื่อชื่อที่ไม่มีในตาราง

### สาเหตุที่ 2 — เกราะทำให้ผู้เล่นหายไปจากรายชื่อเป้าหมาย

บอทข้ามเป้าหมายที่ติดดีบัฟอยู่แล้ว (เพื่อไม่ให้ซ้ำคนเดิม) ซึ่งถูกต้อง
แต่การตรวจใช้แค่ "มี `activeEffects` ที่ยังไม่หมดอายุไหม" — และ **บัฟที่ผู้เล่นซื้อเอง
อยู่ในลิสต์เดียวกัน** โดยเก็บด้วย `expiresAt: Date.now() + 99999999` (ราว 27 ชั่วโมง)

ผลคือ **ซื้อเกราะหรือไอเทมคูณคะแนนครั้งเดียว = หายไปจากสายตาบอทตลอดทั้งแมตช์**
และคนที่ซื้อเกราะก็คือคนที่กำลังนำอยู่พอดี

**แก้:** แยกบัฟของตัวเองออกจากดีบัฟที่คนอื่นยิงใส่ รายการบัฟดึงมาจาก `SHOP_CATALOG`
(`type === 'buff'`) ไม่ได้เขียนชื่อไอเทมตายตัวไว้ เพิ่มไอเทมบัฟใหม่แล้วไม่ต้องกลับมาแก้ตรงนี้

เกราะยัง **กัน** การโจมตีได้เหมือนเดิมและถูกใช้ไป 1 ครั้ง — กันได้หนึ่งครั้งคือสิ่งที่ตั้งใจ
ส่วนการมองไม่เห็นตลอดกาลคือบั๊ก

### ทดสอบ

`npm run test:targeting` (ใหม่) **10/10** — ก่อนแก้ ตก 6 ผ่าน 4
ครอบคลุมทั้งสองสาเหตุ บวกกับกรณีที่ต้องไม่พังไปด้วย: บอทที่นำจริงยังต้องถูกเลือก
(ไม่ใช่ยิงคนเสมอ), ดีบัฟจริงยังต้องกันการถูกซ้ำ, ดีบัฟที่หมดอายุแล้วต้องไม่กัน,
ระบบแก้แค้นยังทำงาน, คนตกรอบไม่ถูกยิง

**ทดสอบบนเบราว์เซอร์จริง** — เรียกโมดูลตัวจริงผ่าน dev server แล้วจำลองสถานการณ์ที่ผู้ใช้เจอ
(คนนำ 280 คะแนน บอท 120/90 บอทคิดว่าตัวเองมี 900 และคนถือเกราะอยู่):
- ถือเกราะ → `🛡️ เกราะของคุณป้องกันการโจมตีจาก Bot_A` (ก่อนแก้ไม่มีอะไรเกิดขึ้นเลย)
- ไม่ถือเกราะ → `🚨 Bot_A ใช้ไอเทม Ink Fog โจมตีใส่คุณ!` และดีบัฟติดจริงบน `playerState`

## 2. UI หน้าแบบฝึกหัดแออัด

หน้า `/exercise` ยังใช้ขนาดเดิมอยู่ ทั้งที่หน้า challenge/debug ปรับไปแล้วรอบก่อน
คอลัมน์ซ้ายตั้งไว้เท่าหน้า landing page: หัวข้อ 32px ระยะห่าง 24-32px และปุ่มเลือกโจทย์
ขนาดเต็มต่อหนึ่งข้อ ทำให้กล่องรางวัลตกไปอยู่ใต้ขอบจอ

| | ก่อน | หลัง |
|---|---|---|
| ความกว้างคอลัมน์ซ้าย | 300-320px | 248-276px |
| หัวข้อโจทย์ | 30-32px | 18-20px |
| ปุ่มเลือกโจทย์ | 14px · py-3 | 12px · py-2 |
| คำอธิบาย | 16-18px · leading-8 | 13px · leading-6 |
| ปุ่มแถบล่าง | 14px · py-2.5 | 12px · py-1.5 |
| ความคืบหน้า + รางวัล | สองกล่องแยก สูงรวม ~120px | แถวเดียว ~52px |

วัดบนหน้าจอจริงที่ 1280×720: คอลัมน์ซ้ายกว้าง 276px หัวข้อ 20px
ปุ่มทั้งห้าอยู่แถวเดียวกันหมด (y=489 สูง 30px) และหน้าไม่มี scroll แนวนอน

## 3. เข้าโหมดเกมต้องถึงเลเวล 10

**หมายเหตุเรื่องคำว่า "ผู้เชี่ยวชาญ"** — ในระบบไม่มียศชื่อนี้อยู่จริง
มีแค่ `normalizePlayerLevel()` ที่คืน Beginner/Intermediate/**Advanced** โดย Advanced
เริ่มที่ **เลเวล 3** ถ้าตีความว่า "ผู้เชี่ยวชาญ **หรือ** เลเวล 10" แบบ OR จริงๆ
เงื่อนไขจะเป็นจริงตั้งแต่เลเวล 3 และกฎเลเวล 10 จะไม่มีความหมายเลย
จึงตีความว่าทั้งสองอย่างคือหมุดเดียวกัน และ **บังคับที่เลเวล 10** โดยเรียกยศนั้นว่า
"ผู้เชี่ยวชาญ" ในข้อความบนหน้าจอ

- ตัวเลขอยู่ที่เดียวใน `client/src/utils/gameModeAccess.js`
- กัน **ที่ route ไม่ใช่แค่ปุ่ม** — พิมพ์ `/matchmaking` เองก็เจอหน้าเดียวกัน
  (`/menu`, `/online`, `/competitive-arena`, `/matchmaking`)
- แอดมินผ่านได้ เพราะต้องเข้าไปดูโหมดที่ตัวเองดูแล
- **เป็นหน้าอธิบาย ไม่ใช่การเด้งกลับ** — คนที่กดแล้วเด้งกลับที่เดิมไม่ได้รับข้อมูลอะไรเลย
  และจะกดซ้ำ หน้านี้บอกว่าต้องถึงเลเวลเท่าไร ตอนนี้อยู่เลเวลไหน เหลืออีกกี่เลเวล
  พร้อมหลอดความคืบหน้า และปุ่มเดียวบนหน้าคือไปหน้าบทเรียน

ทดสอบบนหน้าจอจริงด้วยบัญชีเลเวล 1: ทั้ง `/menu` และ `/matchmaking` แสดง
"โหมดเกมยังไม่เปิดให้คุณ ... เหลืออีก 9 เลเวล" · ลดเพดานชั่วคราวเป็น 1 แล้วหน้า
เมนูโหมดเกมกลับมาปกติทั้งสองการ์ด · คืนค่าเป็น 10 แล้ว

## 4. บทเรียนย่อยต้องปลดล็อกตามลำดับ

เดิมกดเรียนบทไหนก่อนก็ได้ ตราบใดที่เลเวลถึง — บทที่ 2 เขียนโดยสมมติว่าอ่านบทที่ 1 มาแล้ว
คนที่เปิดกลางบทจึงเจอไวยากรณ์ที่ไม่มีใครอธิบายให้ และสรุปว่าตัวเองทำไม่ได้

บทถัดไปเปิดเมื่อบทก่อนหน้า **ทำแบบทดสอบหลังเรียนเสร็จ** (`post_quiz_completed`)
ซึ่งเป็นสัญญาณเดียวกับที่ป้าย "เรียนเสร็จสิ้น" ใช้อยู่แล้ว
ป้ายบอกว่า "ต้องเรียนบทก่อนให้จบ" และ tooltip ระบุ **ชื่อบทที่ต้องเรียนก่อน** ตรงๆ

ทดสอบจริง: บทที่ 1 เปิด บทที่ 2-4 ล็อก · กดบทที่ล็อกแล้ว URL ไม่เปลี่ยน ·
กดบทที่ 1 ไป `/lesson/1` ได้ปกติ

**ยังไม่ได้ทำ:** พิมพ์ `/lesson/3` ตรงๆ ยังเข้าได้ การกันระดับ route ต้องรู้ความคืบหน้า
ของทั้งบทก่อนตัดสิน ซึ่งหน้า `/lesson` ยังไม่ได้โหลดข้อมูลนั้น — ไม่กระทบความถูกต้องของรางวัล
เพราะแบบฝึกหัดยังตรวจที่ server เหมือนเดิม

## 5. ตารางอันดับเพิ่ม 5 ประเภท

เดิมมีแค่ XP ซึ่งบอกคนที่เล่นแต่ Arcade หรือคนที่สะสมไอเทมว่าเขาไม่ใช่ใครเลย

| แท็บ | เรียงจาก | ที่มาของข้อมูล |
|---|---|---|
| XP รวม (ค่าเริ่มต้น) | `users.xp` | เหมือนเดิม |
| เลเวล | `users.level` | |
| อัตราชนะ Arcade | `wins / matches_played` | `arcade_player_stats` |
| โจทย์ Competitive | `COUNT(DISTINCT challenge_id)` | `multiplayer_submissions` |
| เหรียญ | `users.virtual_currency` | |
| ไอเทมตกแต่ง | `COUNT(*)` | `user_inventory` |

**สองการตัดสินใจที่ตั้งใจ**
- **อัตราชนะมีขั้นต่ำ 3 แมตช์** ไม่งั้นชนะครั้งเดียวคือ 100% และจะนั่งอันดับหนึ่งตลอดไป
  เหนือคนที่ชนะ 40 จาก 60 หน้าจอบอกขั้นต่ำนี้ไว้ด้วย และแสดง "ชนะ 9 จาก 14 แมตช์"
  กำกับเปอร์เซ็นต์เสมอ
- **นับโจทย์ Competitive แบบไม่ซ้ำ** ส่งข้อเดิมซ้ำไม่ใช่ความสำเร็จเดียวกับการทำข้อใหม่

ทุกแท็บใช้ฐานผู้เล่นชุดเดียวกัน (ไม่นับบัญชีที่ถูกลบ ถูกแบน และแอดมิน) และคืนข้อมูลรูปแบบเดียวกัน
ชื่อแท็บที่ไม่รู้จักตกกลับไปที่ XP แทนที่จะ error — ค่าที่รับมาจาก URL ถูกใช้เปิดตารางที่กำหนดไว้ตายตัว
ไม่เคยถูกต่อเข้าไปในคำสั่ง SQL

ทดสอบครบทั้ง 6 แท็บบนหน้าจอจริง และยิง API ทั้ง 6 แบบ + ชื่อแท็บมั่ว
