# OTP ไม่ถูกส่ง — Gmail ปฏิเสธรหัสผ่าน และระบบไม่ยอมบอกว่าส่งไม่สำเร็จ

**วันที่:** 2026-08-26 เวลา 01:10 (ของวันถัดไป)
**ผู้ทำ:** Person 3
**ที่มา:** ผู้ใช้แจ้งว่าสมัครสมาชิกแล้ว OTP ไม่ถูกส่ง และ console ขึ้น 400 Bad Request

---

## สาเหตุจริง — Gmail ไม่รับรหัสผ่านที่ตั้งไว้

ใน log ของเซิร์ฟเวอร์:

```
⚠️ ส่งอีเมลรหัสยืนยันไม่สำเร็จ: Invalid login: 535-5.7.8 Username and Password not accepted
```

**ค่า `EMAIL_PASS` ใน `server/.env` ใช้กับ Gmail ไม่ได้** — Gmail เลิกรับรหัสผ่านปกติของบัญชี
ไปแล้ว ต้องใช้ **App Password 16 หลัก** ซึ่งสร้างได้ต่อเมื่อเปิด 2-Step Verification ก่อน
นี่เป็นเรื่องการตั้งค่า ไม่ใช่บั๊กของโค้ด และไม่ได้เกิดขึ้นเพราะงาน OTP เมื่อกี้
(ระบบลืมรหัสผ่านที่ใช้ transporter ตัวเดียวกันก็ส่งไม่ได้มาตลอดเช่นกัน)

## แต่โค้ดผิดจริงสองเรื่อง และเป็นความผิดที่ร้ายกว่า

### 1. ⭐ ระบบโกหกว่าส่งแล้ว

`sendOtpEmail()` จับ error ของ SMTP ไว้เงียบๆ แล้ว endpoint ก็ยังตอบว่า
*"ส่งรหัสยืนยัน 6 หลักไปที่ ... แล้ว"* คนสมัครจึงนั่งรออีเมลที่**ไม่มีวันมาถึง**
โดยไม่มีอะไรบอกว่าต่างจากเมลที่มาช้า

นี่เป็นความผิดของงานเมื่อวาน ไม่ใช่ของเดิม

**แก้:** `sendOtpEmail()` คืนค่าว่าส่งออกไปจริงหรือไม่ · `/api/register` และ
`/api/resend-otp` ส่ง `emailDelivered` กลับมาด้วย · หน้าจอขึ้นข้อความสีแดงว่า
ระบบอีเมลใช้ไม่ได้ บัญชีถูกสร้างไว้แล้ว และให้แจ้งผู้ดูแล — แทนที่จะขึ้นข้อความเขียวว่าส่งแล้ว
พร้อมเปลี่ยนหัวข้อจาก "เราส่งรหัส 6 หลักไปที่" เป็น "บัญชีของอีเมลนี้ยังรอการยืนยัน"
เพราะสองข้อความเดิมขัดกันเองบนหน้าจอเดียว

**ข้อความที่ผู้ใช้เห็นไม่ใช่ข้อความของ SMTP** — `535-5.7.8 Username and Password not accepted`
เป็นเรื่องของคนที่ตั้งค่าเซิร์ฟเวอร์ ซึ่งอยู่ใน log ให้อยู่แล้ว ส่วนผู้เรียนต้องรู้แค่ว่า
รอไปก็ไม่มีอะไรมา และต้องบอกใคร

### 2. สมัครซ้ำด้วยอีเมลเดิมกลายเป็นทางตัน — ที่มาของ 400

เมื่ออีเมลไม่มาถึง สิ่งที่คนจะทำคือสมัครใหม่ แล้วเจอ 400
*"Username หรือ Email นี้ถูกใช้ไปแล้ว"* ซึ่งเป็นความจริงที่ช่วยอะไรไม่ได้เลย —
บัญชีนั้นเป็นของเขาเอง เพียงแต่เข้าไม่ได้ **นี่คือ 400 ที่เห็นใน console**

**แก้:** ถ้าอีเมลนั้นมีบัญชีที่**ยังไม่ยืนยัน** ระบบจะออกรหัสใหม่แล้วพาไปหน้ากรอกรหัสเลย
แทนที่จะขึ้น error · **ไม่แตะบัญชีเดิมเลย** ทั้งรหัสผ่านและชื่อผู้ใช้ จึงใช้ยึดบัญชีคนอื่นไม่ได้
คนที่ถือกล่องจดหมายยังเป็นคนเดียวที่ทำต่อได้ · ถ้าอีเมลนั้นยืนยันไปแล้ว ยังขึ้น 400 เหมือนเดิม

### 3. บอกตั้งแต่ตอนบูตว่าอีเมลใช้ไม่ได้

เพิ่ม `emailTransporter.verify()` ตอนเริ่มเซิร์ฟเวอร์ เพราะการตั้งค่าที่ Gmail ปฏิเสธ
**หน้าตาเหมือนการตั้งค่าที่ถูกต้องทุกประการ** จนกว่าจะมีคนกดสมัครจริง
(`EMAIL_USER` กับ `EMAIL_PASS` มีค่าอยู่ครบ `EMAIL_CONFIGURED` จึงเป็นจริง)

ตอนนี้ถ้าใช้ไม่ได้จะขึ้นตอนบูตทันที พร้อมบอกวิธีแก้เป็นภาษาไทย 3 บรรทัด รวมลิงก์
หน้าสร้าง App Password

## สิ่งที่ผู้ใช้ต้องทำเอง

1. เปิด 2-Step Verification ที่บัญชี Google ที่ใช้ส่งเมล
2. สร้าง App Password ที่ https://myaccount.google.com/apppasswords
3. เอาค่า 16 หลักนั้นใส่เป็น `EMAIL_PASS` ใน `server/.env` (ตัดเว้นวรรคออก) แล้วรีสตาร์ท
4. ดูว่าตอนบูตขึ้น `✅ ระบบอีเมล: เชื่อมต่อ SMTP ได้` แล้วค่อยลองสมัครใหม่

**บัญชี `pong` (user 124) ที่สมัครค้างไว้ยังอยู่ครบ ไม่ได้ลบ** เมื่อแก้ค่าอีเมลแล้ว
กดขอรหัสใหม่จากหน้ากรอกรหัสได้เลย ส่วนบัญชีทดสอบที่ผมสร้างระหว่างตรวจสอบลบทิ้งหมดแล้ว
