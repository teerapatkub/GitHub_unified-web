**ผู้ทำ:** Person 3
**ที่มา:** ผู้ใช้แจ้งว่าเตรียม deploy และจะย้ายฐานข้อมูลไป Supabase
พร้อมเพิ่ม Supabase MCP server เข้า `.mcp.json` ของโปรเจค

## สามอย่างที่ขวางอยู่ ถ้าย้ายเลยตอนนี้จะเจอทั้งหมด

### 1. ต่อไม่ติดเลย — โค้ดไม่เคยรองรับ TLS

`DB_CONFIG` ใน `server/db.js` ไม่มี `ssl` ฐานข้อมูลแบบ managed ทุกเจ้าปฏิเสธการต่อที่ไม่เข้ารหัส
จึงต่อไม่ได้ตั้งแต่แรก และไม่รองรับ connection string ที่ Supabase ให้มาด้วย

**แก้:** รับ `DATABASE_URL` (หรือ `POSTGRES_URL`) เพิ่ม และตัดสิน TLS **จากชื่อ host เอง**
— localhost / 127.0.0.1 / ชื่อ service ใน docker → ไม่ใช้ TLS · ชื่อโดเมนจริง → ใช้ TLS
เพราะสองสภาพแวดล้อมนี้ต้องการตรงข้ามกันและไม่ควรต้องจำว่าต้องตั้งค่าอะไร
สั่งทับได้ด้วย `PGSSLMODE` และตรวจใบรับรองจริงได้ด้วย `PGSSLROOTCERT`

### 2. ⭐ ตาราง `users` จะถูกเปิดให้อ่านผ่านอินเทอร์เน็ต

Supabase เอา schema `public` ไปเปิดเป็น REST API และให้สิทธิ์บทบาท anonymous อ่านตารางในนั้น
schema นี้มี `users` ซึ่งเก็บ**อีเมลจริงและ bcrypt hash ของทุกคน**
ใครก็ตามที่มี publishable key ของโปรเจค (ซึ่งอยู่ในหน้าเว็บที่ทุกคนโหลดได้)
จะดึงตารางผู้ใช้ทั้งตารางผ่าน HTTPS ได้ **โดยไม่มี request ไหนล้มเหลว
ไม่มี log ที่ไหนผิดปกติ และไม่มีอะไรบนหน้าจอบอกเลย**

**แก้:** `lockDownPublicSchema()` ใน `db.js` เปิด RLS ให้ทุกตารางใน `public` โดยไม่ผูก policy
ซึ่งเท่ากับปฏิเสธทุกบทบาทที่อยู่ใต้ RLS (คือบทบาทของ API) ส่วน **เจ้าของตารางไม่อยู่ใต้ RLS**
แอปจึงทำงานเหมือนเดิมทั้งหมด

ข้อควรระวังที่จงใจใส่ไว้:
- **แตะเฉพาะตารางที่บัญชีนี้เป็นเจ้าของ** ตารางที่ไม่ได้เป็นเจ้าของถูกข้ามพร้อมเตือนในล็อก
  ถ้าเผลอเปิด RLS ให้ตารางที่ไม่ได้เป็นเจ้าของ query จะคืน 0 แถวเงียบๆ แทนที่จะ error
  ซึ่งเป็นความพังที่หาสาเหตุยากที่สุดแบบหนึ่ง
- **ทำงานเฉพาะเมื่อ host ไม่ใช่เครื่องนี้** เครื่องพัฒนาไม่มี REST API มาเปิดข้อมูลอยู่แล้ว
- **เรียกสองครั้ง** ท้าย `db.ready` และอีกครั้งใน `server.js` หลัง `ensureMergedSchemas()`
  เพราะตารางของ Competitive Arena ถูกสร้างทีหลัง ถ้าเรียกครั้งเดียวจะมีช่องว่างหนึ่งรอบบูต
- ปิดได้ด้วย `SUPABASE_RLS_LOCKDOWN=off`

### 3. ไฟล์ดัมป์ restore ไม่ผ่านถ้า Supabase ยังเป็น PostgreSQL 15/16

`schema.sql` กับ `seed-content.sql` สร้างจาก Postgres 18 จึงมีบรรทัด `SET transaction_timeout = 0`
ซึ่งเป็นค่าที่เพิ่งมีใน 17 ฐานข้อมูลรุ่นเก่ากว่าจะตอบ `unrecognized configuration parameter`
แล้วทั้งไฟล์ล้ม

**แก้:** `scripts/dump-schema.js` ตัดบรรทัดนี้ออกตอนสร้าง (ค่าที่ตัดออกคือ 0 = ไม่จำกัดเวลา
ซึ่งเป็นค่าเริ่มต้นอยู่แล้ว จึงไม่เสียอะไร) และสร้างไฟล์ใหม่แล้ว

## ทดสอบ

สร้างฐานข้อมูลทิ้งชื่อ `rls_probe` ในคอนเทนเนอร์เดียวกัน แล้วชี้แอปไปที่มันด้วยชื่อ host
ที่มีจุด (`127.0.0.1.nip.io`) เพื่อให้โค้ดถือว่าเป็นเครื่องนอก — จำลองเส้นทางเดียวกับ Supabase
ทุกขั้นตอน **ลบฐานข้อมูลทิ้งแล้วหลังทดสอบเสร็จ**

| ตรวจอะไร | ผล |
|---|---|
| ติดตั้งลงฐานข้อมูลว่างเปล่าครั้งแรก | ✅ ลง schema + เนื้อหา แล้วเปิด RLS ครบ **64/64 ตาราง** |
| แอปยังอ่านเขียนได้หลังเปิด RLS | ✅ `SELECT` และ `INSERT` ผ่านปกติ (เจ้าของไม่อยู่ใต้ RLS) |
| บูตด้วย `DATABASE_URL` ทั้ง server จริง | ✅ ต่อติด ตารางของ Competitive Arena ถูกปิดด้วย |
| ฐานข้อมูลพัฒนาบนเครื่อง (localhost) | ✅ **ไม่ถูกแตะเลย 0/64 ตาราง** ตามที่ตั้งใจ |
| การเลือก TLS ทั้ง 6 กรณี | ✅ localhost/127.0.0.1/`db` → ปิด · pooler.supabase.com และ db.\*.supabase.co → เปิด · `PGSSLMODE` สั่งทับได้ทั้งสองทาง |
| `test:shop` · `test:lessons` | ✅ 11/11 · 18/18 |

## ที่ยังไม่ผ่าน และไม่ได้เกิดจากงานนี้

`npm run test:problems` ได้ 14 ผ่าน 3 ตก ทั้งสามข้อมาจากเรื่องเดียวกัน:
มีโจทย์แข่งขันข้อใหม่ (`entry_id` 21 "print hello world" สร้างเมื่อ 2026-08-26 01:52)
ถูกโพสต์ผ่านหน้าแอดมินหลังจากที่ตาราง `multiplayer_challenges_pre_merge` ถูกแช่ไว้
ชุดทดสอบนี้เทียบ view กับ snapshot ที่แช่ไว้ จึงตกทุกครั้งที่มีคนเพิ่มโจทย์จริง
**ไม่ควรแก้ด้วยการลบแถวนั้นทิ้ง** — ควรแก้ที่ตัวทดสอบให้ข้ามแถวที่สร้างหลัง snapshot
หรืออัปเดต snapshot ใหม่ ซึ่งเป็นงานคนละชิ้นและควรคุยกับเจ้าของฟีเจอร์ก่อน

## ที่ยังไม่ได้ทำ

- **ยังไม่ได้ต่อกับ Supabase จริง** เพราะ MCP server ยังไม่ได้ผ่านการยืนยันตัวตน
  (ต้องรัน `claude /mcp` ใน terminal ปกติ ซึ่งผู้ใช้ต้องทำเอง) และยังไม่มี connection string
  ทั้งหมดข้างบนจึงทดสอบกับ Postgres ในเครื่องโดยจำลองว่าเป็นเครื่องนอก
- **ไฟล์ที่ผู้ใช้อัปโหลดไม่ได้ย้ายไปด้วย** ยังอยู่บน volume ของเครื่องที่รันแอป
  ถ้าจะใช้ Supabase Storage เป็นงานอีกชิ้น
- **ข้อมูลผู้ใช้เดิมไม่ได้ย้าย** `dump-schema.js` จงใจไม่ดัมป์ข้อมูลผู้ใช้ ถ้าต้องการย้ายจริง
  ต้อง `pg_dump` เฉพาะตารางนั้นเองและห้าม commit ไฟล์นั้นลง git
