# ปุ่ม "ทดสอบโค้ด" ใน Arcade ไม่บอกผลเทสเคส

**วันที่:** 2026-08-26 เวลา 00:30
**ผู้ทำ:** Person 3
**ที่มา:** ผู้ใช้เขียนคำตอบถูกต้องแล้วกด "ทดสอบโค้ด" แต่หน้าจอขึ้นว่า
"โค้ดรันแล้วแต่ไม่ได้พิมพ์อะไรออกมา" ทั้งที่คำตอบถูก

---

## อาการและสาเหตุ

โจทย์ใน Arcade ตอบด้วยการ **เขียนฟังก์ชัน** ไม่ใช่การพิมพ์ผลลัพธ์
ปุ่ม "ทดสอบโค้ด" เอาโค้ดไปรันในเบราว์เซอร์ตรงๆ เพียงอย่างเดียว ซึ่งได้แค่ *นิยาม* ฟังก์ชัน
ไม่มีใครเรียกมัน จึงไม่มีอะไรถูกพิมพ์ออกมาเลย — คำตอบที่ถูกต้องสมบูรณ์ก็ได้ข้อความนี้

ปุ่มชื่อว่า "ทดสอบโค้ด" ผู้เล่นจึงคาดหวังผลของเทสเคส และคาดหวังถูกแล้ว

**ที่มาของบั๊ก**: ตอนแก้ก้อน 2 ผมเอาข้อความปลอมออกจากปุ่มนี้ (ของเดิมพิมพ์
`[PASS] Test Case 1 / [SUCCESS]` ตายตัวโดยไม่ได้รันอะไรเลย) แล้วเปลี่ยนเป็นการรันจริง
การเอาของปลอมออกถูกแล้ว แต่ "รันไฟล์เฉยๆ" ไม่ใช่สิ่งที่โจทย์แบบเรียกฟังก์ชันต้องการ

## แก้อย่างไร

ปุ่มนี้ห่อโค้ดของผู้เล่นด้วยตัวครอบเล็กๆ ที่ **เรียกฟังก์ชันจริงด้วยเทสเคสของรอบนั้น**
แล้วรายงานผลกลับมาเป็นบรรทัดเดียวที่ฝั่ง JS อ่านได้

```
✅ เทสเคสที่ 1: count_words("hello world")
   ควรได้    2
   ได้จริง   2
✅ เทสเคสที่ 2: count_words("")
   ควรได้    0
   ได้จริง   0
✅ เทสเคสที่ 3 ผ่าน
✅ เทสเคสที่ 4 ผ่าน
✅ เทสเคสที่ 5 ผ่าน

ผ่าน 5 จาก 5 เทสเคส
นี่คือการลองรันในเครื่องคุณเอง คะแนนจริงคำนวณที่เซิร์ฟเวอร์ตอนหมดเวลารอบ
```

**ยังเป็น "ลองรัน" เหมือนเดิม** — รันในเบราว์เซอร์ ไม่ให้คะแนน ไม่จ่ายรางวัล
คำตัดสินยังเป็นของ server ตอนปิดรอบตาม `docs/adr/0001-server-owns-the-verdict.md`
และมีบรรทัดบอกไว้ในผลลัพธ์ทุกครั้ง เพื่อไม่ให้ผู้เล่นเข้าใจว่านี่คือคะแนน

**บอกละเอียดเฉพาะเทสเคสที่การ์ดโจทย์เปิดเผยอยู่แล้ว** ส่วนเทสเคสที่เหลือบอกแค่ผ่าน/ไม่ผ่าน
ไม่บอก input และคำตอบ — การ์ดโจทย์ตั้งใจซ่อนครึ่งหลังของชุดทดสอบไว้ ไม่ให้กลายเป็นตารางลอกคำตอบ
ถ้าปุ่มนี้พิมพ์ออกมาหมดก็เท่ากับยกให้ฟรี

## บั๊กที่เจอระหว่างทดสอบ — และร้ายแรงกว่าเรื่องเดิม

ทดสอบด้วยการ**ตั้งชื่อฟังก์ชันผิด** ปรากฏว่ายังขึ้นว่าผ่านเหมือนเดิมทุกตัวอักษร

Pyodide ใช้ล่าม **ตัวเดียวตลอดทั้งแมตช์** ฟังก์ชันที่นิยามไว้ตอนกดทดสอบครั้งก่อน
จึงยังอยู่ใน `globals()` ตัวครอบรุ่นแรกอ่านจาก `globals()` มันเลยหยิบของเก่ามาใช้
— ผู้เล่นที่ลบหรือเปลี่ยนชื่อฟังก์ชันไปแล้วจะยังเห็นว่า "ผ่าน" อยู่

แก้เป็น `exec` โค้ดของผู้เล่นลงใน namespace ใหม่ทุกครั้ง แล้วหาฟังก์ชันจาก namespace นั้น
ไม่ใช่จาก globals ของล่าม

## กรณีอื่นที่ครอบคลุมด้วย

| ผู้เล่นทำอะไร | เห็นอะไร |
|---|---|
| ตอบถูก | ผ่านทุกเทสเคส พร้อมค่าที่ได้จริง |
| ตอบผิด | บอกว่าเทสไหนไม่ผ่าน และได้ค่าอะไรออกมาแทน |
| ฟังก์ชันพังตอนถูกเรียก | บอกชนิดข้อผิดพลาด เช่น `IndexError: list index out of range` เฉพาะเทสเคสนั้น |
| เขียนผิดไวยากรณ์ | "โค้ดหยุดทำงานก่อนที่จะได้ทดสอบสักเทสเคส: SyntaxError: expected ':'" |
| ตั้งชื่อฟังก์ชันไม่ตรง | "ไม่พบฟังก์ชันชื่อ `most_frequent` — ตรวจว่าสะกดตรงกันไหม..." |
| มี `print()` ของตัวเอง | แสดงแยกใต้หัวข้อ "สิ่งที่โปรแกรมพิมพ์ออกมา:" |

โจทย์ที่ไม่ได้เป็นแบบเรียกฟังก์ชัน (ยังไม่มีในคลัง แต่เป็นไปได้) จะกลับไปรันไฟล์ตรงๆ เหมือนเดิม

ต้องยังตอบว่าไม่พบฟังก์ชัน — ถ้าไม่มีเทสข้อนี้ บั๊กที่เพิ่งแก้จะกลับมาได้แบบเงียบๆ
