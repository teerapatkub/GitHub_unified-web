# Import ฐานข้อมูลขึ้น Supabase (ยังไม่ย้ายแอปไปใช้)

**วันที่:** 2026-08-26 เวลา 00:30 (ของวันถัดไป)
**ผู้ทำ:** Person 3
**ที่มา:** ผู้ใช้ขอให้ import ฐานข้อมูลขึ้น Supabase ไว้ก่อน โดยยังไม่ย้ายแอปไปใช้

---

## หาที่อยู่ของฐานข้อมูลก่อน

รู้แค่ `project_ref` จาก URL ของ MCP server และ MCP ยังไม่ได้ยืนยันตัวตน จึงถาม API ไม่ได้
หาเอาจากการเชื่อมต่อจริง

- **ต่อตรง `db.<ref>.supabase.co:5432` ใช้ไม่ได้จากเครื่องนี้** — DNS มีแต่ระเบียน AAAA (IPv6)
  และเครื่องนี้ไม่มี IPv6 ออกอินเทอร์เน็ต Node ตอบ `getaddrinfo ENOTFOUND`
  ทั้งที่ `nslookup` เห็นที่อยู่ นี่คือเหตุผลที่เอกสาร deploy เขียนไว้ว่าให้ใช้ pooler
- **ไล่หาภูมิภาคด้วยการลองต่อทีละที่** — pooler ตอบ `tenant/user not found` ถ้าโปรเจคไม่ได้อยู่
  ภูมิภาคนั้น ลองไป 10 ภูมิภาคจึงเจอว่าอยู่ที่ **ap-northeast-1 (โตเกียว)** ไม่ใช่สิงคโปร์อย่างที่เดา

**ที่อยู่ที่ใช้ได้:** `aws-0-ap-northeast-1.pooler.supabase.com`
พอร์ต **5432 = session mode** (ใช้ตอน import เพราะรองรับทุกอย่าง) ·
พอร์ต **6543 = transaction mode** (ใช้ตอนรันจริง) · ฐานข้อมูลเป็น **PostgreSQL 17.6**

## วิธี import — ให้แอปติดตั้งตัวเองตามทางที่เขียนไว้ในเอกสาร

ไม่ได้ยิง SQL เข้าไปมือเปล่า แต่บูตแอปหนึ่งครั้งโดยชี้ `DATABASE_URL` ไปที่ Supabase
ซึ่งเป็นเส้นทางเดียวกับที่เขียนไว้ใน `docs/deploy.md` และเป็นการทดสอบโค้ดที่เพิ่งแก้ไปด้วยในตัว

ลำดับที่เกิดขึ้นจริงตามล็อก: ฐานข้อมูลว่างเปล่า → ลง `schema.sql` → ใส่ `seed-content.sql`
→ สร้างตาราง Arcade + seed คลังโจทย์ → ร้านค้า → ความสำเร็จ → แบบสำรวจ →
ตารางของ Competitive Arena → คำนวณว่าโจทย์ข้อไหนตรวจอัตโนมัติได้บนเครื่องนั้น

## ⭐ สิ่งที่พบ — Supabase เปิด RLS ให้เองอยู่แล้ว

ล็อกไม่มีบรรทัด `🔒 ปิดการเข้าถึงจาก Data API` เลย ทั้งที่ทุกตารางมี RLS เปิดอยู่
ตามไปตรวจด้วยการสร้างตารางเปล่าขึ้นมาใหม่แล้ววัดค่า `relrowsecurity` ทันที — ได้ `true`
โดยไม่มีใครไปสั่ง

แปลว่า **Supabase เปิด RLS ให้ตารางใหม่ใน `public` โดยอัตโนมัติ** และ `lockDownPublicSchema()`
ที่เขียนไว้เมื่อวานทำงานถูกต้อง คือ **ข้ามตารางที่มี RLS อยู่แล้วและไม่พูดอะไร**
(คำเตือนในโค้ดที่เขียนว่า Supabase ไม่ทำให้เอง จึงเป็นการเดาที่ผิด — แต่ผลลัพธ์ตรงกัน)

ฟังก์ชันนั้นยังมีประโยชน์อยู่ เพราะ Postgres เจ้าอื่น (Neon, RDS) ไม่มีพฤติกรรมนี้
และเป็นตาข่ายรองสำหรับตารางที่หลุดจากค่าเริ่มต้นของ Supabase

## สิ่งที่ยังไม่ทำ และตั้งใจไม่ทำ

- **แอปยังชี้ที่ฐานข้อมูลในเครื่องเหมือนเดิม** ไม่ได้ใส่ `DATABASE_URL` ลงใน `server/.env`
  ตามที่ผู้ใช้บอกว่ายังไม่ย้าย — ที่อยู่ Supabase ใช้เป็นตัวแปรชั่วคราวตอนรันคำสั่งเท่านั้น
- **ไม่ได้ย้ายบัญชีผู้ใช้เดิม** 30 บัญชีบนเครื่องพัฒนายังอยู่ที่เดิม ถ้าจะย้ายต้อง `pg_dump`
  เฉพาะตารางนั้นแยกต่างหาก และห้ามให้ไฟล์นั้นเข้า git
- **ไม่ได้ทดสอบว่า REST API ของ Supabase ปฏิเสธการอ่านจริงหรือไม่** เพราะต้องใช้ publishable key
  ซึ่งยังไม่มี ที่ยืนยันได้คือสถานะ RLS ในฐานข้อมูลว่าเปิดครบทุกตาราง
- **ลบสคริปต์ที่ใช้สำรวจทิ้งแล้ว** ไม่มีไฟล์ไหนในโปรเจคที่มีรหัสผ่านฐานข้อมูลอยู่

## ⚠️ เรื่องรหัสผ่าน

รหัสผ่านฐานข้อมูลถูกส่งมาในแชทเป็นข้อความธรรมดา ควรถือว่าเป็นรหัสที่หลุดแล้ว
แนะนำให้เปลี่ยนรหัสใหม่ใน Supabase (Settings → Database → Reset database password)
หลังจากตั้งค่าที่จำเป็นเสร็จ แล้วเก็บรหัสใหม่ไว้ใน `server/.env` อย่างเดียว
