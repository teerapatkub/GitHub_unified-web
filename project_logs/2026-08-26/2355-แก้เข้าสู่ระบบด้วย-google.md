# แก้เข้าสู่ระบบด้วย Google ที่ใช้งานไม่ได้

**วันที่:** 2026-08-26 เวลา 23:55
**ผู้ทำ:** Person 3
**ที่มา:** ผู้ใช้กดปุ่ม "เข้าสู่ระบบด้วย Google" แล้วขึ้นข้อความแดงว่า
`ยังไม่ได้ตั้งค่า GOOGLE_CLIENT_ID เป็น OAuth Web Client ID ใน server/.env`

---

## ต้นเหตุ — ตั้งค่าไว้ครึ่งเดียว

การเข้าสู่ระบบด้วย Google ต้องใช้ค่าเดียวกันสองฝั่ง

| ฝั่ง | อ่านจาก | สถานะที่พบ |
|---|---|---|
| เบราว์เซอร์ (ขอ token จาก Google) | `client/.env` → `VITE_GOOGLE_CLIENT_ID` | ✅ มีอยู่ ถูกต้อง |
| เซิร์ฟเวอร์ (ตรวจ token ที่ Google ออกให้) | `server/.env` → `GOOGLE_CLIENT_ID` | ❌ **ไม่มีเลย** |

`server/.env` ไม่มีบรรทัดนี้ (ไฟล์นี้มีมาก่อนที่ Person 2 จะเพิ่มฟีเจอร์นี้)
`GOOGLE_LOGIN_ENABLED` จึงเป็นเท็จ และ `POST /api/auth/google` ตอบ 503 ทุกครั้ง
พร้อมข้อความที่ผู้ใช้เห็นในภาพ

**อาการนี้จะเกิดตอน deploy จริงด้วย** เพราะ compose ส่ง `VITE_GOOGLE_CLIENT_ID`
เป็น build arg แต่ไม่มีใครบอกว่า runtime ต้องมี `GOOGLE_CLIENT_ID` ใน `server/.env`

## ที่แก้

**1. ใส่ `GOOGLE_CLIENT_ID` ใน `server/.env`** (ไม่อยู่ใน git ตรวจแล้วด้วย `git check-ignore`)
ใช้ค่าเดียวกับฝั่งเบราว์เซอร์ — OAuth **Web** Client ID ไม่ใช่ความลับอยู่แล้ว
เพราะถูกฝังอยู่ในบันเดิลที่ทุกคนดาวน์โหลด

**2. ปุ่มต้องบอกความจริงตั้งแต่ก่อนกด** — เดิมหน้าเข้าสู่ระบบเชื่อค่าที่ฝังมากับบันเดิล
อย่างเดียว ปุ่มจึงกดได้ปกติ ผู้ใช้เลือกบัญชี Google เสร็จ **แล้วค่อยไปล้มตอนสุดท้าย**
ตอนนี้หน้าเข้าสู่ระบบถาม `/api/config/google` เสมอ ถ้าเซิร์ฟเวอร์ตรวจ token ไม่ได้
ปุ่มจะขึ้นว่า "ยังไม่เปิดให้เข้าสู่ระบบด้วย Google" และกดไม่ได้ ส่วนการเข้าสู่ระบบ
ด้วยชื่อผู้ใช้ยังทำงานปกติทุกอย่าง

**3. ข้อความสำหรับคนสองกลุ่ม แยกกัน** — คนที่มองหน้าจอเข้าสู่ระบบไม่ได้เป็นคนตั้งค่า
และแก้อะไรไม่ได้ จึงได้ข้อความว่า *"ตอนนี้เข้าสู่ระบบด้วย Google ยังใช้ไม่ได้
กรุณาเข้าสู่ระบบด้วยชื่อผู้ใช้และรหัสผ่าน"* ส่วนวิธีแก้ไปอยู่ใน log ของเซิร์ฟเวอร์
กับ console ซึ่งเป็นที่ที่คนแก้ได้จะเห็น

**4. เอกสาร** `docs/deploy.md` เพิ่มแถว `GOOGLE_CLIENT_ID` และหัวข้อ
"ตั้งที่เดียวพอ" — ใส่ใน `server/.env` อย่างเดียว ไม่ต้องตั้ง `VITE_GOOGLE_CLIENT_ID`
ตอน build เพราะหน้าเข้าสู่ระบบขอค่านี้จาก `/api/config/google` อยู่แล้ว
พร้อมเตือนว่าถ้าสองฝั่งเป็นคนละ client id ผู้ใช้จะเลือกบัญชีได้ตามปกติแล้วไปล้มตอนสุดท้าย

## ไฟล์

| ไฟล์ | ทำอะไร |
|---|---|
| `server/.env` (ไม่อยู่ใน git) | เพิ่ม `GOOGLE_CLIENT_ID` |
| `server/server.js` | ข้อความ 503 และ 500 ของ `/api/auth/google` เป็นภาษาที่ผู้เรียนอ่านแล้วรู้ว่าต้องทำอะไร + log สำหรับผู้ดูแล |
| `client/src/pages/FriendLogin.jsx` | ถามสถานะจากเซิร์ฟเวอร์เสมอ · ปิดปุ่มเมื่อระบบยังไม่พร้อม |
| `docs/deploy.md` | วิธีตั้งค่าสำหรับตอน deploy |

## ทดสอบ

| สถานะ | ผลบนหน้าจอจริง |
|---|---|
| ตั้งค่าครบ | ✅ `/api/config/google` → `enabled:true` · ปุ่มขึ้น "เข้าสู่ระบบด้วย Google" กดได้ |
| ตั้งค่าครบ + token ปลอม | ✅ เซิร์ฟเวอร์เข้าสู่ขั้นตอนตรวจจริงและปฏิเสธ (ไม่ใช่ 503 เหมือนเดิม) |
| ไม่ได้ตั้งค่า (ปิดชั่วคราวแล้วรีสตาร์ทจริง) | ✅ ปุ่มขึ้น "ยังไม่เปิดให้เข้าสู่ระบบด้วย Google" และกดไม่ได้ · API ตอบข้อความภาษาไทยที่ผู้ใช้ทำตามได้ |
| คืนค่าเดิม | ✅ กลับมาปกติ ตรวจซ้ำแล้ว |

## หมายเหตุ

ยังไม่ได้ทดสอบการล็อกอินด้วยบัญชี Google จริงจนจบ เพราะต้องใช้บัญชีของผู้ใช้เอง
สิ่งที่ยืนยันได้คือช่องโหว่การตั้งค่าที่ทำให้ระบบปฏิเสธทุกคำขอถูกปิดแล้ว
ถ้าล็อกอินจริงแล้วยังไม่ผ่าน ให้ดูที่ **Authorized JavaScript origins** ของ client id
ใน Google Cloud Console ว่ามีที่อยู่ที่ใช้เปิดเว็บอยู่หรือยัง (เช่น `http://localhost:5174`)
ซึ่งเป็นการตั้งค่าฝั่ง Google ที่ต้องทำในบัญชีของผู้ใช้เอง
