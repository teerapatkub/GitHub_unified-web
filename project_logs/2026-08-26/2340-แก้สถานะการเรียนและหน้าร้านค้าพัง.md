**ผู้ทำ:** Person 3
**ที่มา:** ผู้ใช้เล่นจริงแล้วเจอสองอาการ พร้อมภาพหน้าจอ

1. สถานะการเรียนไม่แสดงว่ากำลังเรียนอยู่ ทั้งที่ทำโจทย์ไปแล้ว

## อาการที่ 2 — ร้านค้าเรียก API ผิดที่อยู่ (พังทั้งหน้า)

ข้อความ `Unexpected token '<'` แปลว่าโค้ดขอ JSON แต่ได้ HTML กลับมา
ต้นเหตุคือหน้าร้านค้ายิงไปที่ `/shop/items` ซึ่ง**ไม่ได้ขึ้นต้นด้วย `/api`**

เส้นทางของ request มีแค่สองที่ที่ยอมส่งต่อไปยัง API คือ `/api` กับ `/uploads`
— dev server proxy ตามนี้ และตอน deploy จริง server ตัวเดียวกันเสิร์ฟหน้าเว็บด้วย
แล้วถือว่าทุก path นอกสองอันนี้คือ "หน้าเว็บ" จึงตอบ `index.html` กลับมา
ร้านค้าจึงได้ HTML แทน JSON **ทั้งในเครื่องพัฒนาและบนเครื่องจริง**

เดิมไม่พังเพราะโค้ดเขียน `http://localhost:3001/shop/items` ตรงๆ ซึ่งข้ามระบบ proxy ไปเลย
พอเปลี่ยนมาใช้ `API_BASE` เพื่อให้ deploy ได้ (commit `96eeae7`) ที่อยู่นี้จึงกลายเป็น
path เปล่าที่ไม่มีใครรับ — ร้านค้าเป็นหน้าเดียวในแอปที่ยังใช้ path นอก `/api`

**ที่แก้:** route ของร้านค้าทั้ง 6 เส้นรับทั้ง `/api/shop/...` และ `/shop/...` เดิม
(ฟังก์ชัน `shopPath()` ใน `server.js`) ส่วนหน้าร้านค้าเปลี่ยนมาเรียก `/api/shop/...`
ที่เก็บ path เดิมไว้ด้วยเพราะชุดทดสอบ `test:shop` / `test:achievements` ยิงตรงเข้า `:3001`
ด้วย path เดิม และของแบบนั้นไม่ควรพังเพราะการย้ายที่อยู่

## อาการที่ 1 — ป้ายสถานะอ่านฟิลด์ที่ API ไม่เคยส่ง

`LearningPage.jsx` ตัดสินป้ายสถานะจาก `lesson.post_quiz_completed` และ
`lesson.pre_quiz_completed` แต่ `GET /api/course-content` **ไม่เคยส่งสองฟิลด์นี้เลย**
ส่งมาแค่ `completed_count` / `total_count` ของแบบฝึกหัด

`undefined` เป็นเท็จเสมอ ป้ายจึงตกลงมาที่ "ยังไม่เริ่ม" ทุกบท ทุกคน ตลอดเวลา

### ⭐ ของแถมที่อันตรายกว่า — หลักสูตรตันตั้งแต่บทที่ 2

รอบที่แล้วผู้ใช้สั่งให้บทเรียนย่อยปลดล็อกตามลำดับ และเงื่อนไขที่ใช้คือ
`previousLesson.post_quiz_completed` — **ฟิลด์เดียวกับที่ไม่มีอยู่จริง**

ผลคือบทที่ 2 เป็นต้นไปจะไม่มีวันเปิดให้ใครเลย ไม่ว่าจะเรียนหรือทำแบบทดสอบไปแล้วแค่ไหน
และ**ไม่มี error ที่ไหนเลยสักที่** หน้าเว็บดูปกติทุกอย่าง เห็นได้จากภาพหน้าจอที่ผู้ใช้ส่งมา
ที่บทที่ 2-4 ขึ้น "ต้องเรียนบทก่อนให้จบ" ทั้งที่บทที่ 1 กำลังเรียนอยู่

นี่คือบั๊กที่การอ่านโค้ดฝั่งหน้าจออย่างเดียวจับไม่ได้ ต้องยิง API ดูจริงว่าฟิลด์ที่โค้ดอ่านมีอยู่ไหม

### ต้นเหตุร่วม — นิยาม "เรียนถึงไหนแล้ว" มีสามชุดที่ไม่ตรงกัน

ระหว่างตามเรื่องเจอว่ามีสามที่ที่ตัดสินว่าบทเรียนจบแล้วหรือยัง เขียนกันคนละเวลา:
ตัวนับความสำเร็จ, หน้าโปรไฟล์, และป้ายในหน้าบทเรียน (ที่ถามหาฟิลด์ที่ไม่มี)
รูปแบบเดียวกับที่โปรเจคนี้เคยมีตัวตรวจคำตอบ 5 ตัวที่ให้ผลไม่ตรงกัน

**รวมเหลือชุดเดียวที่ `server/lessonProgress.js`** ทั้งสามที่เรียกตัวเดียวกัน

### เกณฑ์ที่ใช้

| เกณฑ์ | นิยาม | ทำไม |
|---|---|---|
| **กำลังเรียน** | ทำแบบทดสอบก่อน/หลังเรียน **หรือ** ส่งคำตอบแบบฝึกหัดแล้ว แม้ยังไม่ผ่าน | ลองแล้วผิดก็คือการเรียน การบอกคนที่ทำไปแล้วว่า "ยังไม่เริ่ม" เหมือนแอปทำงานเขาหาย |
| **เรียนเสร็จสิ้น** | ผ่านแบบทดสอบท้ายบท **และ** แบบฝึกหัดผ่านครบ | เท่าเดิม ตรงกับหน้าโปรไฟล์และความสำเร็จ |
| **เปิดบทถัดไป** | ผ่านแบบทดสอบท้ายบทเท่านั้น | เบากว่า "เรียนเสร็จสิ้น" โดยตั้งใจ — คนที่ติดแบบฝึกหัดข้อเดียวไม่ควรถูกล็อกทั้งหลักสูตร |
| **บทที่ไม่มีแบบทดสอบท้ายบท** | ใช้แบบฝึกหัดครบแทน | **5 บทจาก 24 ไม่มีแบบทดสอบท้ายบท** (บทที่ 6 และทั้งบทที่ 8-9) ถ้ายืนกรานว่าต้องผ่านแบบทดสอบ บททั้งห้าจะจบไม่ได้ตลอดกาล และกลายเป็นกำแพงกลางหลักสูตร |

ข้อความตอนล็อกก็บอกให้ชัดว่าต้องทำอะไร — "ทำแบบทดสอบท้ายบทของ ... ให้ผ่านก่อน"
แทนคำว่า "ให้จบก่อน" ที่ไม่ได้บอกว่าอะไรคือจบ

## ผลกระทบกับส่วนอื่น

- **ไม่มีการเปลี่ยน schema** ใช้ตาราง `lesson_quiz_attempts`, `lesson_quizzes`,
  `exercise_submissions` เดิมทั้งหมด
- `/api/course-content` **เพิ่มฟิลด์อย่างเดียว** ของเดิมชื่อเดิมความหมายเดิมครบทุกตัว
- `/api/profile/:userId` ให้ค่าเท่าเดิมทุกค่า ยกเว้นบทที่ไม่มีแบบทดสอบท้ายบท
  ซึ่งเดิมคิด % จากขั้นตอนที่ไม่มีอยู่จริง (ทำให้ 5 บทนั้นขึ้น 100% ไม่ได้)
- ตัวนับความสำเร็จ `lessons_completed` อาจนับได้เพิ่มขึ้นสำหรับบทที่ไม่มีแบบทดสอบท้ายบท
  ซึ่งเป็นการนับที่ถูกต้อง — ของเดิมนับไม่ได้เลยไม่ว่าจะทำครบแค่ไหน
- แก้ SQL ของ `/api/course-content` เป็น `COUNT(DISTINCT ...)` ทั้งสองฝั่ง
  ของเดิมนับต่อแถวของตารางส่งคำตอบ ถ้ามีใครส่งซ้ำจะขึ้น "ภาคปฏิบัติ 2/9" ในบทที่มี 5 ข้อ
