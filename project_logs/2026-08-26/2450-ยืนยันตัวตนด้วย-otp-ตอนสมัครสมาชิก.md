# ยืนยันตัวตนด้วยรหัส OTP ตอนสมัครสมาชิก

**วันที่:** 2026-08-26 เวลา 00:50 (ของวันถัดไป)
**ผู้ทำ:** Person 3
**ที่มา:** ผู้ใช้ขอให้การลงทะเบียนบัญชีมีการส่ง OTP เพื่อยืนยันตัวตน

---

## ของเดิมเป็นแค่พิธีกรรม

ตอนสมัคร ระบบส่ง**ลิงก์**ยืนยันที่มีอายุ 24 ชั่วโมง แต่ **ไม่มีโค้ดที่ไหนตรวจเลยว่ายืนยันหรือยัง**
คอลัมน์ `users.email_verified` มีอยู่จริงในตาราง แต่ **ไม่มี code path ไหนเขียนค่าลงไปเลย**
(ตรวจแล้ว: ผู้ใช้ทั้ง 30 คนในฐานข้อมูลพัฒนามีค่าเป็น 0 ทุกคน รวมทั้งคนที่กดลิงก์ไปแล้ว
เพราะ endpoint ของลิงก์อัปเดตแค่ `email_verifications.verified_at`)

บัญชีที่ไม่เคยเปิดอีเมลจึงใช้งานได้เหมือนบัญชีที่ยืนยันแล้วทุกประการ

**ทำไมเป็นรหัสไม่ใช่ลิงก์** — สถานการณ์จริงของกลุ่มผู้ใช้คืออ่านเมลบนมือถือแต่สมัครบนคอม
ซึ่งเป็นกรณีที่ลิงก์ทำงานได้แย่ที่สุด รหัส 6 หลักพิมพ์ข้ามเครื่องได้

## กติกาของรหัส และเหตุผล

| ค่า | ตั้งเท่าไหร่ | ทำไม |
|---|---|---|
| ความยาว | 6 หลัก | เดาถูก 1 ใน 1,000,000 ต่อครั้ง |
| อายุ | 10 นาที | |
| เดาผิดได้ | 5 ครั้ง | **นี่คือสิ่งที่ทำให้ 6 หลักปลอดภัยพอ** ถ้าเดาได้ไม่จำกัด 1 ในล้านไม่ได้แปลว่าอะไรเลย |
| ขอรหัสใหม่ | ทุก 60 วินาที | กันการใช้ระบบเราส่งเมลถล่มคนอื่น |

- **สุ่มด้วย `crypto.randomInt` ไม่ใช่ `Math.random`** เพราะตัวเลขนี้คือความลับทั้งหมด
- **เก็บเป็น bcrypt hash** เหมือนรหัสผ่าน ฐานข้อมูลที่หลุดต้องไม่แจกรหัสสดของทุกคนที่กำลังสมัครอยู่
- **มีรหัสที่ใช้ได้ทีละหนึ่งอันต่อบัญชี** การขอรหัสใหม่ลบอันเก่าทิ้ง ไม่งั้นทุกรหัสที่เคยส่ง
  จะใช้ได้หมดจนกว่าจะหมดอายุ ซึ่งทำให้ "ขอรหัสใหม่" กลายเป็นการเพิ่มเป้าให้คนเดา
- **ทั้งเพดานการเดาและอายุเก็บไว้ในแถวของฐานข้อมูล** ไม่ใช่ในหน่วยความจำ จึงอยู่รอดข้ามการรีสตาร์ท
  และไม่โดนหลบด้วยการเปิดหลายแท็บ

## ⭐ จุดที่ต้องระวัง — ห้ามล็อกผู้ใช้เดิมออกจากระบบ

ถ้ากันคนเข้าระบบด้วยเงื่อนไข `users.email_verified = 0` **ผู้ใช้เดิมทั้ง 30 คนจะเข้าไม่ได้ทันที**
เพราะไม่มีใครเคยเขียนคอลัมน์นั้น

จึงกันด้วยเงื่อนไขที่ตรงกว่า: **บัญชีนี้มีรหัสที่ยังไม่ได้ใช้ค้างอยู่หรือไม่**
(`email_verifications` ที่ `purpose = 'otp'` และ `verified_at IS NULL`)
บัญชีเดิมไม่มีแถวแบบนี้เลยสักคน จึงไม่ได้รับผลกระทบ ส่วนบัญชีที่สมัครหลังจากนี้จะมี
และการยืนยันสำเร็จก็เป็นครั้งแรกที่คอลัมน์ `email_verified` ถูกเขียนจริง

## รายละเอียดที่ตั้งใจทำ

- **ตรวจรหัสผ่านก่อนแล้วค่อยตรวจสถานะยืนยัน** ที่ `/api/login` — ถ้าสลับกัน จะกลายเป็น
  ช่องให้คนเดาว่าบัญชีไหนมีอยู่ในระบบโดยไม่ต้องรู้รหัสผ่าน
- **`/api/resend-otp` ตอบเหมือนกันทุกกรณี** ไม่ว่าอีเมลนั้นจะมีบัญชีหรือไม่ ด้วยเหตุผลเดียวกัน
- **เข้าสู่ระบบด้วยบัญชีที่ยังไม่ยืนยัน ไม่ใช่ความผิดพลาด** แต่คือคนเดิมที่กลับมาทำต่อ
  ระบบจึงพาไปหน้ากรอกรหัสให้เลย แทนที่จะขึ้น error ที่ผู้เรียนทำอะไรต่อไม่ถูก
- **ยืนยันเสร็จแล้วเข้าใช้งานได้เลย** ไม่ต้องกลับไปล็อกอินใหม่ เพราะเพิ่งพิสูจน์ทั้งรหัสผ่าน
  และกล่องจดหมายไปพร้อมกันแล้ว การส่งกลับไปหน้าล็อกอินอ่านได้ว่ารหัสไม่ผ่าน
- **ถ้ายังไม่ได้ตั้งค่า SMTP รหัสจะออกที่ log ของเซิร์ฟเวอร์** เพื่อให้พัฒนาต่อได้
  **แต่ไม่เคยส่งกลับผ่าน API** ไม่งั้นเครื่องที่ deploy แล้วลืมตั้งค่าเมลจะแจกรหัสให้ใครก็ได้ที่ขอ
- ลิงก์แบบเดิมยังใช้ได้อยู่ (แยกกันด้วยคอลัมน์ `purpose`) เพราะลิงก์ที่ส่งไปแล้วไม่ควรตายกลางทาง

## ทดสอบ

**ปิด SMTP ชั่วคราวระหว่างทดสอบ ไม่มีอีเมลจริงถูกส่งออกไปเลย** และคืนค่าเดิมแล้ว

| กรณี | ผล |
|---|---|
| สมัครสมาชิก | ✅ ได้ `requiresOtp` และรหัสออกที่ log |
| เข้าสู่ระบบทั้งที่ยังไม่ยืนยัน | ✅ 403 พร้อม `requiresOtp` และอีเมล |
| กรอกรหัสผิด | ✅ นับถอยหลัง "เหลืออีก 4 / 3 / 2 / 1 ครั้ง" |
| ผิดครบ 5 ครั้ง | ✅ รหัสตาย **แม้กรอกรหัสที่ถูกต้องก็ไม่ผ่าน** |
| รหัสหมดอายุ (ย้อนเวลาในฐานข้อมูล) | ✅ 410 พร้อมข้อความให้ขอรหัสใหม่ |
| ขอรหัสใหม่ก่อนครบ 60 วินาที | ✅ 429 บอกว่าเหลืออีกกี่วินาที |
| ขอรหัสใหม่หลังครบเวลา แล้วยืนยันด้วยรหัสใหม่ | ✅ ผ่าน (กู้คืนจากรหัสที่ตายแล้วได้จริง) |
| ใช้รหัสเดิมซ้ำหลังยืนยันแล้ว | ✅ ปฏิเสธ |
| ขอรหัสด้วยอีเมลที่ไม่มีบัญชี | ✅ ตอบเหมือนกรณีมีบัญชี ไม่บอกว่าใครสมัครไว้ |
| เข้าสู่ระบบหลังยืนยันแล้ว | ✅ 200 ปกติ |
| **บนหน้าจอจริง — สมัคร → กรอกรหัสผิด → กรอกถูก** | ✅ เห็นข้อความ "เหลืออีก 4 ครั้ง" แล้วเข้าสู่หน้าแบบสำรวจ |
| **บนหน้าจอจริง — ล็อกอินบัญชีที่ยังไม่ยืนยัน** | ✅ เด้งเข้าหน้ากรอกรหัสพร้อมอีเมลที่ถูกต้อง |

## สิ่งที่ยังไม่ได้ทดสอบ

**การส่งอีเมลจริงผ่าน SMTP** — ตั้งใจไม่ทดสอบเพราะจะเป็นการส่งอีเมลออกไปจริง
โค้ดส่วนที่เรียก `emailTransporter.sendMail()` เป็นตัวเดิมที่ระบบลืมรหัสผ่านใช้อยู่แล้ว
เปลี่ยนแค่เนื้อความ ถ้าต้องการยืนยัน ให้ลองสมัครด้วยอีเมลจริงของตัวเองหนึ่งครั้ง
