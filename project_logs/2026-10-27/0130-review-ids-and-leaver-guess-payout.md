## 1. รอบตรวจคำตอบ AI: id ของตัวเลือกบอกว่าข้อไหนถูก

- **บั๊ก:**
  - `computeReview` สร้างตัวเลือกเป็น `[เฉลย, ...คำตอบผิด]` แล้วตั้ง id เป็น `'abcd'[i]` เฉลยจึงเป็น `a` ทุกข้อ
  - หน้าจอสลับลำดับให้แต่ละคน แต่ id ส่งถึง browser ตรงๆ
  - ใครเปิด DevTools หรือแค่จำได้ว่า "เลือก a" ก็ชนะทุกรอบตรวจ
- **แก้ (`server/arcade/round-kinds.js`):**
  - id ของตัวเลือกคือ sha256 ของโค้ด 8 ตัวอักษร ไม่ขึ้นกับลำดับในรายการ
  - `choiceOptions` คำนวณ id ใหม่ทุกครั้งที่อ่าน แถว `round_data` เดิมที่เก็บเป็นตัวอักษรจึงปลอดภัยทันทีโดยไม่ต้องคำนวณข้อมูลใหม่
  - หน้ารอบ การตรวจคำตอบ การตรวจ payload และบอท อ่านผ่าน `choiceOptions` ตัวเดียวกันหมด
  - ยาว 8 ตัวอักษรเพราะ endpoint ส่งคำตอบจำกัด `choice` ไว้ที่ 8 ตัว
- **`bot-ticker.js`:**
  - `decideChoice` เคยเทียบตัวเลือกด้วย identity (`option !== right`)
  - ตอนนี้ `choiceOptions` คืน object ใหม่ทุกครั้ง จึงเปลี่ยนเป็นเทียบด้วย id
  - ถ้าไม่แก้ บอทจะนับคำตอบถูกเป็นคำตอบผิดด้วย

## 2. ทายผู้รอดถูก แต่ออกจากห้องก่อนจบแมตช์ ทองหาย

- **บั๊ก:**
  - ปุ่มออกจากห้องของคนที่ตกรอบ (ticket 06) ลบแถว participant
  - ตอน settle จ่ายเฉพาะคนที่ยังมีแถวอยู่ 30 ทองจึงหายเงียบๆ
- **แก้ (`server/arcade/match-rewards.js`):**
  - ล็อกบัญชีของคนที่ทายแล้วออกไปพร้อมผู้เล่นใน query เดียว เรียงตาม `user_id` เหมือนเดิม จึงไม่เพิ่มโอกาส deadlock
  - คนที่ออกไปแล้วไม่มีอันดับ จึงไม่ได้ทองของแมตช์และไม่มี receipt ได้เฉพาะทองจากการทาย
  - กันจ่ายซ้ำด้วยคอลัมน์ใหม่ `arcade_spectator_guesses.paid_coins` ซึ่งตั้งค่าครั้งเดียวใน transaction ของ settle
- **migration ใหม่ `202610270001` (`arcade_guess_payouts`):** ไฟล์ `server/arcade/migrate-guess-payouts.js` ไม่แตะ migration เดิม
