# เตรียมการทดสอบกับผู้เริ่มต้นจริง (ประตูสุดท้ายของ Arcade)

**วันที่**: 2026-08-20 เวลา 19:02
**ผู้ทำ**: Person 3 (Arcade Battle Royale)

---

## สิ่งที่ทำไม่ได้ และทำแทนไม่ได้ — พูดตรงๆ ก่อน

ข้อนี้คือ **"ยังไม่มีผู้เริ่มต้นจริงลองเล่น"** ซึ่งผมเป็นผู้เริ่มต้นแทนไม่ได้
สิ่งที่ผมรู้คำตอบอยู่แล้วทำให้ผมไม่มีทางวัดได้ว่า "คนที่เพิ่งเรียน Python คิดออกไหมใน 60 วินาที"
การที่ผมเล่นเองแล้วผ่านทุกรอบ **ไม่ใช่หลักฐานอะไรเลย**

ดังนั้นงานรอบนี้คือทำให้การทดสอบกับคนจริง **เกิดขึ้นได้ง่ายและเก็บผลได้เอง**
ไม่ใช่การแกล้งทำว่าทดสอบไปแล้ว

---

## 1. เจออุปสรรคก่อนเริ่ม: guest เข้าโหมดนี้ไม่ได้

`/matchmaking` มี route guard เป็น `isAuthenticated = user && !user.isGuest`
แปลว่าผู้ทดสอบ **ต้องมีบัญชีจริง** ถ้าให้เขามาสมัครหน้างานจะเสียเวลาและเสียอารมณ์ก่อนได้เริ่มเล่น
→ ใส่ไว้เป็นข้อแรกของคู่มือว่า **ต้องสร้างบัญชีให้ผู้ทดสอบล่วงหน้า**

---

## 2. เพิ่มให้ประวัติแมตช์จำได้ว่าเล่นที่ระดับไหน

`arcade_round_history` เก็บทุกอย่างที่ต้องใช้อยู่แล้ว (โค้ด ผ่านกี่เทส ใช้เวลาเท่าไร)
แต่**ไม่ได้เก็บว่าห้องนั้นตั้งระดับอะไรและรอบยาวเท่าไร** ซึ่งจำเป็นต่อการตัดสิน —
"ทำได้ 2 จาก 4 รอบ" มีความหมายคนละอย่างระหว่างห้อง 30 วินาทีกับ 60 วินาที
และห้องจะถูกลบทิ้งทันทีที่ไม่มีคนอยู่ จึงย้อนไปดูทีหลังไม่ได้

เพิ่มคอลัมน์ `difficulty` และ `round_duration_mode` ลง `arcade_round_history`
(เพิ่มล้วน ไม่มี DROP/TRUNCATE) เหตุผลเดียวกับที่เคย denormalize `room_code`/`room_name` ไว้
พร้อมให้ `GET /players/:user_name/history` ส่งค่าออกมาด้วย

## 3. `playtest-report.js` — เปลี่ยนการเล่นจริงให้เป็นคำตัดสิน

```bash
npm run playtest:report -- <ชื่อผู้ใช้>
```

อ่านแมตช์ล่าสุดของคนนั้น แล้วแสดงรายรอบ: ผ่านกี่ test case (มีแถบภาพ), ใช้เวลาไปกี่ % ของรอบ,
คะแนน quality — แล้วตัดสินตามเกณฑ์ **≥2 จาก 4 รอบ ในห้อง easy โหมด Standard**

จุดที่ตั้งใจออกแบบไว้:
- **ถ้าแมตช์ไม่ใช่ easy/Standard จะไม่ตัดสินผ่าน/ไม่ผ่าน** แต่บอกว่าให้ถือเป็นข้อมูลประกอบ
  (เกณฑ์ตั้งไว้สำหรับเงื่อนไขเดียว จะเอาไปตัดสินเงื่อนไขอื่นไม่ได้)
- **ถ้าไม่ผ่านเกณฑ์ จะไม่บอกให้ไปแก้ค่าอะไรทันที** แต่เตือนก่อนว่ารอบที่ทำไม่สำเร็จหน้าตาในฐานข้อมูล
  เหมือนกันหมด ไม่ว่าจะเพราะ **อ่านไม่เข้าใจ / คิดไม่ออก / พิมพ์ไม่ทัน** ซึ่งแก้คนละทางโดยสิ้นเชิง
  แล้วค่อยแสดงว่าแต่ละสาเหตุแก้ที่ไหน

## 4. `PLAYTEST-PROTOCOL.md` — เก็บสิ่งที่ฐานข้อมูลเก็บไม่ได้

คู่มือสำหรับคนที่จะนั่งดูผู้ทดสอบเล่น มีหัวข้อสำคัญคือ **"สามอย่างที่ต้องแยกให้ออก"**:

| อาการที่เห็น | แปลว่า | ทางแก้ |
|---|---|---|
| ถามว่า "ให้ทำอะไร" | อ่านไม่เข้าใจ | คำอธิบายโจทย์ / ตัวอย่าง |
| เข้าใจแต่นั่งนิ่ง | คิดไม่ออก | hint / ลดความยากในกลุ่ม easy |
| รู้ว่าต้องเขียนอะไรแต่พิมพ์ไม่ทัน | พิมพ์ไม่ทัน | scaffold / `beginnerCharsPerMinute` |
| ทำได้แต่ยังแพ้บอท | บอทแข็งไป | `botSkillByDifficulty.easy` |

รวมถึงสิ่งที่ควรบอก/ไม่ควรบอกผู้ทดสอบ (เช่น **ห้ามใบ้ว่าไอเทม hint ทำอะไร** —
ถ้าไม่มีใครกดใช้เลย นั่นก็คือผลการทดสอบอย่างหนึ่ง), ตารางจดระหว่างเล่น, และคำถามหลังจบ 5 ข้อ

## 5. ทดสอบตัวเครื่องมือเอง

ผมไม่ได้แค่เขียนสคริปต์แล้วบอกว่าใช้ได้ — ขับแมตช์จริงผ่าน API สองแมตช์ที่มีผลต่างกันคนละแบบ
เพื่อดูว่ารายงานแสดงถูกทั้งสองทาง (**นี่คือการทดสอบเครื่องมือ ไม่ใช่การแทนผู้เริ่มต้น**)

| สถานการณ์ | ผลที่ได้ |
|---|---|
| ผ่านเกณฑ์ (solved 2/4, มี partial 1 รอบ) | `✅ PASS — solved 2/4, the bar is 2` แสดงครบ 4 รอบพร้อมแถบ 5/5, 2/5, 0/5 |
| ไม่ผ่านเกณฑ์ (solved 1/4) | `❌ BELOW BAR` พร้อมคำเตือนเรื่องสามสาเหตุและจุดที่ต้องไปแก้ |
| แมตช์เก่าที่ยังไม่มีข้อมูลระดับห้อง | `⚠️ treat the result as context, not a pass or fail` — ไม่ตัดสินมั่ว |
| รอบที่ผู้เล่นตกรอบก่อน | `— not reached` ไม่นับเป็นทำไม่ได้ |

**เจอปัญหาของตัวเองแล้วแก้**: ตอนแรกใช้ "โค้ดสั้นกว่า 60 ตัวอักษร = น่าจะยอมแพ้"
ซึ่ง**จับผิดทันทีในการรันครั้งแรก** — โค้ดที่ผู้เล่นพยายามเขียนจริง 5 บรรทัดกับ scaffold ที่ไม่ได้แตะ
ยาวพอๆ กัน (53 vs 51 ตัวอักษร) เปลี่ยนไปใช้สัญญาณที่แม่นจริง: **ถ้าโค้ดที่ส่งมายังมีคอมเมนต์ `# TODO` อยู่
แปลว่าไม่ได้แตะ scaffold เลย** ทดสอบซ้ำแล้วขึ้นเฉพาะรอบที่ส่ง scaffold เปล่า ไม่ขึ้นกับรอบที่พยายามจริง (3/5)

ลบข้อมูลสังเคราะห์ที่สร้างขึ้นเพื่อทดสอบรายงาน (ผู้ใช้สมมติ `playtestdemo` และ `playtestfail`

## 8. ขั้นต่อไป — ต้องมีคนทำ ไม่ใช่ผม

1. สร้างบัญชีให้ผู้ทดสอบ 1-2 คนที่เพิ่งเริ่มเรียน Python
2. ทำตาม `server/scripts/arcade-tests/PLAYTEST-PROTOCOL.md` (แมตช์ easy/Standard ก่อน แล้ว Quick)
3. รัน `npm run playtest:report -- <ชื่อผู้ใช้>`
4. เอาผลจากสคริปต์วางคู่กับตารางที่จดไว้ แล้วบันทึกลง `project_logs/`

**ถ้าไม่ผ่านเกณฑ์** ค่าที่ปรับได้อยู่ที่ `shared/arcadeConfig.json` จุดเดียว
(`beginnerCharsPerMinute` ทำให้สุ่มโจทย์สั้นลง, `botSkillByDifficulty.easy` ทำให้บอทอ่อนลง)
แต่ต้องรู้สาเหตุก่อนว่าแพ้เพราะอ่าน คิด หรือพิมพ์ — ปรับผิดจุดจะไม่ช่วยอะไรเลย
