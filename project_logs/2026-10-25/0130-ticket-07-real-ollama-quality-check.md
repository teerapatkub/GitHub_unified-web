## เลือกโมเดล: `scb10x/typhoon2.5-qwen3-4b`

| | Typhoon 2.5 (qwen3 4B) | Typhoon 2.1 (gemma3 4B) |
|---|---|---|
| โหลดบน Ollama 0.30.0 | ได้ | **ไม่ได้**: chat template parse ไม่ผ่าน (`selectattr: unknown test 'tool_calls'`) runner จบทันที |
| อยู่บน GPU | 68% (3.5 GB, Windows เหลือให้ ~3.2 GiB) | 20/35 layer ก่อนจะล้ม |
| ความเร็ว warm | ~13 token/วินาที | วัดไม่ได้ |

- **เหตุผล:** ตัวสำรองใช้กับ Ollama รุ่นนี้ไม่ได้ และต่อให้ใช้ได้ก็อยู่บน GPU น้อยกว่า
- **อยู่บน GPU ทั้งตัวไม่ได้ทั้งสองตัวบนเครื่องนี้** (checkbox แรกของ ticket ไม่ผ่าน) แต่ความเร็วที่ได้พอสำหรับทุกงานหลังแก้ Lumi
- `server/.env.production.local` (git ไม่ track): เพิ่ม `LLM_CHAT_MODEL`, `LLM_JUDGE_MODEL`, `LLM_ADVICE_MODEL` = Typhoon 2.5 และ `LLM_TIMEOUT_MS=45000`
  - ก่อนหน้านี้ไฟล์นี้ไม่มีชื่อโมเดลเลย ถ้า deploy ไปตามนั้น AI ทุกงานจะปิด
  - ไม่ได้อ่านหรือแสดงค่าอื่นในไฟล์

## ผลแต่ละงาน (Typhoon 2.5, warm)

### Lumi 10 คำถาม

| | ก่อนแก้ | หลังแก้ |
|---|---|---|
| ตอบได้ | 2/10 (อีก 8 ข้อ timeout ที่ 45 วินาที) | **10/10** |
| เวลา | 15–30 วินาทีเมื่อตอบได้ | **4.2–12 วินาที** |
| ภาษาไทย | ไทย | ไทยทุกข้อ (ปนชื่อฟังก์ชัน/โค้ด) |

- **สาเหตุ:** endpoint ส่ง `max_tokens: 2048` และไม่บอกความยาว โมเดลเขียนยาวเกิน 600 token ซึ่งที่ 13 token/วินาทีใช้เกิน 45 วินาที
- **แก้ (`server/server.js`):** `withLumiLengthRule` ต่อกฎ "สั้น ไม่เกิน 5 บรรทัด" เข้าไปใน system message ของหน้าเว็บ (หรือสร้างใหม่ถ้าไม่มี ให้มี system message เดียวเสมอ) และ `max_tokens` 400
- **เทส:** เพิ่ม subtest ใน `tests/local-llm-chat.test.js` (fail ก่อนแก้ด้วย `max_tokens 2048` ผ่านหลังแก้)
- **ความถูกต้อง:** อธิบายถูกทั้ง 10 ข้อ (for, list/tuple, input→int, IndentationError, range, dict, while/for, def/return, คู่/คี่ด้วย `%`, f-string) บางประโยคใช้คำแปลกๆ เช่น "สลับตัวแปรใส่ร่างกระดาษ" แต่ไม่ผิดสาระ

### สร้างโจทย์ฝึก 5 ข้อ (Debug Lab 3, Hard Challenge 2)

- **ผ่าน validate และเสิร์ฟให้ผู้เรียน: 1/5** ("Calculate Average Grade")
- ไม่ผ่าน 4 ข้อ ได้โจทย์ในระบบแทน:
  - เฉลยของโมเดลไม่ผ่าน test case ของตัวเอง 3 ข้อ (1/4, 0/4, 0/4)
  - Debug Lab ที่โค้ดตั้งต้นผ่านเทสอยู่แล้ว 1 ข้อ
- เวลา 20–35 วินาทีต่อข้อ (ต่ำกว่า timeout 45 วินาที)
- **ตัวตรวจทำงานตามที่ออกแบบ:** ไม่มีโจทย์ผิดหลุดถึงผู้เรียน แต่โจทย์ส่วนใหญ่ยังมาจากคลังในระบบ

### คำแนะนำ Competitive 3 ครั้ง (คำตอบที่ผิด 0/3)

| โจทย์ | เวลา | คำแนะนำ |
|---|---|---|
| Upper | 6.1 วินาที | ถูก: บอกให้ใช้ `.upper()` |
| Sum to N | 3.5 วินาที | ถูก: ลูปต้องเริ่มที่ 1 |
| Count Vowels | 4.5 วินาที | ถูก: นับทุกตัวอักษรแทนที่จะนับแค่สระ |

- ทั้ง 3 ครั้ง `aiReviewed: true` อยู่ในเวลา 12 วินาทีที่ตั้งไว้ คะแนน 48 ทุกครั้งจาก rubric

### คำแนะนำหลังแมตช์ Arcade 3 ครั้ง

| โจทย์ | เวลา | คำแนะนำ |
|---|---|---|
| Reverse String (คืน `s` เดิม) | 4.0 วินาที | ถูก: ชี้ว่าไม่ได้กลับด้าน |
| Sum of Array (ลูปซ้อน, `Total`) | 8.9 วินาที | ถูก: ใช้ findings ที่วัดได้ครบ (1.6 เท่า, ลูปซ้อน, snake_case) |
| Count Vowels (ยังเป็น TODO) | 6.1 วินาที | ถูก: บอกว่ายังไม่ได้เติมส่วนที่ต้องทำ |

- **ข้อสังเกต:** Reverse String ที่คืน `s` เดิม (ผิดทุกเทส) ได้คุณภาพ 100/100/100 จากการวัด เพราะการวัดดูรูปแบบโค้ด ไม่ได้ดูความถูกต้อง ซึ่งเป็นงานของ ADR 0007 ไม่ใช่ ticket นี้ (คะแนนรวมยังมาจากจำนวนเทสที่ผ่าน)
