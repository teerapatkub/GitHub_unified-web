# D10 — Arcade rematch

## งานที่ทำ

- แยกสถานะผู้เล่นที่ยังไม่เลือกอยู่ต่อออกจาก roster ของ lobby: ห้องยังเปิดรับคนใหม่ได้ แต่ผู้เล่นเดิมยังเห็นผลการแข่งขันและปุ่มตัดสินใจหลังอีกคนกดอยู่ต่อหรือรีเฟรชหน้า
- คืนสถานะและข้อมูลรางวัลของผู้เล่นที่ยังไม่เลือกผ่าน room API โดยไม่เพิ่มคนนั้นเข้าในจำนวนที่นั่งของ lobby
- ป้องกันการโอนหัวห้อง rematch ให้ผู้เล่นที่ยังไม่เลือกอยู่ต่อ
- เมื่อลูกค้าไม่ได้เป็นสมาชิกห้องอีกต่อไปหลังเริ่ม rematch ให้กลับออกจากห้อง แทนการค้างในหน้าการแข่งขัน
- เพิ่ม regression สำหรับห้องสองที่นั่ง การเปลี่ยนหัวห้อง การ retry ของ remain/leave/start และการรักษาผลเดิม

## ผลตรวจ

- `server`: `node --test tests/arcade-membership.test.js` ผ่าน 12/12 บน PostgreSQL ทดสอบแบบชั่วคราว
- `client`: `npm test` ผ่าน 19/19; `npm run build` ผ่าน; ESLint ของไฟล์ D10 ผ่าน
- `server`: `npm test` ผ่าน 134/135; จุดที่ล้มเป็น assertion เวลาเอฟเฟกต์ AOE ใน `tests/arcade-attacks.test.js:69` ซึ่งมีอยู่ก่อน D10 และรันทดสอบไฟล์นั้นเดี่ยวก็ยังล้ม
- Code review สองแกนไม่พบข้อบกพร่องใหม่ใน diff; แกน spec ระบุว่าการตรวจผ่าน browser จริงยังไม่ครบ

## สิ่งที่ยังต้องตรวจ

- Browser smoke test ของ rematch ระหว่าง refresh, เครือข่ายขัดข้อง และ viewport แคบยังไม่สำเร็จ การเริ่ม backend ที่ผูก Supabase จริงถูก auto-review ปฏิเสธ เพราะจะเปิด background worker กับฐานข้อมูลที่ใช้ร่วมกัน จึงไม่เปลี่ยนฐานจริงเพื่อทดสอบรอบนี้
- D11: Auth guard และ API client กลาง แยกจาก D10 ตามขอบเขตที่ตกลง
