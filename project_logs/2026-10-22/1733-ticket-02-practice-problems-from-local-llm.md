## สิ่งที่ทำ (`server/server.js`)

- **JSON mode:**
  - `generateLearningTaskWithAI` เรียก `callAiChat` ด้วย `json: true` (ส่ง `response_format: json_object`)
  - `callAiChat` ส่งตัวเลือกนี้ต่อไปที่ `ai/llm.js`
- **ตรวจโจทย์ที่โมเดลเขียนก่อนให้ผู้เรียน (`verifyGeneratedLearningTask`):**
  - prompt ทั้งสองแบบ (Debug Lab / Hard Challenge) ขอ `solutionCode` มาด้วย
  - โจทย์ต้องมีครบ: title, instructions, starterCode, solutionCode และ test case อย่างน้อย 3 ข้อ (เก็บแค่ 5 ข้อแรก)
  - เฉลยของโมเดลต้องผ่าน test case ของตัวเองทุกข้อ ตรวจผ่านตัวตรวจตัวเดียวของระบบ (`judgeLearnerSubmission` → `problemGrader`)
  - Debug Lab: โค้ดตั้งต้นต้อง**ไม่ผ่าน** ไม่อย่างนั้นจะไม่มีอะไรให้แก้ ใช้ `starterMustFail` บน config ของโหมด
  - ตัวอย่างบนหน้าจอต้องตรงกับ test case ข้อใดข้อหนึ่ง ถ้าไม่ตรงจะใช้ test case ข้อแรกแทน
  - เฉลยถูกทิ้งหลังตรวจ ไม่บันทึกลง `ai_payload` และไม่ส่งไปเบราว์เซอร์
  - ถ้าผิดข้อใดข้อหนึ่ง ใช้โจทย์สำรองทั้งข้อ
    - เดิม `normalizeGeneratedLearningTask` เอาส่วนที่ขาดมาเติมจากโจทย์สำรอง จึงเคยได้ชื่อโจทย์จาก AI แต่ test case เป็นของโจทย์ภาษี
- **`learningTaskProblem(testCases)`:** รูปแบบโจทย์ที่ใช้ตรวจ ใช้ร่วมกันทั้งตอนตรวจโจทย์ที่สร้างและตอนผู้เรียนส่งคำตอบ (`/api/learning/ai-task/submit`)
- **prompt:** เพิ่มกฎว่า expected ต้องเป็นสิ่งที่ solutionCode พิมพ์ออกมาจริง

## เทส (`tests/local-llm-practice-tasks.test.js`, เพิ่มใน `npm test`)

- บูต server จริงกับ Ollama ปลอม แล้วยิง `GET /api/learning/ai-task`
- ปิดคลังโจทย์ในฐานชั่วคราว เพราะปกติระบบเลือกโจทย์จากคลังก่อน
- มี 9 กรณี:

  | กรณี | ผลที่ต้องได้ |
  |---|---|
  | โจทย์ถูกต้อง | ได้โจทย์จากโมเดล, เก็บ test case ตรงกัน, ไม่มีเฉลยในฐาน, ส่ง JSON mode และใช้ชื่อโมเดลที่ตั้งไว้ |
  | ไม่ใช่ JSON | ได้โจทย์สำรอง |
  | JSON ไม่มี test case | ได้โจทย์สำรองทั้งข้อ ไม่ปนกัน |
  | เฉลยไม่ผ่าน test case ของตัวเอง | ได้โจทย์สำรอง |
  | Debug Lab ที่โค้ดตั้งต้นผ่านอยู่แล้ว | ได้โจทย์สำรอง |
  | โมเดลช้าเกิน timeout | ได้โจทย์สำรอง |
  | Hard Challenge ที่เริ่มจากคอมเมนต์ | ได้โจทย์จากโมเดล |
  | ตัวอย่างไม่ตรง test case | ใช้ test case ข้อแรกเป็นตัวอย่าง |
  | test case 7 ข้อ | ตัดเหลือ 5 ข้อ |

- อีกกรณีบูตแยก: ไม่ตั้ง `LLM_BASE_URL` แล้วได้โจทย์สำรอง และไม่มี request ไปที่โมเดลเลย
- เทสใหม่ fail กับโค้ดเดิมก่อนแก้ 5 กรณี

## ผลกระทบ

- **ผู้เรียน:** โจทย์ที่ AI สร้างจะถึงมือก็ต่อเมื่อรันผ่านจริงแล้ว ถ้าโมเดลเล็กเขียนผิดบ่อย จะเห็นโจทย์สำรองบ่อยขึ้น
- **เวลาตอบ:** การสร้างโจทย์ช้าขึ้นราว 1–2 วินาที เพราะต้องรัน Python ตรวจเฉลยและโค้ดตั้งต้น
- **ขอบเขตการใช้งาน:** ระบบยังเลือกโจทย์จากคลังก่อนเสมอ โมเดลถูกเรียกเฉพาะเมื่อคลังหมด
- schema, บอท และ Arcade ไม่ถูกแตะ
