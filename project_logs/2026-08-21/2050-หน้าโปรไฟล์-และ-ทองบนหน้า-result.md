## 1. หน้า RESULT ของ Arcade โชว์ทองที่ได้ (ค้างจากรอบก่อน)

**ปัญหาเดิม**: ทองเข้ากระเป๋าจริงตั้งแต่รอบก่อน แต่ผู้เล่นไม่เห็นตอนจบแมตช์เลย

**ทำ**: เพิ่ม `arcade_participants.coins_awarded` เขียนตอนแมตช์ถึง RESULT
(หลังอัปเดตกระเป๋าสำเร็จเท่านั้น — จ่ายไม่สำเร็จจะไม่ขึ้นเหมือนจ่ายแล้ว)
`GET /rooms/:id` ใช้ `SELECT *` อยู่แล้ว ค่าจึงไหลไปถึง client เอง
หน้า RESULT อ่านจากแถวของตัวเองแล้วแสดงการ์ด "ทองที่ได้รับ"

**ที่ตั้งใจ**: แสดงตัวเลขที่**เขียนไว้จริง** ไม่ใช่คำนวณตารางรางวัลซ้ำฝั่ง client
ถ้าคำนวณเองแล้ววันหลังแก้ config ตัวเลขบนจอกับในกระเป๋าจะไม่ตรงกันโดยไม่มีใครรู้
ผู้เล่นที่ไม่มีบัญชี (guest) ได้ 0 พร้อมข้อความอธิบาย ไม่ใช่ 0 เฉยๆ

**เพิ่มคำแปล**: `coinsEarnedTitle`, `coinsEarnedHint`, `coinsUnit`, `coinsNoneHint` ทั้ง en/th

## 2. หน้าโปรไฟล์ผู้ใช้ (ใหม่)

`GET /api/profile/:userId` — รวมทุกอย่างในคำขอเดียว เพื่อให้ตัวเลขทุกตัวบนจอมาจากช่วงเวลาเดียวกัน
(ถ้าให้หน้าเว็บยิงหกคำขอ ตัวเลขจะมาจากคนละจังหวะ)

หน้าเว็บอยู่ที่ `/profile` (ของตัวเอง) และ `/profile/:userId` (ของคนอื่น)
เข้าได้จากการคลิกรูปโปรไฟล์มุมขวาบน

**สิ่งที่แสดง**:
| ส่วน | ข้อมูล |
|---|---|
| ตัวตน | รูปโปรไฟล์พร้อมกรอบที่สวมอยู่, ชื่อ, **ระดับความสามารถ** (ผู้เริ่มต้น/ระดับกลาง/ระดับสูง), สมาชิกตั้งแต่ |
| เลเวล | เลเวล, แถบ XP ในเลเวลนั้น, XP สะสม, ทอง, สตรีคต่อเนื่อง |
| ตัวเลขสรุป | บทเรียนที่จบ, แบบฝึกหัดที่ผ่าน, จำนวนแมตช์ Arcade, อัตราการชนะ |
| กำลังเรียน | บทที่กำลังเรียน + % + คะแนนก่อน/หลังเรียน + แบบฝึกหัด พร้อมปุ่มเรียนต่อ |
| ตามหมวด | 9 โมดูล แต่ละอันมีแถบ % และจำนวนบทที่จบ |
| Arcade | เล่นกี่แมตช์ ชนะ/แพ้ อัตราชนะ อันดับดีที่สุด คะแนนสะสม + **ตารางประวัติ 10 แมตช์ล่าสุด** |
| บทเรียนทั้งหมด | 24 บท พร้อมสถานะ/% (ซ่อนบทที่ยังไม่เริ่มได้) |
| ความสำเร็จ | 20 อย่าง แยกปลดล็อกแล้ว/ยังล็อก |

**วิธีวัด % ของบทเรียน** — schema ไม่มีการติดตามรายสไลด์ จึงวัดจากสิ่งที่บทเรียนมีจริง:
แบบทดสอบก่อนเรียน + หลังเรียน + แบบฝึกหัดของบทนั้น
`% = ขั้นที่ทำแล้ว / ขั้นทั้งหมด` โดยหลังเรียนนับว่าผ่านที่เกณฑ์ 60% เดียวกับที่หน้าบทเรียนบังคับ
"กำลังเรียนบทไหน" = บทที่แตะล่าสุดและยังไม่จบ ถ้าไม่มีก็บทแรกที่ยังไม่เริ่ม — ไม่ได้เดา

**ระดับความสามารถ** ใช้ `normalizePlayerLevel` ที่มีอยู่แล้วในโปรเจค (เลเวล ≤1 / 2 / ≥3) ไม่ได้ตั้งเกณฑ์ใหม่ซ้อน

## 3. เจอข้อมูลเสียหายเพิ่ม — และซ่อมได้

พอหน้าโปรไฟล์แสดงความสำเร็จ ก็เห็นทันทีว่า **คำอธิบายทั้ง 20 อันเป็นอักษร `?` ล้วน**

เป็น encoding ที่พังมาก่อน (แบบเดียวกับเนื้อหาบทเรียนที่เจอตอน merge) แต่รอบนั้น**ผมสแกนไม่เจอ
เพราะเดาชื่อคอลัมน์ผิด** — ไปเช็ค `achievements.title` ซึ่งไม่มีอยู่จริง คอลัมน์จริงคือ `description`
คำสั่งนั้น error แล้วผมปล่อยผ่านไป

คราวนี้เขียนสคริปต์สแกน**ทุกคอลัมน์ข้อความใน public** แทนที่จะเดารายชื่อ พบพัง 10 คอลัมน์ใน 6 ตาราง

**ก่อนซ่อม พิสูจน์ก่อนว่า id สองฝั่งตรงกันจริง**: ใน `advanced_validation` มี 7 แถวที่ `correct_answer`
ยังอ่านออก เทียบกับต้นฉบับแล้วตรงกันทุกแถว และ 3 แถวที่พังคือแถวที่คำตอบเป็นภาษาไทยพอดี
→ ยืนยันได้ว่าเขียนทับตาม id ได้ปลอดภัย

**ซ่อม 61 ค่า** จากสำเนาต้นฉบับที่ยัง stage อยู่ในฐาน `p1_import` (สำรองก่อนซ่อม)

| ตาราง | ผล |
|---|---|
| `achievements.description` | ซ่อมครบ 20/20 |
| `advanced_validation` (question_text, correct_answer) | ซ่อมครบ |
| `advanced_validation_choices.choice_text` | ซ่อมครบ |
| `survey_questions` / `survey_options` (id 1-2, 1-7) | ซ่อมครบเท่าที่มีต้นฉบับ |

**ที่ตั้งใจไม่ซ่อม**: `learning_ai_tasks` (1 แถว) — เป็นโจทย์ที่ AI สร้างรายบุคคล
id เดียวกันในสองฐานคือโจทย์คนละอันของคนละคน เขียนทับตาม id จะได้ข้อมูลผิดคน

**ที่ซ่อมไม่ได้ (ไม่มีต้นฉบับ)**: `survey_questions` id 1001-1003 กับ options ของมัน
ตรวจแล้วเป็น**ฉบับซ้ำที่พัง**ของคำถาม 1-2 ที่ซ่อมไปแล้ว (id ขึ้นต้น 1001 แบบเดียวกับ `modules`
ที่เจอตอน merge) และ**ไม่มีใครตอบสักคน** (0 responses) — ไม่ลบเพราะเป็นการลบข้อมูล ยังไม่ได้ขอ
