# เซ็ตเครื่องแต่งตัวในร้านค้า — ธีมอวกาศ และ ธีมซากุระ

**วันที่**: 2026-08-21 เวลา 19:30
**ผู้ทำ**: Person 3
**ที่มา**: ผู้ใช้สั่งสร้างของในร้านค้าเป็นเซ็ตธีมเดียวกัน 2 เซ็ต (อวกาศ / ซากุระ)
แต่ละเซ็ตมีธีมเว็บ กรอบโปรไฟล์ และเคอร์เซอร์เมาส์ พร้อมกำหนดราคาที่ซื้อยกเซ็ตถูกกว่าซื้อแยก

---

## 1. ตรวจก่อนสร้าง — เจอสองอย่างที่ทำให้ "ซื้อไปก็ไม่เห็นอะไร"

ก่อนสร้างของ ไล่ดูว่าเครื่องแต่งตัวแต่ละชนิดแสดงผลยังไง แล้วพบว่า:

**1.1 `/api/user/profile/:userId` ไม่ส่งข้อมูลเครื่องแต่งตัวกลับมาเลย**
เวอร์ชันที่เราเก็บไว้ตอน merge SELECT แค่ `user_id, username, email, role, level, xp, virtual_currency`
แต่ `ThemeContext` ต้องการ `equipped_theme_id` + `theme_asset_url` และ `MouseEffectLayer`
ต้องการ `mouse_effect_data` → **ซื้อธีมแล้วสวม พอรีเฟรชหน้าก็หายหมด**
เป็นหนึ่งใน 10 endpoint ที่บันทึกไว้เมื่อรอบก่อนว่ายังเป็นเวอร์ชันเก่า — ดึงของ Person 1 มาแทน
(ตรวจ helper ที่มันเรียกครบก่อนย้าย ไม่ให้ซ้ำรอย `insertLedgerEntry`)

**1.2 กรอบโปรไฟล์ไม่มีที่วาด และที่วาดอยู่ก็วาดผิด**
`grep` ทั้งโปรเจคแล้วไม่มีที่ไหนแสดงกรอบเลย — แต่พอไล่ดู `App.jsx` พบว่าแถบผู้ใช้มุมขวาบน
เอา `profile_asset_url` (ซึ่งคือรูป**กรอบ**) มาแสดงเป็น**รูปโปรไฟล์**เสียเอง
แปลว่าสวมกรอบแล้วกรอบจะไปแทนที่ตัวผู้เล่น ไม่ใช่ล้อมรอบ
แก้เป็น: วงกลมอวตาร์ (ตัวอักษรแรกของชื่อ) อยู่ตรงกลาง แล้ววางรูปกรอบทับด้านบน
(กลางกรอบทุกอันโปร่งใสอยู่แล้ว) — ตอนนี้กรอบโผล่ทุกหน้าที่มีแถบผู้ใช้

## 2. ของที่สร้าง

ภาพพื้นหลังธีมมีอยู่แล้วใน `server/uploads/` ทั้งสองอัน (เช็คด้วยตาแล้วว่าตรงชื่อจริง) —
`space-theme.png` เป็นอวกาศพาสเทลมีดาวเคราะห์ และไฟล์ซากุระเป็นภาพสีน้ำดอกซากุระ
ที่ต้องทำใหม่คือ**กรอบโปรไฟล์** เขียนเป็น SVG (คมทุกขนาด ไฟล์เล็ก ตรงกลางโปร่งใส):
`frame-space.svg` (วงโคจรไล่สีม่วง-ฟ้า + ดาวเคราะห์ + ดาว) และ
`frame-sakura.svg` (วงชมพู + ดอกซากุระ 5 ดอก + กิ่งไม้)
ทดสอบด้วยการวางทับอวตาร์จริงที่ขนาด 140px และ 200px ก่อนใช้

| เซ็ต | ธีมเว็บ | กรอบโปรไฟล์ | เคอร์เซอร์ | รวมแยกชิ้น | **ราคาเซ็ต** |
|---|---|---|---|---|---|
| อวกาศ | ธีมอวกาศ 120 | กรอบดาวเคราะห์ 80 | ฝุ่นดาว ✨/🪐 60 | 260 | **200** |
| ซากุระ | ธีมซากุระ 120 | กรอบกลีบซากุระ 80 | กลีบซากุระปลิว 🌸 60 | 260 | **200** |

**เหตุผลของราคา**: อิงจากที่เกมจ่ายจริง — ชนะ Arcade หนึ่งแมตช์ได้ 50 เหรียญ
แบบฝึกหัดบทเรียนละ 5-10 → เซ็ตเต็มประมาณชนะ 4 แมตช์ ประหยัด 60 เหรียญ (23%)

**โชคดีที่ palette รองรับอยู่แล้ว**: `ThemeContext` เลือกโทนสีจาก*ชื่อ*ธีม — มีเคส `space`
(ม่วง `#7c3aed`) และค่า default เป็นชมพู `#ec4899` ซึ่งเป็นโทนซากุระพอดี ไม่ต้องแตะ palette เลย

**ธีมซากุระใช้ของเดิม ไม่สร้างซ้ำ**: มี THEME ซากุระอยู่แล้ว (item 13) ที่ผู้ใช้จริง 2 คนซื้อไป
และ 1 คนสวมอยู่ → seed จึง**รับ item เดิมเข้าเซ็ต** แทนที่จะสร้างธีมซากุระอันที่สองแล้วทิ้งของเขาไว้เฉยๆ

**ของทดสอบเก่า 6 ชิ้น** (ชื่อ `asd`, `rtt`, `?nasd` และ URL ชี้ไป `localhost:5000` ที่ไม่มีแล้ว)
ตั้ง `is_active = 0` ให้หายจากร้าน — **ไม่ลบ** เพื่อไม่ให้อะไรที่อ้างถึงพัง

## 3. กลไกเซ็ต

Schema เพิ่มผ่าน `server/db.js` ตามกฎโปรเจค:
- `shop_items.set_key` — บอกว่าชิ้นนี้อยู่เซ็ตไหน
- ตาราง `shop_sets` — ราคายกเซ็ต เก็บเป็นตัวเลขจริง ไม่ให้ client คำนวณส่วนลดเอง

Endpoint ใหม่:
- `GET /shop/sets?userId=` — คืนเซ็ตพร้อมของข้างใน ราคารวมแบบแยก ราคาเซ็ต ส่วนที่ประหยัด
  และ**ราคาที่ผู้เล่นคนนี้ต้องจ่ายจริง**
- `POST /shop/buy-set` — ซื้อเฉพาะชิ้นที่ยังไม่มี ในอัตราเซ็ต

**กรณีมีของบางชิ้นอยู่แล้ว**: ไม่คิดราคาเต็มเซ็ต และไม่คิดซ้ำของที่มี — คิดราคาเซ็ต
ตามสัดส่วนของที่ยังขาด เช่น มีธีม (120 จาก 260) อยู่แล้ว จะจ่าย `ceil(200 × 140/260) = 108`
ซึ่งยังถูกกว่าซื้อสองชิ้นที่เหลือแยก (140) — ส่วนลดไม่หายไปเพราะเผลอซื้อชิ้นเดียวไปก่อน

UI: เพิ่มส่วน "เซ็ตธีม" เหนือรายการสินค้าใน `ShopPage` แสดงของ 3 ชิ้น ป้าย "มีแล้ว"
ราคาแยกชิ้นขีดฆ่า ราคาเซ็ต และปุ่มซื้อ (เปลี่ยนเป็น "มีครบแล้ว" เมื่อครบ)

## 4. บั๊กที่เจอตอนทดสอบจริง — `jsonb` ถูก parse ซ้ำ

สวมเคอร์เซอร์แล้ว `mouse_effect_data` กลับมาเป็น `[]` ทุกครั้ง ทั้งที่ในตารางมีข้อมูลครบ

สาเหตุ: `db.js` ของเราคืนคอลัมน์ `jsonb` มาเป็น **object ที่ decode แล้ว** ส่วน mysql2 คืนเป็น
string โค้ดที่ย้ายมาจากฝั่ง MySQL จึง `JSON.parse` ทับ → `JSON.parse(array)` แปลง array เป็น
`"[object Object]"` → throw → `catch` คืน `[]` **เงียบสนิท ไม่มี error ให้เห็น**

แก้ที่ `safeJsonParse` ให้ปล่อยผ่านค่าที่ไม่ใช่ string และเปลี่ยนจุดที่ parse ตรงๆ มาใช้มัน
ไล่ตรวจคอลัมน์ `jsonb` ทั้ง 7 คอลัมน์ในฐานข้อมูลแล้วว่าไม่มีจุดอื่นที่พลาดแบบเดียวกัน
(`lesson_quiz_attempts.answers_json` เป็น `text` ไม่ใช่ jsonb จึงไม่กระทบ)

อีกจุดเล็ก: `/shop/items` ไม่ได้ SELECT `rarity` ทำให้การ์ดทุกใบขึ้น COMMON ทั้งที่ตั้งเป็น RARE
