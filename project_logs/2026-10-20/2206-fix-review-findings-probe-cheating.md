# แก้ข้อที่ code review ของ b4850db พบ: โกงตัววัดได้, false positive, fallback, ป้ายคำแนะนำ

**วันที่:** 2026-10-20 22:06 (Asia/Bangkok) — Person 3 (Arcade)
**อ้างอิง:** ADR 0007 (เพิ่มหัวข้อ "กันการโกงตัววัด")

## เหตุผล

ผู้ใช้สั่ง `/code-review` พร้อมให้เล่นทดสอบระดับปานกลาง 1 แมตช์และระดับยาก 1 แมตช์ รีวิวทั้งสองด้าน (Standards และ Spec) และการเล่นจริงพบปัญหาดังนี้:

1. **โกงคะแนนเวลาได้**
   - `sys.settrace(None)` หรือ `import __main__; __main__.steps = ...` ทำให้คำตอบช้าได้คะแนนเวลาเต็ม
   - ลองกับโจทย์ FizzBuzz (task 13): คำตอบเดียวกัน ถ้าตรงไปตรงมาได้คุณภาพ 57 ถ้าโกงได้ 90
   - การ print บรรทัดผลปลอมก็ทำได้ ถ้ารู้ marker
2. **false positive:** `for x in sorted(...)` ถูกหักว่าเรียก `sorted()` ซ้ำในลูป ทั้งที่ตัวที่ loop วนจะคำนวณแค่ครั้งเดียว
   - ยืนยันกับคำตอบที่ส่งในรอบ 3 ของแมตช์ระดับปานกลาง (task 31) ซึ่งเสีย 10 คะแนนประสิทธิภาพ
   - comprehension ซ้อน 2 ชั้นถูกนับเป็นชั้นเดียว
3. **ทางสำรองไม่เคยถูกใช้:**
   - ถ้า Python ใช้ไม่ได้ คำตอบได้ 0 แล้วถูก cache ไว้ แทนที่จะใช้คะแนนแบบง่าย
   - ถ้าเฉลยวัดไม่สำเร็จครั้งหนึ่ง ผลนั้นจะค้างใน cache จนกว่าจะ restart
4. **ป้ายคำแนะนำผิด:** แถวเก่าที่เป็น `flagged` ถูกติดป้าย "คำแนะนำจาก Lumi (AI)" ทั้งที่เป็นข้อความตายตัว
   - endpoint ตอบ 403 เมื่อไม่ใช่เจ้าของ ซึ่งบอกได้ว่ามี id นั้นอยู่

## สิ่งที่แก้

- **`server/arcade/quality-probe.py`**
  - **ตรวจก่อนรัน:** ถ้าโค้ดอ้างถึงกลไกของตัววัด (`settrace`, `__main__`, `_getframe`, `gc`, `inspect`, `builtins`, `__closure__`, `_exit`, `modules` ฯลฯ) จะไม่รันโค้ดนั้น
  - **ตรวจระหว่างรัน:** หลังรันแต่ละเทส ตรวจ `sys.gettrace()` เพื่อจับการปิด tracer แบบซ่อนชื่อ เช่น `getattr(sys, 'set' + 'trace')`
