## ปัญหาที่ต้องแก้
หลังแก้บั๊ก auto-submit รอบก่อน ระบบจะส่งคำตอบให้อัตโนมัติเมื่อเหลือ 8 วินาที (`autoSubmitLeadSeconds`) ซึ่งดีกว่าเดิมที่ได้ 0 คะแนน **แต่ผู้เล่นจะถูกล็อกไม่ให้แก้โค้ดต่อเร็วกว่าที่คาดคิด 8 วินาทีโดยไม่มีการเตือนใดๆ** — ยืนยันจากการทดสอบขั้นที่ 1 ว่าเกิดขึ้นจริง

## สิ่งที่ทำ

### ค่าคอนฟิกใหม่
เพิ่ม `autoSubmitWarnSeconds: 16` ใน `shared/arcadeConfig.json` พร้อมคอมเมนต์ระบุชัดว่า **ต้องมากกว่า `autoSubmitLeadSeconds` เสมอ** — การเตือนตอนที่ระบบกำลังส่งพอดีไม่ถือเป็นการเตือน ช่องว่าง 8 วินาทีระหว่างสองค่านี้คือเวลาที่ผู้เล่นมีไว้ตัดสินใจกดส่งเอง
export ต่อเป็น `AUTO_SUBMIT_WARN_SECONDS` ใน `constants.js`

### ข้อความ 2 สถานะ (TH/EN)
- `autoSubmitWarning` — "อีก {{n}} วินาทีระบบจะส่งคำตอบให้อัตโนมัติ — ถ้ายังไม่เสร็จให้กดส่งคำตอบเองตอนนี้" (นับถอยหลังจริงจากส่วนต่าง `timeLeft − lead`)
- `autoSubmitFiring` — "หมดเวลา — ระบบกำลังส่งคำตอบให้อัตโนมัติ…"

### แบนเนอร์ใน `BattleRoyaleGameplayView.jsx`
วางใต้การ์ดโจทย์ เหนือ editor แสดง 2 สถานะ:
- **16s → 9s**: พื้นเหลืองอำพัน กระพริบ (`animate-pulse`) นับถอยหลังบอกว่าเหลืออีกกี่วินาทีจะถูกส่งอัตโนมัติ
- **≤ 8s (ระหว่างกำลังตรวจ)**: พื้นแดงกุหลาบ บอกว่ากำลังส่งให้แล้ว
ซ่อนทั้งหมดถ้าผู้เล่นส่งคำตอบเองไปแล้ว หรือตกรอบไปแล้ว

## บั๊กที่เจอในโค้ดของตัวเองระหว่างทดสอบ (แก้แล้ว)
เวอร์ชันแรกครอบเงื่อนไขทั้งก้อนด้วย `!playerState.hasSubmittedThisRound` ผลคือ:
- แบนเนอร์เหลืองขึ้นถูกต้องช่วง 16s → 9s
- แต่พอถึงวินาทีที่ 8 **แบนเนอร์หายไปเฉยๆ ไม่แสดงข้อความ "กำลังส่งให้อัตโนมัติ" เลย**

สาเหตุ: `submitMyRound()` ตั้ง `hasSubmittedThisRound = true` ทันทีที่เริ่มทำงาน (แบบ synchronous) ดังนั้นวินาทีที่ auto-submit ยิง เงื่อนไขก็เป็นเท็จทันที แบนเนอร์จึงถูกซ่อนพร้อมกัน

**จับได้จากการทดสอบบนหน้าจอจริง ไม่ใช่จากการอ่านโค้ด** — ร่องรอยที่บันทึกได้:
```
ROUND 2 13s warn=1 fire=0
ROUND 2 12s warn=1 fire=0
ROUND 2 11s warn=1 fire=0
ROUND 2 10s warn=1 fire=0
ROUND 2  9s warn=1 fire=0
ROUND 2  8s warn=0 fire=0   <-- ควรเป็น fire=1 แต่หายไปทั้งคู่
ROUND 2  7s warn=0 fire=0
```

**วิธีแก้**: แยกเงื่อนไขสองสถานะออกจากกันชัดเจน โดยสถานะ "กำลังส่ง" ตรวจจาก `isGrading && timeLeft <= lead` **ไม่พึ่ง `hasSubmittedThisRound` เลย** ส่วนสถานะเตือนล่วงหน้าใช้ `!hasSubmittedThisRound && timeLeft <= warn && timeLeft > lead`
การจับคู่ `isGrading` กับช่วง lead ยังช่วยแยกแยะได้ด้วยว่าเป็นการส่งอัตโนมัติ ไม่ใช่ผู้เล่นกดส่งเองตั้งแต่ต้นรอบ (ซึ่งไม่ต้องขึ้นแบนเนอร์)

## การทดสอบ — ผ่านทั้ง 2 สถานะ (บนหน้าจอจริง)

ใช้วิธีเดิมจากขั้นที่ 1: ฝัง `setInterval` ในหน้าเว็บบันทึกสถานะทุก 400ms แล้วอ่านย้อนหลัง (ทนต่อการที่ Chrome throttle แท็บ)

| สถานะ | ผล |
|---|---|
| แบนเนอร์เหลืองขึ้นตอน countdown = 16 พอดี | PASS — ข้อความที่อ่านได้จริง: **"อีก 8 วินาทีระบบจะส่งคำตอบให้อัตโนมัติ — ถ้ายังไม่เสร็จให้กดส่งคำตอบเองตอนนี้"** (16 − 8 = 8 ถูกต้อง แปลว่าการแทนค่า `{{n}}` ทำงาน) |
| ไม่ขึ้นก่อนถึงเวลา | PASS — ที่ countdown 27s และ 25s ยังไม่ขึ้น |
| แบนเนอร์เหลืองอยู่ต่อเนื่องช่วง 16s → 9s | PASS (ร่องรอย warn=1 ตลอดช่วง) |
| แบนเนอร์แดง "กำลังส่งคำตอบให้อัตโนมัติ" ตอน ≤ 8s | PASS — ยืนยันด้วย screenshot: แบนเนอร์แดงขึ้นพร้อมปุ่มส่งคำตอบเปลี่ยนเป็น "กำลังตรวจโค้ด..." |
| auto-submit ยังทำงานถูกต้องหลังแก้ | PASS — toast แสดงผลตรวจ "0/3 tests \| 0/100 \| 51s" ในรอบที่ไม่ได้กดส่งเอง |
