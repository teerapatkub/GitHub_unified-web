## กติกาสำคัญของฟีเจอร์นี้: ปิดแชทระหว่างรอบเขียนโค้ด

ทุกคนในห้องแก้โจทย์**ข้อเดียวกันพร้อมกัน** ดังนั้นถ้าเปิดช่องแชทระหว่างรอบ มันคือช่องแจกเฉลย ไม่ใช่ช่องคุยเล่น
บังคับกติกานี้**ที่ endpoint ฝั่งเซิร์ฟเวอร์** ไม่ใช่แค่ซ่อนช่องพิมพ์ฝั่ง client — เพราะการซ่อนปุ่มไม่ใช่การบังคับกติกา ใครก็ยิง API ตรงได้
ช่วงที่คุยได้: ล็อบบี้, สรุปผลรอบ, ช่วงพักซื้อไอเทม

## สิ่งที่ทำ

### ตารางใหม่ `arcade_chat_messages` (`server/db.js`)
- คอลัมน์: `room_id`, `user_name`, `kind` ('text' | 'emoji'), `message` VARCHAR(300), `emoji` VARCHAR(16), `created_at`
- ใช้ตารางเดียวเก็บทั้งข้อความและอีโมจิ โดย `kind` เป็นตัวบอก ส่วนคอลัมน์ที่ไม่ใช้เป็น NULL
- `ON DELETE CASCADE` ตามห้อง เหมือนตารางระดับแมตช์อื่นๆ
- เพิ่ม index `(room_id, id)` เพราะ client ดึงแบบ "เอาเฉพาะที่ใหม่กว่า id ล่าสุดที่ฉันมี"

### Endpoint (`server/server.js`)
- `POST /rooms/:id/chat` — ตรวจตามลำดับ: ห้องมีจริง → **ไม่ใช่ ROUND_ phase** → ผู้ส่งอยู่ในห้องจริง → อีโมจิอยู่ใน whitelist / ข้อความผ่าน `sanitizeName` → ไม่ส่งถี่เกิน 700ms
- `GET /rooms/:id/chat?since=<id>` — ดึงเฉพาะข้อความใหม่ (LIMIT 100) พร้อมส่ง `emojiSet` กลับไปให้ client ใช้เป็นชุดปุ่ม

**การตัดสินใจด้านความปลอดภัย** (ตาม `CLAUDE.md` ที่สั่งให้ validate ทุกจุดที่รับ input ผู้เล่น):
- อีโมจิใช้ **whitelist 8 ตัว** ไม่ใช่รับ string อะไรก็ได้ — เพราะถ้ารับอิสระ ช่อง `emoji` จะกลายเป็นช่องข้อความอิสระที่เลี่ยงทั้งกติกาปิดแชทตอนรอบแข่งและเลี่ยงลิมิตความยาว
- ข้อความผ่าน `sanitizeName()` ตัวเดิมที่ใช้กับชื่อห้อง/ชื่อผู้เล่น (ตัดอักขระควบคุม + จำกัดความยาว)
- เช็คว่าผู้ส่ง**อยู่ในห้องจริง** ไม่งั้นใครรู้ room_id ก็โพสต์เข้าแมตช์ที่ตัวเองไม่ได้เล่นได้
- rate limit 700ms/ข้อความ/คน กันคนเดียวถล่มประวัติห้องและ payload ของคนอื่น
- ทุก query ใช้ `?` placeholder ตามกฎ ไม่มี string concatenation

### ฝั่ง client
- `hooks/useChat.js` (ใหม่) — poll ทุก 2 วินาที **ผูกกับ `roomId` ที่เป็น primitive** ไม่ใช่ object `currentRoom` (บทเรียนจากบั๊ก render loop) ดึงแบบ incremental ด้วย `since` และล้างประวัติเมื่อย้ายห้อง
- `widgets/ChatPanel.jsx` (ใหม่) — รายการข้อความ (เลื่อนตามอัตโนมัติ **เฉพาะตอนผู้อ่านอยู่ล่างสุดอยู่แล้ว** จะได้ไม่กระชากจอตอนคนกำลังเลื่อนอ่านย้อนหลัง), แถวปุ่มอีโมจิ, ช่องพิมพ์
- แสดงผลใน 2 จุด: ล็อบบี้ในห้อง และช่วงพักซื้อไอเทม
- เพิ่ม 6 คีย์แปล TH/EN

## ข้อจำกัดที่ต้องบันทึกให้ตรงความจริง
สถานะ "ปิดแชทระหว่างรอบเขียนโค้ด" (`chatLockedDuringRound`) ที่เขียนไว้ใน `ChatPanel.jsx` **ยังไม่มีทางแสดงบนหน้าจอจริงในตอนนี้** เพราะแผงแชทไม่ได้ถูก render ในหน้าจอรอบเขียนโค้ดเลย (ตามเจตนาว่าไม่ให้มีอะไรมากวนตอนเขียนโค้ด)
เก็บโค้ดส่วนนั้นไว้เป็น **safety net เชิงป้องกัน**: ถ้าอนาคตมีใครเอาแผงแชทไปวางในหน้าจอรอบแข่ง มันจะล็อกตัวเองถูกต้องแทนที่จะเปิดให้พิมพ์ — และตัวแปร `chatOpen` ก็สะท้อนกติกาฝั่งเซิร์ฟเวอร์ตรงกัน
**กติกาที่บังคับจริงคือฝั่งเซิร์ฟเวอร์** ซึ่งทดสอบแล้วว่าปฏิเสธจริง (ข้อ 11-12 ด้านบน)
