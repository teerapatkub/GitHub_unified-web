## บั๊กที่พบระหว่างทดสอบ (แก้แล้วทั้งคู่)

### 1. ห้องระดับ "ยาก" จะเจอโจทย์ซ้ำในรอบสุดท้าย
รอบ 1-3 ของห้อง hard ใช้โจทย์ hard[0..2] แต่รอบ 4 ก็ใช้ hard[0] มาตลอด → **รอบชิงชนะเลิศกลายเป็นโจทย์เดียวกับรอบ 1**
แก้: ถ้าห้องเป็นระดับ hard ให้รอบ 4 ขยับไปใช้ hard[3] (ทั้งฝั่ง client และการนับ test case ฝั่งเซิร์ฟเวอร์) ตรวจแล้วว่าโจทย์ทั้ง 4 รอบไม่ซ้ำกัน:
```
round 1: task_id=21  Maximum Subarray Sum
round 2: task_id=22  Longest Substring Without Repeating
round 3: task_id=23  LRU Cache Simulator
round 4: task_id=24  Trapping Rain Water     <-- เดิมจะเป็น 21 ซ้ำรอบ 1
```
ห้องที่ไม่ใช่ระดับ hard รอบ 4 ยังใช้ hard[0] เหมือนเดิม

### 2. โจทย์กับโค้ดตั้งต้นไม่ตรงกัน (stale closure)
เห็นกับตาบนหน้าจอ: ห้องระดับ "ปานกลาง" แสดงหัวข้อ **"1. ตรวจสอบแอนนาแกรม (Anagram Checker)"** ถูกต้อง แต่ในเอดิเตอร์กลับเป็น **`def fib(n):`** ของโจทย์รอบ 1 แบบดั้งเดิม

สาเหตุ: room-state poller มี dependency array แคบโดยตั้งใจ (เพื่อไม่ให้ re-subscribe ทุก render — บทเรียนจากบั๊ก request loop) ผลข้างเคียงคือฟังก์ชันที่มันปิดทับ (closure) ถูกจับไว้ตั้งแต่ตอน mount ซึ่งตอนนั้น `dbTasks` ยังว่างและ `currentRoom` ยังเป็น null → `getPoolTask()` คืน null เสมอ แล้วตกไปใช้โจทย์ดั้งเดิม

**นี่คือสิ่งที่ warning `react-hooks/exhaustive-deps` ชี้อยู่พอดี** ซึ่งก่อนหน้านี้ถูกมองข้ามว่าเป็น baseline

**ผลพลอยได้ — เจอบั๊กเก่าที่ซ่อนอยู่มานาน**: `getRound4Task()` ในตัว poller ก็โดนแบบเดียวกัน แปลว่า**รอบ 4 ใช้ `ROUND_4_FALLBACK_TASK` มาตลอด ไม่เคยดึงโจทย์จากฐานข้อมูลจริงเลย** ที่ไม่มีใครสังเกตเพราะค่า fallback ถูกเขียนให้เหมือนโจทย์ hard ตัวแรกเป๊ะ

แก้: ใช้ `taskResolverRef` เก็บฟังก์ชันเวอร์ชันล่าสุด (แพตเทิร์นเดียวกับ `tickRef` ที่ใช้แก้ render loop) ให้ poller อ่านผ่าน ref แทน — ได้ค่าล่าสุดโดยไม่ต้องขยาย dependency array
หลังแก้ warning `exhaustive-deps` ของไฟล์นี้**หายไปเอง** เหลือแต่ error `motion` ที่เป็น baseline เดิม

### ตรวจความสอดคล้องของการเลือกโจทย์ (client ↔ server)
เทียบการเลือกโจทย์ของทั้งสองฝั่งทุกระดับ × ทุกรอบ — **ตรงกันทั้งหมด** (task_id และจำนวน test case ตรงกันทุกช่อง) เพราะทั้งคู่ใช้ `ORDER BY task_id ASC` แล้ว offset ด้วย `roundNum - 1`

### ทดสอบบนหน้าจอจริง
- หน้าต่างสร้างห้องแสดงตัวเลือกครบ: "มาตรฐาน (รอบละ 60 วินาที)" / "โหมดเร็ว (รอบละ 30 วินาที)" และ "ดั้งเดิม / ง่าย / ปานกลาง / ยาก" พร้อมคำอธิบาย
- เลือกโหมดเร็ว + ปานกลาง ผ่าน UI จริง → บันทึกลง DB ถูกต้อง (`quick` / `medium`)
- เริ่มแมตช์ → นาฬิการอบ 1 เป็น 30 วินาทีจริงตามโหมดเร็ว
- **หลังแก้บั๊ก stale closure**: หัวข้อโจทย์ "1. ตรวจสอบแอนนาแกรม (Anagram Checker)" **และ**โค้ดตั้งต้น `def is_anagram(s, t):` ตรงกันแล้ว
