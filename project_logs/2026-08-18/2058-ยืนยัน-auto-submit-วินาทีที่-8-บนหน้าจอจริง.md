## ทำไมต้องทำขั้นนี้
รอบก่อนแก้บั๊ก "ระบบส่งคำตอบอัตโนมัติส่งไม่ทัน" ไปแล้ว (เพิ่ม `autoSubmitLeadSeconds: 8`) แต่**ยืนยันได้แค่ระดับ API** ว่า "ส่งก่อนหมดเวลา 8 วินาทีรับ / ส่งหลังรอบปิดปฏิเสธ" ยังไม่เคยเห็นกับตาว่า client ยิง auto-submit ที่วินาทีที่ 8 จริงหรือไม่ เพราะแท็บทดสอบถูก Chrome freeze ทำให้ interval ไม่ทำงานในช่วง lead window

## วิธีทดสอบที่ใช้รอบนี้ (แก้ปัญหาแท็บ freeze)
ปัญหาเดิมคือเรียก JS ครั้งเดียวแล้ว `await` ยาว 45 วินาที ทำให้ renderer ถูก freeze แล้ว CDP timeout รอบนี้เปลี่ยนวิธี:
1. ฝัง `setInterval` **ในหน้าเว็บเอง** บันทึกค่า countdown + สถานะการแจ้งเตือน "กำลังตรวจโค้ด" ทุก 500ms ลง `window.__log` — การเก็บข้อมูลจึงไม่ขึ้นกับจังหวะการเรียกเครื่องมือของผม
2. เรียกเครื่องมือแบบ**สั้นๆ หลายครั้ง** และแทรก screenshot เป็นระยะเพื่อปลุกแท็บไม่ให้ถูก freeze
3. อ่าน `window.__log` ย้อนหลังตอนจบเพื่อดูว่าการตรวจโค้ดเริ่มตอน countdown เหลือเท่าไหร่

## สภาพแวดล้อมก่อนเริ่ม (มีปัญหาต้องแก้ก่อน)
พบว่า backend ตายไปแล้ว (exit code 4) สาเหตุ: **คอนเทนเนอร์ PostgreSQL รีสตาร์ตตัวเอง** ทำให้ connection pool ของ node พัง แล้ว server ก็พ่น error รัวๆ จนตาย — นับจาก log ได้ **56,492 บรรทัด** ของ `Arcade match tick error` + 2,843 บรรทัดของ `stale-room sweep error` รวมไฟล์ log 63,140 บรรทัด
ไม่ใช่ผลจากโค้ดที่แก้ไปรอบก่อน (เป็นเรื่อง DB หลุด) แต่ชี้ให้เห็นจุดอ่อนจริงของระบบ: **เมื่อ DB หลุด server ไม่มี back-off เลย พ่น error ทุก 1 วินาทีไม่จำกัดจนตัวเองตาย** — บันทึกไว้เป็นงานที่ควรแก้ (ดูหัวข้อท้ายบันทึก)
แก้เฉพาะหน้าโดยรีสตาร์ต backend + vite ใหม่ ตรวจแล้วว่าตารางและข้อมูลสถิติผู้เล่นรอด (`arcade_player_stats` เหลือ 2 แถวตามเดิม)

## ผลการทดสอบ — ผ่าน

สร้างห้อง `ARC-DXBE` (2 คน: pong + Bot_SyntaxPro) เริ่มแมตช์แล้ว**ตั้งใจไม่แตะปุ่มส่งคำตอบเลย** ปล่อยโค้ด placeholder (`pass`) ไว้อย่างนั้น

**ร่องรอยจาก `window.__log` (บันทึกทุก 500ms):**
```
{ t: 11, judging: false }
{ t:  9, judging: false }
{ t:  9, judging: false }
{ t:  8, judging: true  }   <-- เริ่มตรวจโค้ดตรงนี้พอดี
{ t:  7, judging: true  }
{ t:  6, judging: true  }
```
**การแจ้งเตือน "กำลังตรวจโค้ด" เริ่มขึ้นตอน countdown เหลือ 8 วินาทีพอดี** ตรงกับค่า `autoSubmitLeadSeconds: 8` เป๊ะ

**ผลลัพธ์ที่ลงฐานข้อมูลจริง:**
| user_name | round_num | pass_count | total_count | quality_score | time_used_seconds | round_score |
|---|---|---|---|---|---|---|
| pong | 1 | 0 | 4 | 5 | 51 | 20 |

และคะแนนถูกนับเข้าจริง: `arcade_participants` แสดง pong score = **20** (ไม่ใช่ 0)

**ตีความ**: โค้ด placeholder ที่ไม่ได้แก้เลยได้ 0/4 เทสต์ถูกต้อง, AI judge ให้คะแนนคุณภาพ 5/100 (สมเหตุสมผลมากสำหรับโค้ด stub ที่มีแต่ `pass` — ตรงกับที่ system prompt สั่งให้โค้ดว่าง/stub ได้ 0-10), ใช้เวลา 51 วินาที
**ก่อนแก้บั๊ก เคสนี้จะได้ 0 คะแนนและไม่มีแถวประวัติเลย** ตอนนี้ได้ทั้งคะแนนและประวัติครบ
