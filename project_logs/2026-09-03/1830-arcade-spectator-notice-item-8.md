# ข้อ 8 — แจ้งเตือนผู้ชม Arcade (ส่งคำตอบแล้วแก้โค้ดไม่ได้) ให้ชัดขึ้น

**วันที่/เวลา**: 2026-09-03 ~18:30 (ต่อจากข้อ 7 ที่ commit `aa025df`)

## ปัญหา

เมื่อผู้เล่นส่งคำตอบในรอบแล้ว (`hasSubmittedThisRound`) editor จะถูกล็อก `readOnly` เงียบๆ
มีแค่แบนเนอร์เล็กเหนือ editor ผู้เล่นพิมพ์แล้วช่องเงียบ ไม่รู้ว่าทำไม (ต่างจากกรณีถูกคัดออกที่มี
จอ takeover เต็มอยู่แล้ว)

## สิ่งที่ทำ

- **`client/src/pages/Arcade/widgets/BattleRoyaleGameplayView.jsx`**: เพิ่ม **overlay จางทับ
  editor + ข้อความกลางจอ** เมื่ออยู่สถานะ `spectating` (ส่งคำตอบแล้ว & ยังไม่ถูกคัดออก):
  - ป้าย "✓ ส่งคำตอบรอบนี้แล้ว"
  - "แก้โค้ดไม่ได้จนจบรอบ · รอผลแล้วไปต่อรอบถัดไป"
  - "ระหว่างนี้ยังกดใช้ไอเทมและดูโค้ดคนอื่นได้"
  - overlay เป็น `pointer-events-none` เพื่อไม่บังการกดไอเทม (เจตนาเดิมของการส่งเร็ว
    คือได้เวลาไปเล่นไอเทม) และ **ไม่โชว์ทับ** debuff overlay (blackout/inkFog) ที่ยึดจออยู่แล้ว

## เหตุผล

overlay กลางจอเห็นชัดกว่าแบนเนอร์เล็ก และตอบโจทย์อาการ "พิมพ์แล้วช่องเงียบ" โดยตรง —
บอกทันทีว่าทำไมพิมพ์ไม่ได้ ใช้สถานะ `spectating` เดิมที่โค้ดคำนวณอยู่แล้ว (ใช้กับ `editorLocked`)
ไม่แตะ logic การล็อก

## สถานะการทดสอบ

- **lint สะอาด** (`eslint BattleRoyaleGameplayView.jsx` ผ่าน)
- overlay ผูกกับ boolean `spectating = hasSubmittedThisRound && !eliminated` ที่มีอยู่แล้ว
  และตรวจ debuff ก่อนแสดง — ตรวจความถูกต้องด้วยการอ่านโค้ด
- ⚠️ **ยังไม่ได้ทดสอบภาพในแมตช์จริง**: การเข้าถึงสถานะ "ส่งคำตอบแล้ว" ต้องตั้งห้อง Arcade
  5 คน เริ่มแมตช์ แล้วส่งคำตอบจริง ซึ่ง automate ผ่านเบราว์เซอร์ไม่คุ้ม — **แนะนำให้ผู้ใช้
  เปิดแมตช์จริงแล้วส่งคำตอบดู 30 วินาที** เพื่อยืนยันภาพก่อนถือว่าเสร็จสมบูรณ์ (ตามกฎ CLAUDE.md
  ที่ real-time state ต้องทดสอบผ่าน dev server จริง)
