# Spec 0005 ticket 01–03: รหัสผ่านห้อง, จำนวนผู้เล่นสูงสุด, ลำดับตัวเลือกแบบวัดระดับ

**วันที่:** 2026-10-26 02:15 (Asia/Bangkok) — Person 3

## สิ่งที่แก้

### Ticket 01: บันทึกตั้งค่าห้องแล้วรหัสผ่านไม่หาย (บั๊ก A1)
- ย้าย endpoint `POST /api/arcade/rooms/:id/settings` จาก `server/server.js` ไป `server/arcade/lobby-api.js`
  - ทำให้เทส HTTP ผ่าน fixture ของ Arcade ได้
  - `clampArcadeMaxPlayers` ย้ายไปไฟล์เดียวกัน และ `server.js` import กลับมาใช้ตอนสร้างห้อง
- **สัญญาของรหัสผ่านเปลี่ยนเป็นสามแบบ:**
  - ไม่ส่ง หรือส่งสตริงว่าง = คงรหัสเดิม
  - ส่งสตริงที่ไม่ว่าง = ตั้งรหัสใหม่ด้วย bcrypt
  - `clear_password: true` = ลบรหัส
- `GET /api/arcade/rooms/:id` เพิ่ม `room.is_password_protected`
  - ใช้ชื่อเดียวกับที่รายการห้องและการสร้างห้องใช้อยู่แล้ว แทนชื่อ `has_password` ใน ticket
- **client:**
  - ฟอร์มตั้งค่าไม่เติม `currentRoom.password` อีกต่อไป (ค่านี้ไม่เคยถึง client)
  - ส่งรหัสผ่านไปเฉพาะเมื่อพิมพ์
  - มีข้อความบอกสถานะรหัสผ่านของห้อง และปุ่ม "ลบรหัสผ่าน" / "เก็บรหัสผ่านไว้"
- ข้อความ error 500 เป็นภาษาไทยแทน `err.message`

### Ticket 02: ลดผู้เล่นสูงสุดต่ำกว่าคนในห้องไม่ได้ (บั๊ก A2)
- **server:** ตอบ 409 พร้อมข้อความไทยเมื่อค่าใหม่ต่ำกว่าจำนวนคนในห้อง
  - นับด้วย `rematchRoster` แบบเดียวกับตอนเข้าห้อง จึงไม่นับคนที่จบแมตช์ก่อนแล้วยังไม่เลือกอยู่ต่อ
- **client:** ปิดปุ่มจำนวนที่ต่ำกว่าคนในห้อง และขึ้นข้อความ "ตอนนี้ในห้องมี N คน เลือกน้อยกว่านี้ไม่ได้"

### Ticket 03: สลับลำดับตัวเลือกในแบบวัดระดับ (บั๊ก U4)
- `GET /api/advanced-validation` สลับทั้งลำดับข้อและลำดับตัวเลือกทุกครั้งที่โหลด ใช้ Fisher–Yates กับ `crypto.randomInt`
- การตรวจเทียบจากข้อความของตัวเลือกอยู่แล้ว และ client ส่งคำตอบคู่กับ id ของข้อตามลำดับที่ได้รับ จึงไม่ต้องแก้ client
