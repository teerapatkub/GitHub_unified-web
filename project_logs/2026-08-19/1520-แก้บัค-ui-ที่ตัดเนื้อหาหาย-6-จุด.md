## 2. ต้นเหตุจริง — เป็นบัค 2 ตระกูล ไม่ใช่ CSS หลงบรรทัดเดียว

### ตระกูล A — flex item ถูกบีบจนเล็กกว่าเนื้อหาของตัวเอง

คอนเทนเนอร์ที่เลื่อนได้เขียนไว้เป็น `h-full overflow-y-auto ... flex flex-col space-y-6`
ปัญหาคือ **`flex-shrink` มีค่าเริ่มต้นเป็น 1** พอเนื้อหารวมสูงกว่ากล่อง flex จะ "บีบ" ลูกแต่ละตัวให้เตี้ยลง
แทนที่จะปล่อยให้กล่องแม่ scroll และเพราะการ์ดทุกใบตั้ง `overflow-hidden` ไว้ (เพื่อให้มุมโค้งไม่แตก)
การถูกบีบจึงกลายเป็น **การตัดเนื้อหาตัวเองทิ้ง** — ตรงกับภาพที่ 1 เป๊ะ

### ตระกูล B — `justify-center` ในกล่องที่ scroll ได้

`h-full overflow-y-auto ... flex flex-col items-center justify-center`
การจัดกลางแนวตั้งของ flex คือการแจก "พื้นที่ที่เหลือ" พอไม่มีพื้นที่เหลือ มันจะดันเนื้อหา
**ทะลุขอบบนของกล่อง** ซึ่งเป็นทิศทางเดียวที่ scroll container ไปถึงไม่ได้ (scrollTop ต่ำกว่า 0 ไม่ได้)
เนื้อหาส่วนบนจึงหายไปอย่างถาวร — ตรงกับภาพที่ 2

**วิธีแก้ตระกูล B**: แยกเป็นสองชั้น — ชั้นนอกทำหน้าที่ scroll เท่านั้น ชั้นในเป็น `min-h-full`
เนื้อหาน้อย → ชั้นในสูงเต็มกล่อง จัดกลางได้ตามเดิม; เนื้อหาเยอะ → ชั้นในโตเกินกล่อง
`justify-center` ไม่มีพื้นที่เหลือให้แจก จึงไม่ดันอะไรทะลุ

## 3. บัคจริงที่แก้ (พิสูจน์แล้วว่าเป็นบัคจริง ไม่ใช่แก้เผื่อไว้)

## 4. จุดที่แก้เผื่อไว้ — และยืนยันแล้วว่า "ยังไม่ใช่บัคจริง"

ตรวจแล้วว่าสองจุดนี้ **ไม่ได้ตัดเนื้อหาอยู่จริง** ณ ตอนนี้ แก้เพราะเป็นรูปแบบเดียวกับที่พังไปแล้ว
7 จุดข้างบน จึงไม่อยากทิ้งไว้ให้พังเงียบๆ ตอนมีอะไรงอกเพิ่มด้านบน — บันทึกไว้ตรงๆ ว่าเป็นการแก้เผื่อ
ไม่ใช่การแก้บัค:

- `GlossaryModal.jsx` — เพิ่ม `flex-1 min-h-0` ให้ส่วนที่ scroll (ทดสอบแล้ว: ถอด class ออกก็ยังไม่ตัด
  เพราะ flex item หดเองได้ตามค่าเริ่มต้น และตัวมันมี `overflow-y-auto` อยู่แล้ว)
- `BattleRoyaleGameplayView.jsx` รายชื่อคู่แข่ง — เพิ่ม `min-h-0` (ทดสอบแล้ว: บอท 4 ตัวยังไม่ล้นกล่อง
  `scrollHeight` เท่ากับ `clientHeight`)

ส่วน `RoundSummaryView.jsx` และหน้าผู้สังเกตการณ์ (ตอนตกรอบ) แก้ด้วยรูปแบบเดียวกับข้อ 3
เพราะเขียนด้วยโครงเดียวกันทั้งคู่ (`justify-center` ในกล่อง scroll) — ตรวจหลังแก้แล้วสะอาด

## 6. การทดสอบที่ทำจริง

**เครื่องมือ**: detector ที่ไล่ทุก element หาการตัดเนื้อหา (`overflow:hidden` + `scrollHeight > clientHeight`
หรือ `scrollWidth > clientWidth`) กรอง element ภายในของ Monaco ออก เพราะ Monaco จัดการ scroll
เสมือนของตัวเองและรายงาน `scrollHeight` มหาศาลเสมอ

**ยืนยันว่า detector ใช้งานได้จริง** (สำคัญ ไม่งั้น "0 บัค" ไม่มีความหมาย): ใส่ class เดิมกลับเข้าไปใน DOM
สดๆ แล้ว detector จับได้ทันทีทั้งสองการ์ดที่ผู้ใช้ถ่ายภาพมา — สถิติหาย 106px, แมตช์ที่ผ่านมาหาย 178px
พอถอด class ออกก็กลับมาเป็น 0 ทำแบบเดียวกันกับร้านค้า (จับได้ 167px) และหน้าผลแมตช์
(วัดได้ว่าเนื้อหาถูกดันขึ้นไปอยู่ที่ตำแหน่ง `top: -175.5px` ขณะที่กล่องเริ่มที่ `top: 84px`
= **259.5px ที่เลื่อนไปดูไม่ได้**) หลังแก้: `top` ของชั้นในเท่ากับ `top` ของกล่องพอดี (84 = 84),
`scrollTop` เป็น 0, เนื้อหาสูง 1015px ในกล่อง 496px และ scroll ได้ครบ

**กวาดทุก phase ทุกขนาดหน้าจอ** (ใช้ recorder เก็บผลทุก 700ms เพราะหน้าสรุปรอบโชว์แค่ 5 วินาที
เร็วเกินกว่าจะ poll ทัน):

| ขนาดหน้าจอ | phase ที่กวาด | ผล |
|---|---|---|
| 1280×560 (จอเตี้ย) | ROUND 3, SUMMARY 3, SHOP 3, ROUND 4, RESULT | 0 จุดทุก phase |
| 375×812 (มือถือ) | lobby, modal สร้างห้อง, ห้องรอ, ROUND 1, SUMMARY 1, SHOP 1, ROUND 2, RESULT | 0 จุดทุก phase (ทั้งแกน X และ Y) |
| 768×1024 (แท็บเล็ต) | lobby | 0 จุด |
| 1900×700 (ขนาดเดียวกับหน้าจอผู้ใช้) | lobby พร้อมการ์ดทั้งสองใบที่เป็นปัญหา | 0 จุด |

หน้าผู้สังเกตการณ์ก็ถูกกวาดด้วย — ในแมตช์ที่จอ 1280×560 ผู้เล่นตกรอบจริง (`is_eliminated = 1`)
ดังนั้น ROUND 3 กับ ROUND 4 ที่บันทึกว่าสะอาดคือหน้าผู้สังเกตการณ์นั่นเอง

กับ `set-state-in-effect` ใน `useRoomLifecycle` 1 อัน), `npm run build` ผ่าน, `arcade_rooms` เหลือ 0 แถว

## 7. ผลกระทบ

- **เป็นการแก้ layout/CSS เท่านั้น** ไม่แตะ state, logic การให้คะแนน, การสุ่มโจทย์, Bot AI หรือ schema
- **หน้าจอเดสก์ท็อปหน้าตาเหมือนเดิม** — ค่าที่เปลี่ยนบนจอเล็กใส่ผ่าน `sm:` breakpoint
  ส่วนการแยกชั้น scroll/`min-h-full` ให้ผลเหมือนเดิมทุกกรณีที่เนื้อหาไม่ล้น
- **เปลี่ยนพฤติกรรมที่ควรรู้**: คอลัมน์เขียนโค้ดตอนนี้ scroll ได้เองแทนที่จะตัดทิ้ง
  บนจอเตี้ยมากผู้เล่นอาจต้องเลื่อนเล็กน้อยเพื่อเห็นปุ่มส่งคำตอบ ซึ่งดีกว่าปุ่มหายไปเฉยๆ

## 8. ที่ยังไม่ได้ทำ

- ยังไม่ได้กวาด phase ครบทุกอันบนแท็บเล็ต (กวาดแค่ lobby) — เดสก์ท็อปกับมือถือครอบคลุมช่วง
  breakpoint หลักไปแล้วทั้งสองด้าน
- detector ตรวจได้แค่ "เนื้อหาถูกตัดหาย" ตรวจเรื่องความสวยงามอื่น (สี ระยะห่าง ตำแหน่งเหลื่อม
  ที่ยังมองเห็นครบ) ไม่ได้ — ยังต้องใช้ตาคนดู
