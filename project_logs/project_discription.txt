==================================================
1. จุดประสงค์ของเอกสารนี้
==================================================

ไฟล์นี้มีหน้าที่เป็นเอกสารศูนย์กลางของโปรเจกต์
เป้าหมายของไฟล์นี้มีดังนี้

1) ใช้อธิบายว่าโปรเจกต์นี้คืออะไร
2) ใช้อธิบายว่าแต่ละระบบทำหน้าที่อะไร
3) ใช้อธิบายโครงสร้างภาพรวมว่า Frontend, Backend, Database, AI, Learning, Simulation เชื่อมกันอย่างไร
4) ใช้เป็นเอกสารอ้างอิงให้สมาชิกในทีมทำงานต่อได้โดยไม่ต้องเริ่มทำความเข้าใจใหม่จากศูนย์
5) ใช้ประสานงานกับ AI ตัวอื่น โดยให้ AI อ่านไฟล์นี้ก่อนเพื่อเข้าใจบริบทของงาน
6) ใช้เก็บแนวคิดหลักของโปรเจกต์ เพื่อป้องกันการพัฒนาออกนอกทิศทาง
7) ใช้บันทึกข้อตกลงเชิงโครงสร้าง เช่น ระบบใดเป็นแกนหลัก ระบบใดเป็นระบบเสริม อะไรทำเสร็จแล้ว อะไรยังห้ามแตะ

หลักสำคัญ:
- ถ้ามีการเปลี่ยนทิศทางของโปรเจกต์ ต้องแก้ไฟล์นี้
- ถ้ามีการปรับโครงสร้างระบบ ต้องแก้ไฟล์นี้
- ถ้ามีการเปลี่ยนขอบเขตของบทเรียน ระบบ level ระบบ AI หรือ simulation ต้องแก้ไฟล์นี้
- ไฟล์นี้ควรถูกมองว่าเป็น "คู่มือภาพรวมของโปรเจกต์"

==================================================
3. ภาพรวมของโปรเจกต์
==================================================

โปรเจกต์นี้เป็นเว็บแอปสำหรับการเรียนรู้ภาษา Python สำหรับผู้เริ่มต้น โดยผสมแนวคิดของ:
- เว็บไซต์เรียนเขียนโปรแกรม
- ระบบฝึกปฏิบัติผ่านการเขียนโค้ดจริง
- ระบบแก้บัคและโจทย์ท้าทาย
- ระบบ progression แบบเกม
- ระบบ AI สำหรับช่วยสร้างโจทย์และช่วยผู้เรียน
- ระบบจำลองชีวิตนักพัฒนา (Simulation)

หัวใจของโปรเจกต์นี้ไม่ใช่แค่ "เว็บสอน Python"
แต่เป็น "เกมพัฒนาตัวเองผ่านการเรียนเขียนโปรแกรม"

แนวคิดหลักที่ต้องยึดไว้เสมอคือ:

1) การเรียนคือแกนหลักของระบบ
2) ผู้ใช้ควรเห็นความก้าวหน้าของตัวเองอย่างชัดเจน
3) ระบบต้องทำให้การเรียนรู้รู้สึกสนุกขึ้น ไม่ใช่แค่ย้ายบทเรียนมาไว้บนเว็บ
4) AI เป็นตัวช่วยเพิ่มความหลากหลายและความยืดหยุ่น ไม่ใช่แกนเดียวที่ระบบพึ่งพา
5) Simulation เป็นโหมดท้าทายเสริมสำหรับผู้ใช้ที่อยากใช้ทักษะในบริบทที่กดดันขึ้น

สรุปแนวทางของโปรเจกต์:
"เปลี่ยนเว็บเรียนที่มีเกมแทรก ให้เป็นเกมพัฒนาตัวเองที่ใช้การเรียนเป็น core loop และใช้ simulation เป็น challenge layer"

==================================================
4. เป้าหมายของระบบ
==================================================

เป้าหมายเชิงการเรียนรู้:
- ให้ผู้ที่ไม่เคยเรียน Python มาก่อนสามารถเริ่มเรียนได้
- ให้ผู้ใช้เข้าใจพื้นฐานจริง ไม่ใช่แค่กดผ่าน
- ให้ผู้ใช้ฝึกทั้งการอ่านโค้ด เขียนโค้ด และแก้บัค
- ให้ผู้ใช้ค่อย ๆ สะสมความมั่นใจผ่านด่านและรางวัล

เป้าหมายเชิงประสบการณ์:
- ทำให้การเรียนมีความเป็นเกม
- ทำให้ระบบดูมี progression ชัดเจน
- ทำให้ผู้ใช้รู้สึกอยากกลับมาใช้งานต่อ
- ทำให้ UX เข้าใจง่ายแม้ระบบจะมีหลายส่วน

เป้าหมายเชิงระบบ:
- รวมหลายระบบให้อยู่ในประสบการณ์เดียวกัน
- ใช้ฐานข้อมูลเดียว
- ใช้ user progression เดียว
- ใช้ reward system เดียว

- แบบฝึกหัด placeholder ต้องใช้งานได้ ไม่ทำให้ระบบแตก

==================================================
10. ระบบแบบทดสอบและกิจกรรมการเรียน
==================================================

ในแต่ละบท ระบบอาจมีองค์ประกอบต่อไปนี้:

1) Pre-test
- ใช้วัดความรู้ก่อนเรียน
- แสดงคะแนนทันทีหลังทำเสร็จ

2) Post-test
- ใช้วัดผลหลังเรียน
- แสดงคะแนนหลังทำเสร็จ
- สรุปคะแนนภาพรวมหลัง post-test เสร็จ

3) Exercise
- โจทย์ฝึกเขียนโค้ด
- สำหรับทักษะพื้นฐานและการลงมือทำ

4) Debug Lab
- โจทย์แก้บัค
- เน้นการอ่านโค้ดและหาข้อผิดพลาด

5) Challenge
- โจทย์ท้าทาย
- เน้นความยากที่สูงกว่า exercise ปกติ

6) Promotion Exam
- แบบทดสอบเลื่อนขั้น
- ใช้ AI สร้างโจทย์หรือ fallback ได้
- ผ่านแล้วปลดล็อกระดับ tier ถัดไป

- เชื่อม learning กับ simulation

Level 4 = Flow Tactician
Level 5 = Function Crafter

Tier:

- Level 8-10 = Advanced

==================================================
13. ระบบ Promotion Exam
==================================================

ระบบนี้ใช้ควบคุมการเลื่อนจาก tier หนึ่งไปอีก tier หนึ่ง

กติกาปัจจุบัน:

Beginner -> Intermediate
- ปลดล็อกเมื่อ raw level ถึง 4
- ยังไม่ผ่าน promotion exam จะถูก cap ไว้ก่อน
- ข้อสอบประมาณ 10 ข้อ
- ผ่านที่คะแนน 7 ข้อขึ้นไป

Intermediate -> Advanced
- ปลดล็อกเมื่อ raw level ถึง 8
- ยังไม่ผ่าน promotion exam จะถูก cap ไว้ก่อน
- ข้อสอบประมาณ 12 ข้อ
- ผ่านที่คะแนน 9 ข้อขึ้นไป

ข้อสังเกต:
- ตัวเนื้อหาข้อสอบจริงสามารถให้สมาชิกอีกคนเติมภายหลังได้
- ระบบ logic, route, UI, reward และ promotion state ต้องพร้อมอยู่แล้ว

==================================================
14. ระบบ XP และ Coin
==================================================

ผู้ใช้จะได้ XP และ Coin จาก:
- Exercise
- Debug Lab
- Challenge
- Promotion flow บางกรณี
- กิจกรรมอื่นในอนาคต

หลักการ:
- XP ใช้สำหรับการเติบโตของผู้ใช้
- Coin ใช้แลกของในระบบ เช่น theme หรือของตกแต่ง
- ทั้งสองอย่างต้องมาจาก action ที่ผู้ใช้ทำสำเร็จจริง

==================================================
15. ระบบ Celebration / Reward Feedback
==================================================

ระบบนี้มีไว้ทำให้ผู้ใช้รู้สึกว่าความสำเร็จของตน “มีน้ำหนัก”

มีอย่างน้อย 2 ประเภท:

1) Celebration เมื่อผ่านโจทย์
- ขนาดเล็กกว่า
- แสดง +XP, +Coin, ผ่านโจทย์แล้ว

2) Celebration เมื่อเลเวลอัปหรือเลื่อนขั้น
- ต้องอลังการกว่า
- เป็น feedback ระดับเกม
- ใช้เพื่อเน้นความสำคัญของ progression

หลักการ:
- การผ่านโจทย์ = mini success
- การเลื่อนระดับ = major milestone

==================================================
16. ระบบ AI
==================================================

AI เป็นส่วนสำคัญแต่ไม่ควรเป็น single point of failure

AI ถูกใช้ในหน้าที่ต่อไปนี้:

1) สร้างโจทย์ Exercise / Debug / Challenge
2) สร้าง Promotion Exam
3) สร้างงานใน Job Platform
4) ทำหน้าที่ AI Helper / Lumi

แนวทางสำคัญ:
- ถ้า AI ช้า ต้องมี loader ที่เหมาะสม
- ถ้า AI ไม่ตอบ ต้องมี fallback
- ถ้าโจทย์ยัง active อยู่ อาจ reuse ได้ในบางโหมด
- ถ้าเป็นโจทย์ที่ควรเปลี่ยนใหม่ทุกครั้ง เช่น exercise บางประเภท ค่อย force regenerate

ข้อควรระวัง:
- อย่าผูก UX ทั้งหมดไว้กับ response time ของ AI
- ต้องมีระบบรองรับกรณี AI สร้างเนื้อหาไม่ทันหรือสร้างได้ไม่ดี

==================================================
17. ระบบ Simulation
==================================================

Simulation เป็นโหมดเสริม ไม่ใช่แกนหลักของผู้เริ่มต้น

เป้าหมายของ simulation:
- ให้ผู้ใช้ใช้ทักษะที่เรียนไปในบริบทที่กดดันขึ้น
- ทำให้เห็นการประยุกต์ใช้ความรู้ในโลกจำลอง
- เพิ่มแรงจูงใจให้ผู้ใช้เรียนต่อเพื่อปลดล็อกของและโหมดท้าทาย

องค์ประกอบสำคัญ:
- Desktop จำลอง
- Job Platform
- Code Editor
- งาน freelance
- เงิน
- Reputation
- เวลาในเกม
- สถานะทรัพยากร เช่น stamina / battery / rent

แนวคิดเชิงตำแหน่งของโหมดนี้:
- เป็น advanced challenge layer
- ใช้ต่อยอดจากระบบเรียน
- ควรสัมพันธ์กับ progression ของผู้ใช้

==================================================
18. ระบบหลังบ้าน / Admin
==================================================

ระบบนี้รองรับ:
- ดูสถิติการใช้งาน
- จัดการผู้ใช้
- จัดการบทเรียน
- จัดการโจทย์และ test case
- จัดการธีมและร้านค้า

บทบาทของระบบ admin:
- ช่วยให้ทีมสามารถดูแลเนื้อหาได้
- ช่วยให้สามารถเพิ่มบทเรียนและโจทย์ได้โดยไม่แตะโค้ดทุกจุด

==================================================
19. โครงสร้างเทคนิคของโปรเจกต์
==================================================

Frontend:
- ตำแหน่งหลัก: full_web/unified-web/client
- ใช้ React
- ใช้ React Router
- ใช้ Framer Motion
- ใช้ axios ในการเรียก API

Backend:
- ตำแหน่งหลัก: full_web/unified-web/server

- route หลักส่วนใหญ่อยู่ใน server.js

Database:

หมายเหตุสำคัญ:
- ปัจจุบันโปรเจกต์รวมมาทำงานบน MySQL
- ถ้ามี schema ใหม่ต้องคิดให้เข้ากับ MySQL

==================================================
20. หลักการทำงานร่วมกัน
==================================================

กติกาหลักในการพัฒนาต่อจากนี้:

1) ถ้าส่วนใดเสร็จแล้ว อย่าไปทับโดยไม่จำเป็น
2) ถ้าต้องเพิ่มโครงสร้างใหม่ ให้เพิ่มแบบปลอดภัยและ idempotent
3) ถ้าแก้โครงสร้างระบบ ต้องอัปเดตไฟล์นี้
4) ถ้าเป็นการแก้ bug หรือเพิ่มฟีเจอร์รายวัน ให้จดในไฟล์ตามวันที่
5) หาก AI ตัวอื่นเข้ามาทำงาน ให้เริ่มอ่านไฟล์นี้ก่อน

- การเรียนต้องยังเป็นแกนหลัก
- Simulation ต้องเป็นโหมดเสริมที่มีคุณค่า
- Progression ต้องเป็นแกนกลางร่วมของหลายระบบ
- UX ต้องช่วยผู้เริ่มต้น ไม่ทำให้สับสน
- ถ้าระบบใดซับซ้อนขึ้น ต้องมี onboarding / tutorial รองรับ
