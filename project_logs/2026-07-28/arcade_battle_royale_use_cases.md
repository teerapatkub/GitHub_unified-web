# Arcade Battle Royale (โหมดการเล่นที่ 2) - Use Case & Use Case Description

เอกสารนี้ระบุรายละเอียดของ Use Cases และ Use Case Descriptions สำหรับ**โหมด Arcade Battle Royale (โหมดปาร์ตี้เอาตัวรอด 5 คน แบบ Real-time)** ซึ่งเป็นระบบการเล่นเขียนโค้ดที่มีการแข่งขัน คัดออก และกลั่นแกล้งกันด้วยไอเทมป่วนจอ

---

## 1. Actors (ผู้แสดงบทบาท)

| Actor | Description |
| :--- | :--- |
| **ผู้เล่น (Player)** | ผู้ใช้งานระบบที่เข้าเล่นเกมในโหมด Arcade Battle Royale เพื่อทำโจทย์เขียนโค้ด ซื้อไอเทม และแกล้งผู้เล่นอื่น |
| **เซิร์ฟเวอร์เกม (Game Server / System)** | ระบบหลังบ้านที่ทำหน้าที่ควบคุมเกม, จับคู่ผู้เล่น (Matchmaking), รันระบบเวลา (Timer), ประเมินโค้ด (Compiler/Interpreter), จัดการระบบการซื้อขายไอเทม, และจัดการการส่งผลกระทบของไอเทมแบบ Real-time |
| **ฐานข้อมูล (Database)** | ระบบจัดเก็บข้อมูลถาวร เช่น ข้อมูลผู้ใช้, ยอดเหรียญรางวัลสะสมจริง (Code Coins) |

## 4. Use Case Descriptions (รายละเอียดของแต่ละยูสเคส)

### UC-01: ค้นหาห้องและจับคู่ผู้เล่น (Matchmaking & Lobby)

* **Actor:** ผู้เล่น (Player), เซิร์ฟเวอร์เกม (Game Server)
* **Description:** ผู้เล่นส่งคำขอเข้าร่วมแข่งขันโหมด Arcade Battle Royale ระบบจะทำการค้นหาห้องและจับคู่ผู้เล่นให้ครบ 5 คนเพื่อเข้าสู่ห้อง Lobby เตรียมตัวเริ่มเกม
* **Pre-conditions:**
  1. ผู้เล่นผ่านการ Login เข้าสู่ระบบแล้ว
  2. ผู้เล่นไม่ได้อยู่ในสถานะติดโทษแบนหรือกำลังเล่นเกมอื่นอยู่
* **Post-conditions:**
  1. ผู้เล่นทั้ง 5 คนถูกเชื่อมต่อเข้าห้องเดียวกันในสถานะ Lobby เตรียมพร้อมเริ่มรอบที่ 1
* **Basic Flow (ขั้นตอนการทำงานหลัก):**
  1. ผู้เล่นคลิกปุ่ม "เล่นโหมด Arcade Battle Royale" ในหน้าหลัก
  2. ระบบแสดงหน้าจอค้นหาห้อง (Matchmaking Screen) และเริ่มค้นหาผู้เล่นคนอื่น
  3. เซิร์ฟเวอร์เกมจับกลุ่มผู้เล่นที่กำลังค้นหาห้องรวมกันให้ครบ 5 คน
  4. เมื่อครบ 5 คน ระบบนำผู้เล่นทั้งหมดเข้าสู่หน้าจอ Lobby
  5. ระบบแสดงเลย์เอาต์รายชื่อและโปรไฟล์ของผู้เล่นทั้ง 5 คน
  6. ระบบเริ่มนับถอยหลัง 10 วินาทีเพื่อเตรียมเข้าสู่รอบที่ 1
  7. เมื่อหมดเวลาเซิร์ฟเวอร์จะเปลี่ยนสถานะห้องเข้าสู่การแข่งขันรอบที่ 1
* **Alternative / Exception Flows:**
  * **Alt 1: ค้นหาห้องนานเกินกำหนด (Matchmaking Timeout)**
    * ในขั้นตอนที่ 3 หากเวลาผ่านไป 60 วินาทีแล้วยังได้ผู้เล่นไม่ครบ 5 คน
    * ระบบจะดึงบอท (AI Player) เข้ามาเสียบตำแหน่งที่เหลือให้เต็ม 5 คนทันที เพื่อให้เริ่มเกมได้โดยไม่ต้องรอนาน
  * **Exception 1: ผู้เล่นกดยกเลิกการค้นหาห้อง (Cancel Matchmaking)**
    * ก่อนจะเจอห้องครบ 5 คน ผู้เล่นสามารถกดยกเลิกได้ ระบบจะยุติการค้นหาและพากลับหน้าหลัก
  * **Exception 2: ผู้เล่นหลุดออกจากระบบในห้อง Lobby (Disconnect in Lobby)**
    * หากมีผู้เล่นหลุดไปก่อนนับถอยหลังหมดเวลา ระบบจะหยุดนับถอยหลังและเปิดรับสมัครผู้เล่นอื่นเข้ามาแทนที่ หรือดึงบอทเข้ามาแทนที่หากไม่มีผู้เล่นเชื่อมต่อเข้ามาใหม่ภายใน 15 วินาที

### UC-02: เล่นรอบการแข่งขันเขียนโค้ด (Play Coding Round)

* **Actor:** ผู้เล่น (Player), เซิร์ฟเวอร์เกม (Game Server)
* **Description:** ผู้เล่นเขียนโค้ดแก้โจทย์ภาษา Python ตามระดับความยากของรอบนั้นๆ ภายใต้เวลาที่กำหนด
* **Pre-conditions:**
  1. ห้องแข่งขันเปลี่ยนสถานะเข้าสู่การประลองของแต่ละรอบ (รอบ 1, 2 หรือ 3)
* **Post-conditions:**
  1. บันทึกผลการเขียนโค้ดและเวลาที่ส่งของผู้เล่น
  2. คำนวณคะแนนประสิทธิภาพและ Survival Cash ที่ได้
* **Basic Flow (ขั้นตอนการทำงานหลัก):**
  1. ระบบส่งโจทย์ Python พร้อมชุดทดสอบ (Test Cases) ไปให้ผู้เล่นทุกคนพร้อมกันตามระดับความยากของรอบ:
     * **รอบที่ 1:** โจทย์ระดับง่าย (Easy) เวลา 120 วินาที
     * **รอบที่ 2:** โจทย์ระดับกลาง (Medium) เวลา 120 วินาที
     * **รอบที่ 3:** โจทย์ระดับยาก (Hard) เวลา 120 วินาที
  2. ผู้เล่นพิมพ์โค้ดแก้โจทย์ในหน้าต่าง Code Editor
  3. ผู้เล่นสามารถกด "ส่งโค้ด (Submit)" หรือกด "รันโค้ดเพื่อทดสอบ (Run Test)" ได้ตลอดเวลา
  4. ระบบตรวจสอบโค้ดแบบ Real-time และคืนผลลัพธ์ว่าผ่านกี่ Test Case
  5. เมื่อผู้เล่นเขียนโค้ดผ่าน Test Case ทั้งหมด หรือเวลาในรอบนั้นหมดลง ระบบจะถือว่าสิ้นสุดการทำโจทย์ของผู้เล่นคนนั้น
* **Alternative / Exception Flows:**
  * **Alt 1: ผู้เล่นเขียนโค้ดไม่ทันในเวลาที่กำหนด (Timeout)**
    * หากหมดเวลา 120 วินาทีก่อนผู้เล่นกดยื่นส่งผ่านสำเร็จ ระบบจะบังคับส่งโค้ดเวอร์ชันล่าสุดที่ถูกบันทึกไว้ใน Editor และประเมินคะแนนตามจำนวน Test Case ที่รันผ่าน ณ ขณะนั้น
  * **Exception 1: ผู้เล่นออกจากห้องแข่งขันกลางคัน (Rage Quit / Disconnect)**
    * หากผู้เล่นตัดการเชื่อมต่อระหว่างเล่นรอบใดๆ ระบบจะนับว่าได้คะแนน 0 ในรอบนั้น และหากเป็นรอบคัดออก (รอบที่ 2) จะจัดให้อยู่ในอันดับตกรอบทันที

### UC-03: ซื้อไอเทมจากร้านค้าในช่วงพักรอบ (Purchase Items in Shop)

* **Actor:** ผู้เล่น (Player), เซิร์ฟเวอร์เกม (Game Server)
* **Description:** ผู้เล่นนำเงินดำรงชีพ (Survival Cash) ที่ได้สะสมจากรอบก่อนหน้า มาซื้อไอเทมกลั่นแกล้งสำหรับนำไปใช้ป่วนจอคู่ต่อสู้ในรอบถัดไป
* **Pre-conditions:**
  1. จบรอบที่ 1 หรือรอบที่ 2
  2. ผู้เล่นอยู่ในช่วงพักรอบ (Shop Intermission - เวลา 30 วินาที)
  3. ผู้เล่นยังมีชีวิตอยู่ (ไม่ได้ถูกคัดออก)
* **Post-conditions:**
  1. ไอเทมที่ซื้อถูกเพิ่มเข้าไปในช่องเก็บไอเทม (Inventory) ของผู้เล่น
  2. จำนวนเงิน Survival Cash ของผู้เล่นลดลงตามราคาสินค้า
* **Basic Flow (ขั้นตอนการทำงานหลัก):**
  1. ระบบเปิดหน้าจอร้านค้า (Shop Modal) พร้อมแสดงเงิน Survival Cash ปัจจุบันของผู้เล่น
  2. ระบบแสดงรายการไอเทมที่มีให้เลือกซื้อ เช่น:
     * **ไอเทมหมอกบังตา (Foggy Screen):** บังหน้าจอคู่ต่อสู้ด้วยควันหนา (ราคา 🪙 400)
     * **ไอเทมปุ่มสลับ (Key Scrambler):** สลับปุ่มตัวอักษรบางตัวบนคีย์บอร์ดชั่วคราว (ราคา 🪙 600)
     * **ไอเทมขโมยโค้ด (Code Thief):** คัดลอกบรรทัดโค้ดบางส่วนของคู่ต่อสู้มาใส่จอตัวเอง (ราคา 🪙 800)
     * **ไอเทมโล่ป้องกัน (Shield):** ป้องกันการโดนแกล้ง 1 ครั้ง (ราคา 🪙 300)
  3. ผู้เล่นคลิกเลือกไอเทมและกด "ซื้อ (Buy)"
  4. ระบบตรวจสอบยอดเงิน Survival Cash ของผู้เล่น
  5. หากยอดเงินเพียงพอ ระบบจะลดเงิน และอัปเดตช่องเก็บไอเทมของผู้เล่น
  6. ผู้เล่นสามารถซื้อไอเทมได้เรื่อยๆ จนกว่าเงินจะหมดหรือหมดเวลา 30 วินาที
  7. เมื่อหมดเวลา 30 วินาที ระบบจะปิดหน้าจอร้านค้าและเริ่มการแข่งขันรอบถัดไป
* **Alternative / Exception Flows:**
  * **Alt 1: เงินไม่เพียงพอ (Insufficient Cash)**
    * หากกดซื้อไอเทมที่ราคาสูงกว่า Survival Cash ที่มี ระบบจะแสดงข้อความแจ้งเตือน "เงินไม่พอ" และไม่อนุญาตให้ซื้อ
  * **Alt 2: ผู้เล่นไม่เลือกซื้ออะไรเลยภายในเวลา**
    * หากเวลา 30 วินาทีสิ้นสุดลงโดยไม่มีการกดซื้อ ระบบจะปิดหน้าจอร้านค้าอัตโนมัติ และนำเงิน Survival Cash ทั้งหมดสมทบไปยังรอบถัดไป

### UC-04: ใช้งานไอเทมป่วนจอใส่คู่ต่อสู้แบบ Real-time (Use Sabotage Item)

* **Actor:** ผู้เล่น (Player), เซิร์ฟเวอร์เกม (Game Server)
* **Description:** ระหว่างแข่งขันเขียนโค้ด (ในรอบที่ 2 และ 3) ผู้เล่นสามารถคลิกเลือกไอเทมในคลังและคลิกเลือกผู้เล่นเป้าหมายเพื่อยิงผลลัพธ์การแกล้งแบบ Real-time ใส่จอของคนๆ นั้น
* **Pre-conditions:**
  1. อยู่ในช่วงเวลารอบที่ 2 หรือ 3
  2. ผู้เล่นมีไอเทมป่วนจออยู่ในคลัง (Inventory)
  3. ผู้เล่นเป้าหมายยังไม่ได้ตกรอบ
* **Post-conditions:**
  1. ไอเทมในคลังของผู้เล่นลดลง 1 ชิ้น
  2. เอฟเฟกต์การแกล้งปรากฏขึ้นบนหน้าจอของผู้เล่นเป้าหมายทันที
* **Basic Flow (ขั้นตอนการทำงานหลัก):**
  1. ในหน้าจอทำโจทย์เขียนโค้ด จะมีแถบสถานะขนาดเล็กของผู้เล่นคนอื่นอีก 4 คน (แสดงความคืบหน้าของ test cases)
  2. ผู้เล่นคลิกเลือกไอเทมป่วนจอที่ต้องการจากแถบคลังไอเทม (Inventory Bar) ของตนเอง
  3. ผู้เล่นคลิกเลือกตัวละครหรือไอคอนของผู้เล่นเป้าหมายที่ต้องการแกล้ง
  4. ระบบส่งคำสั่งใช้งานไอเทมผ่าน WebSockets ไปยังเซิร์ฟเวอร์เกม
  5. เซิร์ฟเวอร์ตรวจสอบสถานะของผู้เล่นเป้าหมาย:
     * หากเป้าหมายไม่มีสถานะ "โล่ป้องกัน (Shield)"
     * เซิร์ฟเวอร์ส่งเอฟเฟกต์แกล้งหน้าจอไปแสดงผลที่หน้าจอของผู้เล่นเป้าหมายแบบ Real-time ทันที
  6. ระบบลบไอเทมที่ใช้แล้วออกจากคลังไอเทมของผู้เล่น
* **Alternative / Exception Flows:**
  * **Alt 1: เป้าหมายเปิดใช้งานโล่ป้องกัน (Shield Protected)**
    * ในขั้นตอนที่ 5 หากเป้าหมายมีโล่ป้องกันทำงานอยู่ ระบบจะส่งผลป้องกันเอฟเฟกต์นั้น
    * เซิร์ฟเวอร์เกมจะส่งคำสั่งขจัดไอเทมทั้งสองฝั่ง (ไอเทมแกล้งหายไป และโล่ของฝั่งตรงข้ามแตก)
    * แสดงเอฟเฟกต์ "Shield Blocked" ให้ทั้งสองฝ่ายเห็น
  * **Alt 2: ผู้เล่นเป้าหมายหลุดออกจากห้องหรือตกรอบไปแล้ว**
    * หากเป้าหมายเปลี่ยนสถานะเป็นตกรอบหรือหลุดไปขณะกดยิงไอเทม ระบบจะปฏิเสธการใช้ไอเทมและคืนไอเทมเข้าสู่คลังของผู้เล่น

### UC-05: ตรวจสอบและประมวลผลโค้ด (Evaluate Code)

* **Actor:** เซิร์ฟเวอร์เกม (Game Server)
* **Description:** ระบบรับโค้ดที่ผู้เล่นส่ง รันการทดสอบประเมินความถูกต้อง ประสิทธิภาพ และความเร็ว เพื่อคำนวณคะแนนรวมและบันทึกผล
* **Pre-conditions:**
  1. ผู้เล่นกดส่งโค้ด (Submit) หรือหมดเวลารอบแข่งขัน
* **Post-conditions:**
  1. บันทึกผลการจัดอันดับคะแนนของผู้เล่นในรอบนั้นๆ
* **Basic Flow (ขั้นตอนการทำงานหลัก):**
  1. เซิร์ฟเวอร์เกมรับซอร์สโค้ดของผู้เล่น
  2. ระบบทำการ Sandbox และรันโค้ดกับ Test Cases ทั้งหมดที่เตรียมไว้
  3. ระบบคำนวณคะแนนตามปัจจัย 3 ด้าน:
     * **ความถูกต้อง (Correctness):** จำนวนร้อยละของ Test Cases ที่ผ่าน (ตัวแปรหลัก)
     * **เวลาที่ใช้ (Speed):** ยิ่งส่งโค้ดผ่านได้เร็ว ยิ่งได้คะแนนโบนัสสูง
     * **ประสิทธิภาพโค้ด (Code Efficiency):** การกินทรัพยากรเมมโมรี่ และจำนวนความยาวของโค้ดที่กระชับ
  4. ระบบคำนวณเงิน Survival Cash ที่ได้รับเพิ่มเติมสำหรับผู้ที่ทำได้ดี
  5. ระบบบันทึกคะแนนรวมของผู้เล่นลงใน Session State ของเกมห้องนั้น
* **Alternative / Exception Flows:**
  * **Alt 1: โค้ดทำงานผิดพลาดเฉียบพลัน/ทำงานไม่สิ้นสุด (Runtime Error / Infinite Loop)**
    * หากโค้ดของผู้เล่นเกิด Infinite Loop ระบบ Sandbox จะยุติการทำงาน (Execution Timeout 2-5 วินาที) และให้ผลประเมินว่าไม่ผ่านกรณีทดสอบที่เหลือ ได้คะแนนเฉพาะ Test Case ที่ผ่านก่อนหน้าหน้านั้น

### UC-06: คัดผู้เล่นตกรอบเมื่อจบรอบที่ 2 (Eliminate Players)

* **Actor:** เซิร์ฟเวอร์เกม (Game Server)
* **Description:** เมื่อสิ้นสุดรอบที่ 2 เซิร์ฟเวอร์เกมจะประมวลคะแนนสะสมรวม และทำการคัดผู้เล่นที่ได้คะแนนต่ำที่สุด 2 อันดับออกจากเกม เพื่อให้เหลือเพียง 3 คนไปเล่นต่อในรอบชิงชนะเลิศ
* **Pre-conditions:**
  1. การแข่งขันรอบที่ 2 สิ้นสุดลง (เวลาหมด หรือผู้เล่นทุกคนส่งโค้ดเรียบร้อย)
* **Post-conditions:**
  1. ผู้เล่นอันดับ 4 และ 5 ถูกปรับสถานะเป็น "ตกรอบ (Eliminated)" และเปลี่ยนสถานะการดูเป็น Spectator เท่านั้น
  2. ผู้เล่นอันดับ 1, 2 และ 3 ปลดล็อกไปสู่รอบที่ 3 (Final Round)
* **Basic Flow (ขั้นตอนการทำงานหลัก):**
  1. เซิร์ฟเวอร์เกมดึงตารางคะแนนรวมของผู้เล่นทั้ง 5 คนมาคำนวณ
  2. เรียงลำดับคะแนนจากมากไปน้อย
  3. ระบบระบุผู้เล่น 2 ลำดับสุดท้าย (อันดับ 4 และอันดับ 5)
  4. ระบบแสดงหน้าจอดราม่าเอฟเฟกต์ "Eliminated" สีแดงแก่ผู้เล่นที่ตกรอบ
  5. พอร์ตการทำงานของผู้เล่นที่ตกรอบจะถูกตัดสิทธิ์จากการทำโจทย์รอบถัดไปและส่งไปเข้าโหมดผู้ชม (Spectator Mode)
  6. ผู้เล่น 3 คนที่รอดชีวิตจะได้รับรางวัลโบนัสการเอาชีวิตรอดเป็น Survival Cash พิเศษ และระบบเริ่มเตรียมเข้าสู่ช่วงพักร้านค้ารอบสุดท้าย
* **Alternative / Exception Flows:**
  * **Alt 1: คะแนนเท่ากันในตำแหน่งคัดออก (Tie-Breaker for Elimination)**
    * หากอันดับที่ 3, 4 หรือ 5 มีคะแนนรวมเท่ากัน ระบบจะตรวจสอบเวลาส่งโค้ดที่ถูกต้องล่าสุด (ใครส่งก่อนถือว่าเข้ารอบ)
    * หากยังเท่ากันอีก ระบบจะคำนวณจากความกระชับของโค้ด (Line of Code ที่น้อยกว่า) เป็นอันดับถัดไป

### UC-07: แจกรางวัลและสรุปผลการแข่งขันเมื่อจบรอบที่ 3 (Distribute Rewards & Summary)

* **Actor:** เซิร์ฟเวอร์เกม (Game Server), ฐานข้อมูล (Database)
* **Description:** ประมวลคะแนนผู้รอดชีวิต 3 คนสุดท้ายในการดวลรอบชิงชนะเลิศ เพื่อจัดลำดับที่ 1, 2 และ 3 จากนั้นคำนวณเหรียญเงินรางวัลในกระเป๋าจริง (Code Coins) และทำการเพิ่มมูลค่าเข้าบัญชีของผู้เล่นในฐานข้อมูลถาวร
* **Pre-conditions:**
  1. จบการแข่งขันในรอบที่ 3 เรียบร้อยแล้ว
* **Post-conditions:**
  1. ยอดเงินเหรียญ Code Coins ของผู้เล่นอัปเดตสำเร็จในฐานข้อมูล
  2. ห้องแข่งขันสิ้นสุดลงและคืนทรัพยากรห้องเซิร์ฟเวอร์
* **Basic Flow (ขั้นตอนการทำงานหลัก):**
  1. เซิร์ฟเวอร์ประมวลผลคะแนนการทำโจทย์ระดับยากในรอบที่ 3 ของผู้เล่นทั้ง 3 คน
  2. จัดอันดับผู้ชนะเลิศ: อันดับที่ 1, อันดับที่ 2 และอันดับที่ 3
  3. ระบบแสดงหน้าจอโพเดียมสรุปคะแนนและอันดับอย่างอลังการ (Victory / Podium Screen)
  4. ระบบคำนวณจำนวนเหรียญจริง (Code Coins) ตามอัตราที่กำหนดของอันดับนั้นๆ
  5. ระบบเรียกใช้ API หลังบ้านเพื่อเชื่อมต่อไปยัง Database เพื่อเครดิตยอด Code Coins เข้าบัญชีจริงของผู้เล่นทั้ง 3 คน
  6. ระบบบันทึกประวัติการแข่งขัน (Match History) ลงในฐานข้อมูล
  7. ระบบแสดงปุ่ม "กลับหน้าหลัก (Back to Lobby/Home)" และปุ่ม "เล่นอีกครั้ง (Play Again)" เพื่อให้ผู้เล่นออกจากห้อง
* **Alternative / Exception Flows:**
  * **Exception 1: การเขียนข้อมูลเหรียญรางวัลลงฐานข้อมูลล้มเหลว (DB Write Error)**
    * หากเซิร์ฟเวอร์เชื่อมต่อ Database เพื่อบันทึกเหรียญรางวัลไม่สำเร็จ
    * ระบบจะทำการเข้าคิวธุรกรรมไว้ชั่วคราว (Queue Transaction) เพื่อทำระบบ Retry อัตโนมัติและแสดงข้อความแจ้งผู้เล่นว่า "กำลังโอนเหรียญรางวัลเข้าระบบ กระบวนการอาจใช้เวลา 1-2 นาที" ป้องกันคะแนนตกหล่น
