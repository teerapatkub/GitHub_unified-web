# Generated โจทย์ — Competitive

ทั้งหน้าผู้ใช้ Competitive Arena และหน้าแอดมินสร้างโจทย์แข่งขันมีปุ่ม Generated โจทย์ แบบกรอกเองยังใช้งานได้เหมือนเดิม

เลือกหมวดและประเภท → กด Generated โจทย์ → ตรวจตัวอย่าง → กดใช้โจทย์นี้แทนข้อมูลในฟอร์ม → ตรวจรายละเอียด/test cases → โพสต์ ปุ่มสร้างไม่โพสต์อัตโนมัติและไม่ทับข้อความที่กำลังกรอกจนกว่าจะกดใช้โจทย์

ผู้ใช้เลเวล 10 ขึ้นไปสร้างโจทย์ทั่วไป แอดมินสร้างรายวัน (เป้าหมาย 30 นาที) และรายสัปดาห์ (90 นาที) รางวัลและเวลาคงใช้แบบฟอร์มเดิม AI ไม่กำหนดสิทธิ์หรือรางวัลให้เอง ความยาก/เวลาที่ใช้แก้จริงขึ้นอยู่กับโจทย์และผู้เล่น ต้องตรวจร่างก่อนโพสต์

## ตั้งค่า

> **2026-10-28:** เดิมเรียก Gemini ด้วย API key แล้วเปลี่ยนเป็นโมเดลในเครื่องตอนรวมเข้า main (Spec 0004: ห้ามใช้ API key ของ AI ภายนอก)

ไม่ต้องมีคีย์ ใช้โมเดลในเครื่องตัวเดียวกับแชทบอท (`LLM_BASE_URL`, `LLM_CHAT_MODEL`) และ `LLM_GENERATE_TIMEOUT_MS` (ค่าเริ่มต้น 240000)

- ถ้าไม่ได้ตั้งค่า ปุ่มสร้างตอบ 503
- ไม่มีข้อมูลใดออกนอกเครื่อง ทั้งหัวข้อและโจทย์
- คำแนะนำหลังส่งคำตอบยังเป็นของเดิม: ให้คะแนนด้วย rubric และโมเดลในเครื่องเขียนคำแนะนำเมื่อผ่านเทสไม่ครบ (`LLM_JUDGE_MODEL`) โค้ดผู้เล่นไม่ออกนอกเครื่อง

## การตรวจ

- AI สร้างโจทย์, input 8 ชุดที่ไม่ซ้ำ และโค้ดเฉลย ส่วน **expected ของแต่ละชุดคือสิ่งที่โค้ดเฉลยพิมพ์ออกมาจริง** ไม่ใช้ค่าที่ AI เขียนเอง (โมเดลเล็กเขียน expected ไม่ตรงกับเฉลยของตัวเองราวครึ่งหนึ่ง: docs/llm-benchmark)
- หากร่างไม่ครบ หรือเฉลย error / ไม่พิมพ์อะไร / พิมพ์ค่าเดียวกันทุก input ให้ AI แก้ได้อีกไม่เกิน 2 ครั้ง แล้วปฏิเสธหากยังไม่ผ่าน
- โค้ดเฉลยรันผ่านทั้ง 8 ชุดก่อนแสดงร่าง จำกัด Python subset: ไม่มี imports, files, network APIs หรือ introspection; มี timeout และขนาด output จำกัด ไม่ใช่ OS/container sandbox และไม่รับประกันทรัพยากรหน่วยความจำเหมือน container
- การตรวจ reference กับ test cases ยืนยันความสอดคล้องของสองสิ่งนี้ ไม่ได้พิสูจน์ว่าโจทย์ถูกต้องทางคณิตศาสตร์ทุกกรณี ผู้โพสต์ยังต้องอ่านตัวอย่างและเงื่อนไข
- คำตอบผู้เล่นใช้ Python runner เดิมและ test cases ฝั่ง server ในการตัดสิน คะแนนมาจาก rubric ในเครื่อง โมเดลไม่เปลี่ยนคะแนนหรือผลผ่าน/ไม่ผ่าน
- ต้องผ่าน test cases ครบจึงมีสิทธิ์รางวัล หากโมเดลล่มยังตรวจจากการรันได้ หาก Python runner ล่มให้ส่งใหม่ ไม่ให้ AI เดาผลแทน
- คะแนนประสิทธิภาพ/ความอ่านง่ายของระบบเดิมเป็น rubric/heuristic ไม่ใช่การพิสูจน์ complexity
- โค้ดผู้เล่นยังใช้ runner เดิมซึ่งเป็น Python subprocess; การเปิดต่อสาธารณะควรใช้ worker/container แยกและกำหนด CPU/memory/network limits
- จำกัดสร้างครั้งละ 2 คำขอต่อ process และ 1 ครั้ง/60 วินาทีต่อบัญชี หาก deploy หลาย instances ต้องใช้ rate limiter ร่วมกัน

เมื่อใช้แบบกรอกเอง ผู้โพสต์รับผิดชอบเฉลย test cases เช่นเดิม ไม่มีการสร้างหรือแก้ test cases อัตโนมัติหลังโพสต์

ทดสอบ: `node --test tests/competitive-ai.test.js` ใน server
