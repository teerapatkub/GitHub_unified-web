# ร้านตู้เกม (Arcade Hall) — 6 ตู้มินิเกม Python (Design Spec ระดับร้าน)

> สถานะ: ออกแบบระดับร้านเสร็จ รอผู้ใช้ตรวจ · 2026-11-12 · spec นี้กำหนดเฉพาะรายชื่อตู้และกติกากลาง แต่ละตู้ (ยกเว้นสวนของ Lumi) ต้องมี spec → plan ของตัวเอง

## Context
ผู้ใช้อยากให้เว็บสมกับชื่อ "Arcade" คือเป็นเหมือนร้านเกมที่มีตู้ให้เล่นหลายตู้ จึงเพิ่ม 5 ตู้ต่อจากสวนของ Lumi
(`docs/superpowers/specs/2026-11-10-lumi-garden-design.md`, แผน `docs/superpowers/plans/2026-11-10-lumi-garden.md`)

**เงื่อนไขที่ผู้ใช้ให้มา**
- คนที่รู้ Python น้อยเล่นได้ คนเก่งก็เล่นสนุก
- จบรอบได้เร็ว หรือวนเล่นได้หลายรอบ
- ภาพและเสียงต้องไม่ทำให้เว็บช้า
- เข้าใจง่าย และช่วยให้เก่ง Python ขึ้นจริง
- ทั้ง 6 ตู้ต่างกันทั้งรูปแบบการเล่น แนวเกม และธีม

**การตัดสินใจ**
- ผู้ใช้ผ่านรายชื่อทั้ง 5 ตู้
- รางวัลเป็น "ภารกิจรายวัน + สถิติ"
- **ไม่ล็อกตู้ตามโมดูล**
- สร้าง **สวนของ Lumi ก่อนตามแผนเดิม** แล้วค่อยยกส่วนกลางออกมาเป็น shell ตอนทำตู้ที่ 2

Arcade Battle Royale (`/matchmaking`) ไม่นับรวมใน 6 ตู้ หน้าร้านแค่มีป้ายลิงก์ไปหา

## รายชื่อ 6 ตู้

| ตู้ | แนวเกม | ธีม | วิธีเล่น | ฝึกอะไร | ความท้าทายสำหรับคนเก่ง | ต้องใช้ Python จริง? |
|---|---|---|---|---|---|---|
| 🌾 สวนของ Lumi | จำลองระบบอัตโนมัติ | สวนไทย | เขียนโปรแกรมสั่งหุ่น | ลูป, if, ฟังก์ชัน, OOP | ดาวตาม tick | ใช่ (มี spec แล้ว) |
| 🐞 ตู้ตีบั๊ก | ตอบสนองไว (ตีตัวตุ่น) | ห้องแล็บกำจัดแมลง | แตะบรรทัดที่มีบั๊กก่อนมันหนี รอบละ 60 วินาที | อ่าน error และจับบั๊กที่พบบ่อย | บั๊กที่เนียนขึ้น, คอมโบคูณคะแนน | ไม่ (ใช้คลังบรรทัดที่เตรียมไว้) |
| 🚀 Slice Blaster | ยิงอวกาศ | อวกาศย้อนยุค 8-bit | พิมพ์ index/slice ให้ได้ค่าตามเป้าเพื่อยิง | index, slicing ของ str และ list | step ติดลบ, ศัตรูเร็วขึ้น | ใช่ (Pyodide ประเมิน expression) |
| 🃏 ไพ่ฟังก์ชัน | เกมไพ่ไขปริศนา | แฟนตาซีนักเวท | ลงไพ่อย่าง `x*2`, `x+5`, `x//3` เพื่อพาค่าไปถึงเป้า ใช้ไพ่น้อยได้ดาวมาก | ตัวดำเนินการ, ลำดับการคำนวณ, การส่งค่าต่อกัน | เขียนไพ่ `lambda` เองได้แต่ต้นทุนสูง | ไม่ (คำนวณด้วยตัวตีความเล็กๆ ที่รองรับเฉพาะไพ่) |
| 🏎️ Syntax Racer | แข่งพิมพ์ | ถนนนีออนกลางคืน | พิมพ์โค้ดสั้นๆ ให้ถูกและเร็ว ด่านละ 30–60 วินาที | ความคล่องกับ syntax | แข่งกับรถผีที่เป็นสถิติเก่าของตัวเอง | ไม่ |
| 🕵️ นักสืบข้อมูล | สืบสวน | นักสืบ noir ขาว-ดำ | เขียน query บน list ของ dict เพื่อหาคนร้าย คดีละ 3–5 นาที | list, dict, การกรองข้อมูล, comprehension | ปิดคดีด้วยบรรทัดน้อยที่สุด | ใช่ (Pyodide และตรวจซ้ำบน server) |

**ตัวสำรอง** (ไม่อยู่ในเวอร์ชันแรก): Token Tetris (เรียงชิ้นโค้ดที่ตกลงมาให้เป็นบรรทัดที่ถูก), จับคู่โค้ดกับผลลัพธ์ (เกมจำไพ่)

## กติกากลาง

**หน้ารวมตู้ `/arcade-hall`**
- ตู้เกม CSS 6 ตู้เรียงกัน
- แต่ละตู้แสดงชื่อ คะแนนสูงสุดของตัวเอง และภารกิจวันนี้ (✓ หรือ ยังไม่ทำ)
- มีป้ายลิงก์ไป Arcade Battle Royale

**ไม่มีการล็อกตู้**
- ทุกตู้เล่นได้ตั้งแต่แรก
- มีระดับความยาก 3 ขั้น คือ ฝึกหัด / ชำนาญ / เซียน
- ระบบ *แนะนำ* ขั้นเริ่มต้นจากบทที่เรียนผ่าน แต่ผู้เล่นเลือกเองได้เสมอ
- สวนของ Lumi ยังใช้การปลดล็อกด่านตาม spec ของตัวเอง

**ภารกิจรายวัน** (ตู้ใหม่ทั้ง 5)
- ตู้ละ 1 ภารกิจต่อวัน สร้างจาก seed = วันที่ตามเวลาไทย (Asia/Bangkok) + ชื่อตู้ ทุกคนได้โจทย์เดียวกัน
- ใช้ขั้นฝึกหัดเสมอ
- **server ตรวจคำตอบเอง** แล้วให้ **10 ทอง** ครั้งเดียวต่อตู้ต่อวัน รวมสูงสุด 50 ทองต่อวัน
- ภารกิจต้องออกแบบให้มีคำตอบที่ตรวจได้ ไม่ใช่คะแนนจากความเร็ว เช่น
  - ตีบั๊ก: ระบุบรรทัดบั๊กให้ครบ 10 ข้อ
  - Racer: พิมพ์ snippet ของวันนี้ให้ตรงทุกตัวอักษร ไม่จับเวลา
- ฟาร์มอิสระของสวนยังมีเพดาน 50 ทองต่อวันแยกต่างหาก

**เล่นอิสระ**
- ได้ 🎟️ ตั๋ว และคะแนนสูงสุดของตัวเองเท่านั้น
- ตั๋วแลกได้เฉพาะของในร้าน ได้แก่ ธีมสีตู้ ชุดเสียง และกรอบโปรไฟล์ของร้าน **แลกเป็นทองหรือ XP ไม่ได้**
- ตั๋วและคะแนนสูงสุดเป็นค่าที่ client รายงาน จึงไม่มีผลต่อเศรษฐกิจหลักโดยตั้งใจ
- server รับตั๋วได้ไม่เกิน **50 ใบต่อรอบ** และ **500 ใบต่อวันต่อคน** (รวมทุกตู้) เพื่อกันตัวเลขผิดปกติ ส่วนราคาของในร้านแลกตั๋วกำหนดใน spec ของตู้ที่ 2

**ไม่มีกระดานคะแนนรวมของทุกคน** ในเวอร์ชันแรก เพราะตรวจซ้ำคะแนนความเร็วไม่ได้

## งบทรัพยากร (ทุกตู้)
- แต่ละตู้เป็น chunk แยกด้วย `React.lazy` หลังบีบอัด gzip ไม่เกิน **60 KB** ต่อตู้ โดยไม่นับ Monaco และ Pyodide ที่มีอยู่แล้ว
- ไม่เพิ่มไฟล์ภาพหรือเสียง ใช้ CSS, emoji, inline SVG และ Web Audio (`OscillatorNode`) สังเคราะห์เสียง
- เฉพาะ Slice Blaster, นักสืบ และสวน ที่โหลด Pyodide ส่วนตู้อื่นห้ามโหลด
- ปุ่มปิดเสียงจำค่าไว้ใน `localStorage` (อ่านเขียนผ่าน try/catch) และเคารพ `prefers-reduced-motion`
- ต้องเล่นได้บนมือถือ ตู้ที่ต้องพิมพ์รองรับคีย์บอร์ดบนจอ

## โครงสร้างโค้ดกลาง (ยกออกมาตอนทำตู้ที่ 2)
- `client/src/arcadeHall/`: `ArcadeHallPage.jsx` (หน้ารวมตู้), `CabinetShell.jsx` (header, เริ่ม/หยุด, จับเวลา, หน้าสรุป), `sound.js` (Web Audio)
- แต่ละตู้อยู่ที่ `client/src/arcadeHall/cabinets/<id>/`
- `server/arcadeHall/` ใช้ interface เดียวกันสำหรับทุกตู้
  - `registerCabinet({ id, dailyChallenge(dateSeed), checkDaily(challenge, answer) })`
  - routes: `GET /api/arcade-hall/summary`, `GET /api/arcade-hall/:cabinet/daily`, `POST /api/arcade-hall/:cabinet/daily/submit`, `POST /api/arcade-hall/:cabinet/run`
  - ตาราง: `arcade_hall_daily(user_id, cabinet, day, PRIMARY KEY…)`, `arcade_hall_stats(user_id, cabinet, best_score, tickets…)`
  - สร้างผ่านระบบ migration ใช้ `?` placeholder จ่ายทองใน transaction ด้วย `applyXpRewardToUser`
- สวนของ Lumi ทำตามแผนเดิมก่อน แล้วตอนทำตู้ที่ 2 ค่อยย้ายสวนมาแสดงในหน้ารวมตู้ โดย route ของสวนยังเป็นของเดิม
- **ชื่อเรียก**: เพิ่มคำว่า "ร้านตู้เกม (Arcade Hall)" และ "ตู้ (cabinet)" ใน `CONTEXT.md` เพื่อไม่ให้สับสนกับ Arcade Battle Royale

## ลำดับการสร้าง
1. สวนของ Lumi (ใช้แผนเดิม 9 task)
2. ไพ่ฟังก์ชัน พร้อมยก shell กลาง หน้ารวมตู้ ภารกิจรายวัน และตั๋วออกมา (ตรวจด้วยการคำนวณเลขล้วน เหมาะสำหรับพิสูจน์ shell)
3. ตีบั๊ก
4. Syntax Racer
5. Slice Blaster
6. นักสืบข้อมูล

แต่ละตู้ในข้อ 2–6 ต้อง brainstorm → spec → plan ของตัวเองก่อนลงมือ

## เกณฑ์ความสำเร็จของร้าน
- ทั้ง 6 ตู้เปิดเล่นได้จากหน้ารวมตู้
- ภารกิจรายวันของแต่ละตู้ให้ทองได้ครั้งเดียวต่อวัน และโกงด้วยการส่งค่าจาก client ไม่ได้ (มีเทสยิง endpoint จริง)
- chunk ของแต่ละตู้ไม่เกิน 60 KB gzip (ตรวจจากผล `npm run build`)
- ตู้ที่ไม่ใช้ Pyodide ไม่มี request ไปโหลด Pyodide (ตรวจผ่าน network ใน dev server)
