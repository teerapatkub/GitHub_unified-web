# `avatar_url` เป็นตัวเลือกรูปโปรไฟล์ตัวเดียว ไม่ใช้ `equipped_*_id`

ระบบของตกแต่ง (ธีม, กรอบโปรไฟล์, เอฟเฟกต์เมาส์) เลือกของที่สวมอยู่ด้วยคอลัมน์
`equipped_theme_id` / `equipped_profile_frame_id` / `equipped_mouse_effect_id` ที่ join ไปหา
`shop_items.asset_url` แนวทางที่ตรงกันข้ามจึงเป็นการเพิ่ม `equipped_profile_picture_id`
ให้รูปโปรไฟล์ด้วย แต่เราเลือก **ไม่ทำ**: รูปที่แสดงมาจากคอลัมน์เดียวคือ `users.avatar_url`
เสมอ (ว่าง = ใช้รูปเริ่มต้นตามระดับ) ส่วน `avatar_source` บอกแค่ที่มาของรูปนั้น
(`default`/`upload`/`google`/`shop`/`achievement`) การ resolve อยู่ที่ `resolveAvatar()`
ฝั่ง server ที่เดียว ตามหลักเดียวกับ ADR-0001 (คำตัดสินเป็นของ server)

เหตุผลคือรูปโปรไฟล์มาจาก 5 แหล่ง ไม่ใช่แค่ของในร้าน ถ้ามีทั้ง `equipped_profile_picture_id`
(ของร้าน/achievement) และ `avatar_url` (รูปอัปโหลด/Google/เริ่มต้น) จะมีสองที่ที่กำหนดรูปที่แสดง
และต้องมีกติกาว่า "อันไหนชนะ" ซึ่งเป็นบั๊กที่รอเกิด การรวมทุกแหล่งให้ลงที่ `avatar_url`
จุดเดียวทำให้ "รูปที่เลือกใช้" มีคำตอบเดียวเสมอ

## ทางเลือกที่พิจารณาแล้วไม่เลือก

- **ให้รูปของร้าน/achievement ใช้ `equipped_profile_picture_id` ตาม pattern ของตกแต่งเดิม** —
  สม่ำเสมอกับกรอบ/ธีม แต่ทำให้เกิดตัวกำหนดรูปสองทางที่ต้องมากำหนดลำดับความสำคัญ
- **ทำทุกแหล่งเป็น cosmetic ในตาราง `shop_items`/`user_inventory` แม้แต่รูปอัปโหลดและรูปเริ่มต้น** —
  ต้องยัดรูปที่ไม่ได้ซื้อขายเข้าตารางของในร้านแบบฝืน เกินความจำเป็น

## ผลที่ตามมา

- การ "เป็นเจ้าของ" รูปของร้าน/achievement ยังตรวจผ่าน `user_inventory` เดิม แต่การ **เลือกแสดง**
  ทุกแหล่งทำผ่านการเซ็ต `avatar_url` + `avatar_source` เท่านั้น
- ข้อ 6 (รูปในร้าน) และข้อ 9 (รางวัล achievement เป็นรูป) จะต่อยอดโดยการเซ็ต `avatar_url`
  ให้ชี้ไป `asset_url` ของรูปที่ครอบครอง ไม่ใช่เพิ่มคอลัมน์ equip ใหม่
- ระดับที่เป็นเส้นแบ่งรูปเริ่มต้น (ผู้เริ่มต้น/เชี่ยวชาญ) อยู่ที่ `resolveAvatar()` ค่าเดียว
  (ปัจจุบันเลเวล 10) ปรับที่เดียวมีผลทุกหน้า
