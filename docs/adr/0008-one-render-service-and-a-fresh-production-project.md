# ขึ้นใช้งานจริงด้วย Render บริการเดียว และ Supabase project ใหม่สำหรับ production

## บริบท

ต้องเปิดให้คนจริงใช้ก่อนวันที่ 25 ต.ค. 2026 (เหลือ 4 วัน) ฟรีทั้งหมด และให้มีปัญหาตอน deploy น้อยที่สุด

Spec 0003 วางไว้ว่าหน้าเว็บอยู่บน Vercel, Express อยู่บน Render และใช้ Supabase project เดิม
แต่ระหว่างเล่นทดสอบเมื่อ 2026-10-20 พบปัญหาสองข้อ:

- **มี server อื่นที่ไม่รู้ว่าเป็นของใครต่อฐานเดิมอยู่** และคอยปิดรอบ Arcade ด้วยโค้ดเก่า
  - server ทุกตัวที่ต่อฐานเดียวกันจะแย่งกันปิดรอบ ห้องของผู้เล่นจริงจึงถูกโค้ดของใครก็ได้ตัดสิน
- **repo เป็น public** และในประวัติมีไฟล์สำรองฐานข้อมูลกับค่าที่ดูเหมือน secret

## สิ่งที่ตัดสินใจ

1. **Render free บริการเดียว เสิร์ฟทั้งหน้าเว็บและ API จาก `Dockerfile` เดิม**
   - image นี้ build หน้าเว็บแล้วให้ Express เสิร์ฟ `client/dist` อยู่แล้ว
   - ใช้ origin เดียวกัน จึงไม่ต้องตั้ง CORS, ไม่ต้อง rewrite และ cookie ทำงานแบบ first-party
   - ไม่ใช้ Vercel
2. **production ใช้ Supabase project ใหม่ (Singapore) เริ่มจากฐานว่าง** ส่วน project เดิมกลายเป็นฐานทดสอบ
   - server ที่ไม่รู้เจ้าของ และ dev server ของทุกคน จะเห็นแค่ฐานทดสอบ
   - รหัสฐานและ secret key ของ project ใหม่ไม่เคยอยู่ใน git
   - บัญชีเดิมไม่ย้ายตาม ผู้เล่นสมัครใหม่ (ผู้ใช้ยืนยันแล้ว)
3. **repo ใหม่แบบ private ที่มี commit เดียว** สร้างจากไฟล์ปัจจุบัน แล้วตั้ง repo เดิมเป็น private เก็บไว้
4. **อีเมลยืนยันใช้ Supabase Auth custom SMTP ผ่าน Gmail + App Password** ส่งจากอีเมลของโปรเจกต์เอง
5. **กันเครื่องหลับ:** cron-job.org เรียก `/api/health/live` ทุก 10 นาที (บริการเดียวรัน 24 ชม. อยู่ในโควตาฟรี 750 ชม./เดือน)
6. **ปิด Gemini ไว้ก่อน** คำแนะนำหลังแมตช์จะมาจากผลวัด (ADR 0007)

## ทางเลือกที่ไม่เลือก

- **Vercel + Render (Spec 0003):** มีสองบริการที่ต้องตั้ง rewrite ให้ตรงกัน และ cookie ข้ามโดเมนเสี่ยงพัง โดยไม่ได้อะไรเพิ่มนอกจาก CDN ของหน้าเว็บ
- **Vercel + Supabase อย่างเดียว:** ต้องย้าย ticker ไปปิดรอบตอนมี request และย้ายการตรวจคำตอบไปเป็น Vercel Python Function ซึ่งเป็นโค้ดใหม่ที่ต้องทดสอบใหม่ทั้งชุด เสี่ยงเกินไปสำหรับเวลา 4 วัน
- **ใช้ project เดิมเป็น production:** ต้องเปลี่ยนรหัสฐานเพื่อตัด server ที่ไม่รู้เจ้าของ และทีมต้องย้าย `.env` ข้อดีอย่างเดียวคือได้เก็บบัญชีทดสอบไว้ ซึ่งไม่จำเป็น
- **เขียนประวัติ Git ใหม่ (D01):** ต้อง force-push และทุกคนต้อง clone ใหม่ ใช้เวลามากกว่าทำ repo ใหม่

## ผลที่ตามมา

- Render แบบฟรีมี cold start และหน่วยความจำจำกัด ถ้า ping หยุด ผู้ใช้คนแรกหลังเครื่องหลับจะรอราวครึ่งถึงหนึ่งนาที
- ฐานทดสอบยังมี server ที่ไม่รู้เจ้าของแย่งปิดรอบอยู่ ก่อนเล่นทดสอบจึงต้องตรวจ `pg_stat_activity` ว่าไม่มีใครต่ออยู่
- ขั้นตอนตั้งค่าอยู่ใน `docs/deploy-render.md`
