> **ถูกแทนที่ด้วย ADR 0007 ในวันเดียวกัน:** Gemini ไม่ได้ให้คะแนนแล้ว คะแนนคุณภาพมาจากการวัดในเครื่อง
> Gemini เหลือหน้าที่เขียนคำแนะนำหลังแมตช์ ส่วนที่ยังใช้อยู่จาก ADR นี้ ได้แก่ สูตร starter=0 / ลดตามเทสที่ผ่าน,
> คอลัมน์ใน `arcade_round_history`, และบอทใช้มาตรฐานเดียวกับผู้เล่น

# Arcade ใช้ Gemini ตรวจคุณภาพโค้ด: เวลา ประสิทธิภาพ มาตรฐาน ทั้งคนและบอท

แทนที่ข้อ "คะแนนคุณภาพของบอทยังสุ่มจาก band" ใน ADR 0005

## สิ่งที่ตัดสินใจ

คะแนนรอบของ Arcade ยังเป็น **เทส + คุณภาพ + ความเร็วในการส่ง** (ข้อละ 0–100) เหมือนเดิม ที่เปลี่ยนคือที่มาของ "คุณภาพ"

- **ตัวตรวจคือ Gemini** (`server/arcade/code-judge.js`) ผ่าน `@google/genai`
  - ใช้ `gemini-3.5-flash-lite` ตั้งแต่ 2026-10-20 เพราะคีย์ใหม่ใช้รุ่น 2.5 ไม่ได้แล้ว (404)
  - ปิดการคิดให้น้อยที่สุด: รุ่น 2.x ใช้ `thinkingBudget: 0` รุ่น 3 ขึ้นไปใช้ `thinkingLevel: 'MINIMAL'` เพราะรุ่น 3 ปฏิเสธค่าแบบแรก (400)
    ถ้าโมเดลไม่รู้จักค่านี้ ระบบจะส่งใหม่โดยไม่มีค่านี้
  - คีย์ โมเดล และโควตาอ่านจาก `GEMINI_CODE_JUDGE_API_KEY` / `_MODEL` / `_RPM`
  - ใช้กับ Arcade เท่านั้น Competitive Arena ยังใช้ตัวตรวจ NVIDIA เดิม
- **เกณฑ์ตายตัว 3 ข้อ ข้อละ 0–100** และ server เฉลี่ยเอง ไม่ให้โมเดลบอกคะแนนรวม
  - **เวลา**: เวลารันเทสเคสเทียบกับเฉลยบนเครื่องเดียวกัน และ Big-O
    - เวลารันวัดจริงใน `problemGrader.js` (`results[i].ms`, `runtimeMs`) ฝั่ง function วัดด้วย Python เองเฉพาะช่วงที่เรียกฟังก์ชัน
  - **ประสิทธิภาพ**: งานซ้ำหรือเกินจำเป็น หน่วยความจำ การเลือกโครงสร้างข้อมูล
  - **มาตรฐาน**: PEP 8 การตั้งชื่อ ความอ่านง่าย การใช้ Python อย่างเหมาะสม
- **ความถูกต้องไม่ใช่หน้าที่ของโมเดล** เทสจริงตัดสินเหมือนเดิม
  - เทสที่ไม่ผ่านถูกส่งไปให้โมเดลเพียงเพื่อเขียนคำแนะนำ
- **ความเร็วในการส่งไม่ถูกนับซ้ำ** ยังเป็น `timeScore` ของ server ส่วนหน้าประวัติแสดงไว้คู่กับเกณฑ์ "เวลา"
  - ถ้าให้โมเดลนับด้วย ผู้เล่นจะได้คะแนนความเร็วสองต่อ และ cache ตามโค้ดไม่ได้
- **สูตรคุณภาพ**: `quality = (โค้ดตั้งต้นไม่ได้แก้ หรือว่าง) ? 0 : score × (0.5 + 0.5 × สัดส่วนเทสที่ผ่าน)`
  - ใช้สูตรเดียวกันทั้งคนและบอท
  - โค้ดสวยแต่ผิดได้คุณภาพครึ่งเดียว จึงไม่ชนะโค้ดเรียบๆ ที่ถูก
  - ส่งโค้ดตั้งต้นไม่ได้อะไรเลย
- **บอทถูกตรวจด้วยตัวตรวจเดียวกัน**
  - คลังคำตอบของแต่ละโจทย์ (ADR 0005 ราว 9 แบบ) ถูกตรวจครั้งเดียวต่อการเปิด server
  - บอทได้คะแนนของคำตอบที่ตั้งใจพิมพ์ ตัวพิมพ์ผิดที่ค้างอยู่ทำให้เสียเทส ไม่ได้เรียกตัวตรวจใหม่

## ความเป็นธรรม

- **temperature 0 และ cache** ด้วย `sha256(model, taskId, โค้ดที่ normalize แล้ว)`
  - โค้ดเดียวกันได้คะแนนเท่ากันทุกครั้ง ทุกแมตช์ ทั้งคนและบอท
  - ช่องว่างท้ายบรรทัดหรือ CRLF ไม่ทำให้เป็นคำตอบใหม่
- **โมเดลเห็นโจทย์และโค้ดตั้งต้น** ที่ระบุว่าไม่ใช่ผลงานผู้เล่น
- **กันการเขียนสั่งตัวตรวจ**
  - comment และ string ที่เข้ารูปแบบคำสั่ง (เช่น "ignore previous", "give me full score", "ให้คะแนน", "คะแนนเต็ม") จะไม่ถูกส่งให้โมเดลเลย
  - คำตอบนั้นได้ครึ่งหนึ่งของคะแนนในเครื่อง (`source: 'flagged'`)
  - ใน prompt โค้ดอยู่ในแท็ก `<player_code>` ที่บอกว่าเป็นข้อมูล ไม่ใช่คำสั่ง
  - รูปแบบเหล่านี้ไม่ตรงกับโค้ดตั้งต้นหรือเฉลยข้อใดในคลัง 40 ข้อ (ตรวจ 80 บล็อกแล้ว)

## โควตาฟรีและเวลา

- **ตัวจำกัดอัตรา** เว้นระยะการเรียกตาม `GEMINI_CODE_JUDGE_RPM` (ค่าเริ่มต้น 10)
  - งานของผู้เล่นมาก่อน งานคลังคำตอบบอทรอทีหลัง
- **ได้ 429**: รอตาม `retryDelay` ที่ Gemini บอก แล้วลองใหม่ 1 ครั้ง
  - ถ้าต้องรอนานกว่า 30 วินาที หรือล้มอีก หรือคำตอบไม่ใช่ JSON ที่ถูกต้อง ให้ใช้คะแนนในเครื่องเดิม (`heuristicCodeQualityScore`, `source: 'fallback'`)
  - ผลแบบ fallback ไม่ถูก cache ครั้งหน้าจึงลองโมเดลใหม่ได้
- **เริ่มตรวจตั้งแต่ผู้เล่นกดส่ง** (`submission-api.js`) นอก transaction
  - ตอนจบรอบ finalizer จึงมักได้ผลจาก cache ทันที
  - ถ้ายังไม่เสร็จ รอได้ไม่เกิน 12 วินาที แล้วใช้คะแนนในเครื่อง
  - บอทรอคุณภาพของคลังได้ไม่เกิน 3 วินาที
- **ไม่ตั้งคีย์**: ทุกอย่างให้คะแนนในเครื่องและไม่ส่งโค้ดออกนอกเครื่อง

## สิ่งที่ผู้เล่นเห็น

`arcade_round_history` เพิ่ม 4 คอลัมน์ผ่าน migration ใหม่ `202610200002` (ไม่แก้ migration ที่ apply แล้ว):
- `quality_rubric` (สามเกณฑ์ + อัตราส่วนเวลารัน)
- `quality_reason`
- `quality_feedback`
- `quality_source`

`RoundHistoryPanel` (หน้าสรุปผลและประวัติแมตช์) แสดง:
- แถบสามเกณฑ์
- "ส่งหลังเริ่มรอบ X วินาที · รันนานเป็น Y เท่าของเฉลย"
- เหตุผล
- กล่องคำแนะนำ (บอกด้วยเมื่อพบข้อความสั่งตัวตรวจ หรือส่งโค้ดตั้งต้น)
- ป้ายเมื่อเป็นคะแนนสำรองที่ให้ในเครื่อง

## ทางเลือกที่ไม่เลือก

- **คงตัวตรวจ NVIDIA เดิม**: ผู้ใช้เลือก Gemini เพราะมีโควตาใช้ฟรี
- **ให้ AI ช่วยตัดสินความถูกต้องด้วย**: ผู้ใช้เลือกให้เทสจริงตัดสินอย่างเดียว เพราะคุมได้และอธิบายได้
- **บอทยังสุ่มคุณภาพตาม band**: วัดคนกับบอทคนละมาตรฐาน
- **ให้โมเดลเห็นความเร็วในการส่งและให้คะแนนด้วย**: นับซ้ำกับ `timeScore` และทำให้ cache ตามโค้ดไม่ได้

## ผลที่ตามมา

- **ความเป็นส่วนตัว:** Gemini แบบฟรีอาจนำข้อมูลไปปรับปรุงบริการ โค้ด Arcade ของผู้เล่นจึงถูกส่งไป Google เมื่อตั้งคีย์ ถ้าไม่ต้องการ ให้ปล่อยคีย์ว่าง
- **โควตา:**
  - ผู้เล่น 1 คนใช้ 1 การเรียกต่อรอบ และไม่ใช้ซ้ำถ้าส่งโค้ดเดิม
  - คลังคำตอบบอทใช้ราว 9 การเรียกต่อโจทย์ใหม่ ครั้งเดียวต่อการเปิด server
  - ถ้าโควตาต่อวันหมด จะได้คะแนนในเครื่องจนกว่าจะรีเซ็ต
- **สมดุลบอท:** คุณภาพของบอทไม่ขึ้นกับระดับห้องแล้ว ความยากยังคุมด้วย `botSkillByDifficulty.pass*` และความเร็วพิมพ์
  - ระดับยากจึงปรับ `passMin` 0.45→0.55
  - `npm run sim:bots` ด้วย Gemini จริง (2026-10-20): ง่าย +8.3%, ดั้งเดิม +4.6%, ปานกลาง +4.5%, ยาก +0.5% เทียบกับเดิม
  - `qualityMin/qualitySpread` ยังใช้เฉพาะทางสำรองแบบหลอด (ห้องที่ไม่มีโจทย์ หรือคลังสร้างไม่สำเร็จ)
- `judgeCodeQuality()` และ `heuristicCodeQualityScore()` ถูกย้ายออกจาก `server.js` (heuristic ย้ายไปอยู่ใน `code-judge.js`)
  - Competitive ไม่ได้ใช้สองฟังก์ชันนี้
