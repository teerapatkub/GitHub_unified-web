# Arcade วัดทักษะอ่าน ตรวจ และแก้โค้ด ไม่ใช่แค่เขียน

## บริบท

อาจารย์ที่ปรึกษาถามว่า ทุกวันนี้คนส่วนใหญ่ให้ AI เขียนโค้ดแทนอยู่แล้ว Arcade จะน่าเล่นได้อย่างไร
ถ้าทุกรอบคือ "เขียนฟังก์ชันจากโจทย์" รอบนั้นวัดแค่ว่าใครเปิด AI ได้เร็วกว่า และเป็นทักษะที่คนเรียน
Python รุ่นนี้ใช้จริงน้อยลงเรื่อยๆ

สิ่งที่คนต้องมีเพื่อใช้ AI ให้เป็น คือ **อ่านโค้ดออก ตรวจได้ว่าถูกไหม และแก้ได้เมื่อมันผิด**
ซึ่งใน 30–60 วินาทีใต้ debuff การคัดลอกโจทย์ไปถาม AI ไม่ได้เปรียบมาก

## สิ่งที่ตัดสินใจ

**แต่ละรอบของแมตช์มี "รูปแบบรอบ"** แทนที่จะไล่จับคนใช้ AI ให้เปลี่ยนสิ่งที่ Arcade วัด

- **ระดับห้อง:** ห้องเลือกได้ว่าเป็น "ผสม" (ค่าเริ่มต้นของห้องใหม่) หรือ "คลาสสิก" (เขียนโค้ดทุกรอบเหมือนเดิม)
- **รอบของห้องผสม:** รอบ 1 ทายผลลัพธ์ (ถ้ายังไม่มีรูปแบบนี้จะเป็นรอบเขียน), รอบ 2 เขียน, รอบ 3 แก้โค้ด และรอบ 4 สุ่มจากทุกรูปแบบที่มี
- **ทะเบียนโหมด:** รูปแบบรอบเป็นค่าของทะเบียนโหมด (`problem_modes.round_kinds`) ไม่ใช่ของโจทย์
- **ข้อมูลของแต่ละรูปแบบ:** อยู่ใน `problem_modes.round_data` และ**คำนวณจากการรันโค้ดจริงเสมอ**
  - คำตอบผิดมาจาก bot-coder (ADR 0005) และตรวจด้วยตัวตรวจตัวเดียวกับผู้เล่น
  - ไม่พิมพ์เอง และไม่ถามโมเดล
  - server คำนวณแถวที่ยังไม่มีหรือล้าสมัยเบื้องหลังหลังบูต
  - แต่ละแถวเก็บ hash ของโค้ดและเทสที่ใช้คำนวณ โจทย์ที่ถูกแก้ใน seed จึงได้ข้อมูลใหม่เอง
- **ห้องจำรูปแบบของแต่ละรอบไว้คู่กับโจทย์:** เก็บใน `round_kinds` ของห้องและของแมตช์ ส่วนแมตช์เก่าที่ไม่มีค่านี้อ่านเป็น "เขียน" ทุกรอบ
- **ตอนสุ่ม:** ถ้าโจทย์ที่สุ่มได้เล่นรูปแบบที่วางไว้ไม่ได้ จะสลับเป็นโจทย์ระดับเดียวกันที่เล่นได้ ถ้าไม่มีเลย รอบนั้นเป็นรอบเขียน

### รอบ "แก้โค้ดที่ AI เขียน"

- **เริ่มรอบ:** editor เปิดที่คำตอบผิดซึ่งผ่านเทสมากที่สุดแต่ยังไม่ครบ (อย่างน้อยหนึ่งข้อ) และผู้เล่นเห็นตั้งแต่ต้นว่าผ่านกี่ข้อ
- **คะแนนเทสนับเฉพาะเทสที่ผู้เล่นแก้ให้ผ่าน:** `(ผ่านตอนนี้ − ที่ AI ผ่าน) / (ทั้งหมด − ที่ AI ผ่าน)` ไม่ต่ำกว่า 0
  - ถ้านับเทสทั้งหมด ผู้เล่นที่แค่เติมคอมเมนต์ลงในคำตอบของ AI จะได้ครึ่งหนึ่งของคะแนนเทสโดยไม่ได้แก้อะไร (พบระหว่างทำ มีเทสกันไว้แล้ว)
  - สูตรรวมยังเป็นสูตรเดิม (ความถูกต้อง + คุณภาพ + เวลาที่เหลือ) และคุณภาพยังวัดในเครื่องตาม ADR 0007
  - คำตอบที่ส่งคืนโดยไม่แก้ได้ 0 เหมือนโค้ดตั้งต้นที่ไม่ได้แตะ
- **บอท:** ใช้คลังคำตอบของรอบแก้โดยเฉพาะ คือเฉลย, คำตอบของ AI (= ยอมแพ้) และคำตอบที่แก้ส่วนอื่นแต่บั๊กยังอยู่
  - **โอกาสหาบั๊กเจอ:** เท่ากับสัดส่วนเทสที่บอทตัวนั้นจะทำผ่านในรอบเขียนของโจทย์เดียวกัน บอทจึงแข็งพอๆ กันทั้งสองแบบ
  - **เวลาที่ใช้:** เท่ากับเวลาเขียนคำตอบนั้นในรอบเขียน ส่วนที่เกินจากการพิมพ์นับเป็นเวลาหาบั๊ก
  - **ผล `npm run sim:bots`:** คะแนนเฉลี่ยต่อรอบของรอบแก้ต่ำกว่ารอบเขียน 6–11% ทุกระดับ อยู่ในเกณฑ์ 15%

### รอบ "ทายผลลัพธ์"

- **โจทย์:** โค้ดเฉลยกับการเรียกหนึ่งครั้ง เช่น `print(fib(10))` ผู้เล่นแตะเลือกว่าพิมพ์อะไร ไม่ต้องพิมพ์โค้ด จึงเล่นบนมือถือได้
- **ความยาว:** รอบละ 20 วินาที (โหมดเร็ว 15) ตาม `predictRoundSeconds` ใน `shared/arcadeConfig.json`
- **ตัวเลือก:**
  - **คำตอบถูก:** สิ่งที่ Python พิมพ์จริง
  - **คำตอบผิด:** สิ่งที่คำตอบผิดของ bot-coder พิมพ์เมื่อเรียกแบบเดียวกัน ทุกตัวเลือกจึงเป็นผลของโค้ดที่ดูเป็นไปได้
  - ไม่ใช้เทสที่แสดงเป็นตัวอย่างใต้โจทย์ เพราะตัวอย่างโชว์ผลไว้แล้ว (พบตอนทดสอบบนมือถือ) และหน้าเกมซ่อนตัวอย่างในรอบนี้ด้วย
- **คะแนน:** เลือกถูกได้เทส 100 + คุณภาพ 100 + เวลาที่เหลือ ส่วนเลือกผิดได้ 0 ไม่ถามตัวตรวจคุณภาพ
- **ไอเทม:** ไอเทมที่โจมตีการพิมพ์ (`typingOnlyItems`) ใช้ไม่ได้ในรอบนี้ ไอเทมยังอยู่ในกระเป๋า และร้านบอกล่วงหน้าเมื่อรอบถัดไปเป็นรอบทายผลลัพธ์
  - Ink Fog, Blackout และ Mirror Code ยังบังและกลับด้านส่วนที่ต้องอ่าน ส่วน Freeze ทำให้แตะตัวเลือกไม่ได้
- **บอท:** ตอบถูกด้วยโอกาสแบบเดียวกับรอบแก้ ถ้าคิดไม่ออก ครึ่งหนึ่งจะเดาจากทุกตัวเลือก (คำถามแบบเลือกตอบมีโอกาสเดาถูก)
  - ใช้เวลาอ่าน 25–75% ของรอบ และ Ink Fog/Freeze/Blackout หยุดนาฬิกานั้นได้
- **ผล `npm run sim:bots`:** ห่างจากรอบเขียน −8% ถึง +8%

## ผลที่ตามมา

- เมื่อ 2026-10-26 จาก 40 ข้อ: 33 ข้อเล่นรอบแก้ได้ และ 25 ข้อเล่นรอบทายผลลัพธ์ได้ ข้อที่เล่นรูปแบบที่วางไว้ไม่ได้จะถูกสลับเป็นข้ออื่นหรือเป็นรอบเขียน
- การเพิ่มรูปแบบรอบใหม่ (เช่น ตรวจคำตอบ AI) คือเพิ่ม kind ใน `server/arcade/round-kinds.js` พร้อมวิธีคำนวณข้อมูล, วิธีตัดสิน และวิธีที่บอทเล่น
  - เงื่อนไขเดิม: ไม่มีโมเดลในเส้นทางให้คะแนน (ADR 0007)
  - เงื่อนไขเดิม: คะแนนเฉลี่ยของบอทในรูปแบบนั้นต้องห่างจากรอบเขียนไม่เกิน 15%
- `npm run test:round-kinds` (อยู่ใน `npm run test:arcade`) ตรวจข้อมูลที่เก็บไว้ทุกแถวด้วยการรันซ้ำ
- ป้ายในเกมเขียนว่า "คำตอบที่ AI เขียนมา" เพื่อสื่อสถานการณ์ แต่ไม่ได้เรียกโมเดลจริง
