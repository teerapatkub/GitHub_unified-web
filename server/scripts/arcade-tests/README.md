# Arcade Battle Royale — ชุดสคริปต์ทดสอบ

สคริปต์ในโฟลเดอร์นี้คือสิ่งที่จับบั๊กจริงมาแล้วหลายตัว ไม่ใช่ของประดับ ก่อน commit
งานที่แตะคลังโจทย์ การสุ่มโจทย์ ระบบคะแนน หรือบอท **ให้รันชุดนี้ก่อน**

## รันยังไง

จากโฟลเดอร์ `server/`:

```bash
TEST_DATABASE_URL=postgres://postgres:postgres@127.0.0.1:55432/postgres npm run test:arcade
```

`TEST_DATABASE_URL` ต้องชี้ไปที่ PostgreSQL **ที่ทิ้งได้** (เช่น container `pyarena-test-db`)
ไม่ใช่ฐานของแอปจริง ชุดนี้ **ไม่ต้องเปิด server แยกไว้ก่อนแล้ว** — สี่ตัวที่ต้องคุยกับ server
(`test:score`, `test:draw`, `test:spectator`, `test:bots`) เป็นไฟล์ `node:test` ใน `server/tests/`
ที่บูต server จริงของตัวเองขึ้นมาบนฐานข้อมูลใหม่ที่สร้างแล้วลบทิ้งเอง โดยมีผู้เล่นที่ล็อกอินแล้ว
(ด้วย Supabase token ที่จำลองไว้) ผ่าน `tests/helpers/start-server.js`

รันแยกทีละตัวได้:

```bash
npm run test:tasks
```

| สคริปต์ | ต้องมีอะไรก่อนรัน | ใช้เวลา |
|---|---|---|
| `verify-tasks.py` | Python + Node (**ไม่ต้องมี server / DB**) | ไม่กี่วินาที |
| `difficulty-analysis.py` | Python + Node (**ไม่ต้องมี server / DB**) | ไม่กี่วินาที |
| `tests/arcade-server-scoring.test.js` (`test:score`) | `TEST_DATABASE_URL` + Python | ~10 วินาที |
| `tests/arcade-draw.test.js` (`test:draw`) | `TEST_DATABASE_URL` | ~15 วินาที |
| `tests/arcade-spectator.test.js` (`test:spectator`) | `TEST_DATABASE_URL` | ~10 วินาที |
| `tests/arcade-bot-skill.test.js` (`test:bots`) | `TEST_DATABASE_URL` + Python | ~1 นาที (รอรอบจริงจบ) |
| `ui-clip-check.js` | เบราว์เซอร์ (paste ลง console) | ทันที |
| `playtest-report.js` | server รันอยู่ (ไม่ใช่ test — ใช้หลังให้คนจริงเล่น) | ทันที |

เดิมสี่ตัวนั้นเป็นสคริปต์ในโฟลเดอร์นี้ที่ยิงไปที่ server ซึ่งเปิดค้างไว้ที่ :3001 โดยไม่ส่ง token
หลังย้ายไป Supabase Auth (2026-10-08) ทุก request ได้ 401 ชุดนี้จึงรันผ่านไม่ได้เลย
ย้ายมาเป็น `node:test` เมื่อ 2026-10-22 โดยเก็บทุกเช็กไว้ครบ

`playtest-report.js` ยังอ่าน server ที่รันอยู่ เปลี่ยน URL ได้ด้วย `ARCADE_TEST_BASE=http://host:port`

**หมายเหตุ**: `playtest-report.js` ไม่ได้รวมอยู่ใน `test:arcade` เพราะไม่ใช่การทดสอบอัตโนมัติ
แต่เป็นเครื่องมืออ่านผลหลังให้คนจริงมานั่งเล่น — ขั้นตอนการทดสอบอยู่ใน `PLAYTEST-PROTOCOL.md`

## แต่ละตัวตรวจอะไร และทำไมถึงมีอยู่

### `verify-tasks.py` — คลังโจทย์ 40 ข้อ (458 assertions)

ตรวจว่า เฉลยทุกข้อผ่าน test case ของตัวเอง / `starter_code` เป็น Python ที่ถูกต้อง มี signature
ตรงกับเฉลย และ **ต้องไม่ผ่านเทสเองได้** / `hint_th` กับ `hint_en` มีครบและไม่มีบรรทัดคำตอบ

**จับของจริงมาแล้ว 2 ครั้ง**:
- "6. Longest Word" เก็บคำตอบว่า `"jumps"` แต่เฉลยของมันเอง `max(words, key=len)` คืน `"quick"` —
  คนที่ตอบถูกถูกตัดสินว่าผิดทุกคน
- hint 6 ข้อเผลอยกบรรทัดคำตอบมาแปะ ทำให้ไอเทมราคา 600 กลายเป็นเฉลยฟรี

อ่าน `server/arcadeTaskSeed.js` โดยตรงผ่าน Node จึงไม่มีทางหลุดจากของจริง

### `difficulty-analysis.py` — โจทย์ยังพอดีกับเวลาอยู่ไหม

รายงานว่าผู้เริ่มต้น (90 ตัวอักษร/นาที) พิมพ์ไม่ทันกี่ข้อในแต่ละโหมด
มีไว้เพราะเคยวัดแล้วพบว่า **70% ของคลังโจทย์พิมพ์ไม่ทันในโหมดเร็ว** ซึ่งไม่มีใครสังเกตจนกระทั่งวัด
รันซ้ำทุกครั้งที่แก้ scaffold แก้เฉลย หรือแก้ความยาวรอบ

### `test:draw` — การสุ่มโจทย์ (7 เช็ก)

ทุกข้อที่สุ่มมาต้องอยู่ในงบเวลาของห้อง / ห้อง easy ต้องได้รอบ 4 เป็น medium ไม่ใช่ hard /
ห้อง hard ต้องได้ hard ครบ 4 รอบไม่ซ้ำ / และ **line-up ต้องยังต่างกันทุกแมตช์** —
ข้อสุดท้ายสำคัญ เพราะตัวกรองที่แน่นเกินไปจะผ่านเช็กอื่นหมดแต่ทำให้เกมซ้ำซากจนพัง

### `test:bots` — เลือกห้องง่ายแล้วคู่แข่งอ่อนลงจริงไหม

เดิมบอทใช้ช่วงคะแนนคงที่ไม่ว่าห้องจะตั้งระดับอะไร เลือก easy จึงได้โจทย์ง่ายลงแต่เจอคู่แข่งแข็งเท่าเดิม
เทสนี้รันรอบ 1 หลายห้องแล้วเทียบคะแนนเฉลี่ยที่ **เซิร์ฟเวอร์** เขียนให้บอท (บูต server พร้อม match tick
จริงเพื่อให้รอบปิดและบอทเล่นเหมือนบน production)

### `test:score` — คะแนนรอบมาจากโค้ด ไม่ใช่ตัวเลขที่ client ส่งมา (10 เช็ก)

ส่ง `round_score: 999999999` พร้อม pass_count ที่เป็นไปไม่ได้ แล้วตรวจว่าเซิร์ฟเวอร์ไม่สนใจตัวเลขเหล่านั้น
ส่งซ้ำด้วยโค้ดอื่นไม่ทับคำตอบแรก คนนอกห้องส่งไม่ได้ และเมื่อรอบปิด เฉลยต้องผ่านทุกเทสที่เซิร์ฟเวอร์รัน
ได้คะแนนที่เซิร์ฟเวอร์คิดเอง คุณภาพ 0–100 และเวลาจากนาฬิกาของเซิร์ฟเวอร์

### `test:spectator` — ดูโค้ดคนอื่นได้ก็ต่อเมื่อส่งคำตอบของตัวเองแล้ว (8 เช็ก)

ใช้ผู้เล่นที่ล็อกอินจริงสามคน (สองคนในห้อง หนึ่งคนนอกห้อง) ตรวจว่ายังไม่ส่งดูไม่ได้ อ่านร่างตัวเองได้เสมอ
ส่งแล้วดูได้แต่ทางเดียว ร่างที่ส่งมาหลังส่งคำตอบไม่มีผล คนนอกห้องและชื่อที่ไม่อยู่ในห้องได้ 404
และ request ที่ไม่ได้ล็อกอินได้ 401

### `playtest-report.js` — อ่านผลการทดสอบกับคนจริง

```bash
npm run playtest:report -- <ชื่อผู้ใช้>
```

ทุกรอบที่ผู้เล่นกดส่งจะเขียนแถวลง `arcade_round_history` อยู่แล้ว (โค้ดที่เขียน ผ่านกี่เทส ใช้เวลาเท่าไร
ห้องตั้งค่าอะไร) สคริปต์นี้แค่อ่านกลับมาแล้วตัดสินตามเกณฑ์ **≥2 จาก 4 รอบ ในห้อง easy โหมด Standard**
ถ้าแมตช์ไม่ใช่ easy/Standard มันจะไม่ตัดสินผ่าน/ไม่ผ่านให้ แต่จะบอกว่าให้ถือเป็นข้อมูลประกอบเท่านั้น

⚠️ บอกได้แค่ว่า *ทำได้หรือไม่ได้* บอกไม่ได้ว่า *ทำไม* — รอบที่ทำไม่สำเร็จหน้าตาในฐานข้อมูลเหมือนกันหมด
ไม่ว่าจะเพราะอ่านโจทย์ไม่เข้าใจ คิดไม่ออก หรือพิมพ์ไม่ทัน ซึ่งแก้คนละทางโดยสิ้นเชิง
ต้องใช้คู่กับบันทึกของคนสังเกตการณ์ตาม `PLAYTEST-PROTOCOL.md` เสมอ

### `ui-clip-check.js` — เนื้อหาถูกตัดหาย

paste ลง console แล้วเรียก `__clip()` หาอิลิเมนต์ที่ซ่อนเนื้อหาตัวเองอยู่
เจอของจริง 7 จุดในรอบเดียว รวมถึงสองจุดที่ผู้ใช้ถ่ายภาพมา
มี `__armClipRecorder()` สำหรับ phase สั้นๆ (หน้าสรุปรอบโชว์แค่ 5 วินาที เร็วเกินกว่าจะดูทัน)

**ก่อนเชื่อผลว่า "ไม่เจออะไร" ให้ทดสอบตัวตรวจก่อน** — ใส่ class เดิมกลับเข้าไปใน DOM สดๆ
แล้วดูว่ามันจับได้ไหม ตัวตรวจที่พังจะให้ผลหน้าตาเหมือนหน้าที่ไม่มีบั๊กเป๊ะ
